# 第一部分：每日决策入口（开始日）

## 1.1 统一决策树

```
获取当前日期 + 星期
  │
  ├── 步骤A：是否为交易日？
  │   检查：周末（六/日）→ 否
  │   检查：2026年法定节假日 → 否
  │   检查：调休补班日 → 是（即使周末也交易）
  │   检查：调休放假 → 否（即使工作日也休市）
  │
  ├── 是（交易日）
  │   └── 执行【第二部分：交易日复盘】
  │
  └── 否（休市日）
      ├── 检查重大突发事件触发重定向
      │   ├── 全球主要股指单日跌幅>3%
      │   ├── 央行意外降息/加息
      │   ├── 地缘冲突导致原油单日涨幅>5%
      │   └── 国内出台资本市场顶层设计文件
      │
      └── 判断休市类型 → 执行【第三部分：休市日】
```

## 1.3 去重机制（每日强制）

无论交易日还是休市日，执行前必须：
1. 读取前一日已保存的复盘/审计文件的 `top_news`
2. 重复新闻（相似度>70%）→ 仅保留一句结论或标注"昨日已述"
3. 新新闻（相似度<50%）→ 正常展开
4. 休市日多天连续时，对比前一天假设追踪表

# 第二部分：交易日复盘

## 2.1 数据采集策略

### 核心原则

- **必须并行拆分采集**。单一 agent 在 50 次迭代内无法完成完整采集。
- **必须使用 delegate_task 并行拆分**为独立的子任务（Hermes Agent 特性）。
- **局部失败不阻断流程**：某个模块失败 → 标记 `data_quality: partial` → 继续执行其余模块。

### 并行子任务分配

| 子任务 | 数据源 | 工具 | 说明 |
|:-------|:-------|:-----|:------|
| A: 指数+成交额 | 腾讯API qt.gtimg.cn | `terminal` + curl | GBK→UTF-8 解码 |
| B: 北向成交+十大成交股 | 东方财富Choice | `browser` 或 `terminal` | 成交额、沪/深前三 |
| C: 涨跌家数+涨跌停 | 东方财富行情页(quote.eastmoney.com/zs000001.html) + 新浪财经 | `browser` | 页面顶部含上证/深证涨跌家数，不含北交所 |
| D: 板块涨跌幅 | 东方财富行业资金 | `browser` | 前三+后三+主力净流入 |
| E: 新闻采集 | 财联社 cls.cn | `browser` | 前8条按重要性排序 |
| F: 前一日去重 | 读取前一日复盘文件 | `file` → `read_file` | 对比 top_news |

每个子任务有独立 50 次迭代限额，互不影响。主 agent 汇总后生成报告 + write_file。

**关键：宁可拆 5-10 次并行，也不允许跳过数据源。涨跌家数和北向成交额是必填数据。**

### 数据交叉验证允许误差

| 指标 | 允许误差 |
|------|----------|
| 指数点数 | 0误差 |
| 成交额 | ±50亿 |
| 涨跌家数 | ±50家 |
| 涨停家数 | ±5家 |
| 北向成交额 | ±2亿 |

偏差超范围时，以新浪财经为第三方裁决。

### 单个数据源调用超时规则

- 所有 API 调用必须设超时：`curl --max-time 15`（每个调用上限15秒）
- 所有 Tier 1 调用包装重试：失败后等5秒重试，再失败等15秒重试，3次全失败才放弃

## 2.3 腾讯API数据格式解析

```
v_sh000001="1~上证指数~000001~4090.48~4108.08~...~20260618161419~-17.60~-0.43~...~1560473972715~"
```

字段位置（0-indexed）：
- idx 3：最新价
- idx 4：昨收
- idx 5：开盘价
- idx 31：时间戳 (YYYYMMDDHHMMSS)
- idx 32：涨跌额
- idx 33：涨跌幅
- 成交额在末尾 `~数字~` 中，单位为元 → 需 ÷1e8 转亿

## 2.5 六大模块逐字稿

### 模块1：🎙️ 90秒盘后数据·口播逐字稿

结构：
1. **开场**：「各位观众晚上好，我是丁萌。」
2. **基调句**：一句话定性当日行情体感
3. **指数播报**：上证→深证→创业板（点数+涨跌幅）→科创50→北证50
4. **成交额**：精确值 + 放量/缩量XX亿 + 一句话解读
5. **涨跌家数**：XX涨 vs XX跌 + 涨停/跌停
6. **板块分化**：涨幅前三（板块+涨幅+主力净流入）→ 跌幅前三
7. **北向成交**：总成交额 + 占比 + 沪/深前三标的（先总后分结构）
8. **北向说明**：「自2024年8月起，北向资金当日净流入/净流出已不再按日披露，目前能看到的是成交额和活跃个股数据」
9. **点睛句**：口语化总结，如「科创50的夏天，其他大多数股票的春天还没有来」

**表演标记**：关键位置加【停顿】【语气转为…】标记，使文本有节奏感。

### 模块2：📰 新闻速览

- 5-8条按重要性排序
- 每条带情绪标记（😤/😊/🤔/💪）
- 比对前一日去重
- 排序优先级：央行操作→关键经济数据→重大政策→盘中突发→美股/港股→汇率→期货→行业新闻

### 模块3：🔍 分条详细播报

- 每条100-200字口语化解读
- 不只描述现象，要**给分析框架**（虹吸效应/传导逻辑/铁三角等）
- 嵌入历史对比锚定
- 末尾加「其他重要资讯速览」汇总段

### 模块4：📈 收盘点评

| 元素 | 要求 |
|:-----|:------|
| **核心特征** | 2-3个数字化特征点 |
| **核心矛盾** | 一句话提炼多空冲突 |
| **多空对比表** | 信号 \| 多头 \| 空头 \| 格式 |
| **历史对比** | 当前行情像历史上哪个阶段？像在哪？不同在哪？ |
| **风险预警** | 至少3条，含量化阈值 |
| **操作建议** | 宏观/板块层面，**严禁个股买卖建议** |

末尾加：`> **⚠️ 市场有风险，投资需谨慎。以上内容仅供复盘参考，不构成任何投资建议。**`

### 模块5：🌍 每日市场心态主题

| 星期 | 关键词 | 映射 |
|:---:|:---|:---|
| 周一 | LIGHT | 看见真相，不靠预测靠看见 |
| 周二 | FIRMAMENT | 聚焦主线，忽略杂音 |
| 周三 | SEED | 各从其类，种什么收什么 |
| 周四 | SEASONS | 识别周期，春夏秋冬各做各的事 |
| 周五 | LIVING | 策略要有生命，能适应环境 |
| 周六 | DOMINION | 攻守兼备，该进攻时果断 |
| 周日 | REST | 强制停止，空仓是顶级利润 |

**必须融入当日核心矛盾**，不只讲好的一面。末尾加**明日锚点**——两个可观测指标。

> **执行示例（周四·SEASONS）**：
> ❌ 错误："今天是周四，主题是识别周期。春夏秋冬各做各的事。"
> ✅ 正确："今天是周四，主题是识别周期。今天科创50暴涨4.6%，但全市场下跌家数2722家——这不是春天的信号，这是结构性夏天的极端分化。当前季节适合持有主线，不适合追涨杀跌。明日锚点：①科创50能否站稳2100点以上；②两市成交额是否维持万亿以上。"

### 模块6：📋 信息源表格

至少8条来源，每条链接指向当日专项页面，不可用通用首页替代。

## 2.6 交付格式硬性规定

1. **先写文件到 vault，再出回复**：`write_file` 必须在回复输出之前完成
2. **落盘路径**：`操盘手骑士/04_产出/股市数据播报/2026/<M月>/每日复盘直播稿/YYYY-MM-DD-A股复盘直播稿.md`

4. **YAML字段规范**：无官方数据写 `null` + 注释说明机制变更
5. **信息源表格**：每条链接必须指向当日专项页面

## 2.7 写作质量标准（主人多轮修订沉淀）

### 数据完整度

| 数据项 | 要求 |
|:-------|:------|
| 涨跌家数 | ✅ **必填** —— 揭示"指数红、个股跌"的关键 |
| 北向成交额 | ✅ **必填** —— 成交额/占比/前三标的 |
| 涨停跌停 | ✅ **必填** —— 情绪温度计 |
| 数据来源注释 | ✅ YAML `#` 行内注释，标注来源 |

### 口播稿质量

| 维度 | 标准 |
|:-----|:------|
| 上证描述 | 给定性结论（如"几乎平收"），不只报点数 |
| 表演标记 | 加【停顿】【语气转换】做节奏标记 |
| 解释深度 | 不只描述现象，**给分析框架**（虹吸效应/传导逻辑） |
| 北向口播 | **先总后分**结构：总成交额→占比→前三标的 |
| 点睛句 | 定性要准，如"结构牛，不是全面牛" |

### 收盘点评深度

| 维度 | 标准 |
|:-----|:------|
| **历史对比** | 当前行情像历史上哪个阶段？像在哪？不同在哪？ |
| **虹吸效应** | 遇"指数涨、个股跌"时给出虹吸效应/结构牛解释框架 |
| **传导逻辑** | 海外→A股的因果链要说清楚，点明"估值锚"效应 |
| **明日锚点** | 两个可观测指标，有量化阈值 |

### 不放进日报的

| 模块 | 原因 |
|:-----|:------|
| ❌ **假设追踪表** | 日报不做假设验证——那是周度审计的事 |
| ❌ **最终修订清单** | 读者不需要知道修订过程 |
| ❌ **主持人串词** | 去掉"好的，接下来我们看……"这类过渡 |
| ❌ **元内容** | 无检查清单、版本说明等 |

## 2.8 交易日 Pitfalls

1. 腾讯API返回GBK编码 → 必须 `iconv -f GBK -t UTF-8`
2. **涨跌分布**：同花顺网页端已403需登录，改用东方财富行情页(quote.eastmoney.com/zs000001.html)通过浏览器提取页面顶部静态文本（上证涨/平/跌数）
3. 东方财富push2.eastmoney.com curl不可用 → 仅浏览器JS
4. 东方财富 global/us/hk/futures 系列 → 全部404（已下线），改用腾讯API+新浪财经
5. 百度搜索弹出验证码 → 不可用
4. 成交额单位：腾讯API返回元 → 需÷1e8转亿
5. browser-heavy任务容易达到50次迭代上限 → 用delegate_task拆分
6. **北向资金**自2024年8月起不再按日披露净流入，仅记录成交额（`north_turnover`），**严禁编造净流入数据**
7. **美联储主席信息**必须核实身份+事件日期：沃什2026-05-22就任，6月17日首次FOMC
8. **成交额**不可同时写"精确值"和"约"
9. **数据缺失时禁止编造数据** → 宁愿标"—"也不造假
10. **所有curl调用必须加 `--max-time 15`**，防止单次请求卡死全流程
11. **局部数据缺失** → 标记 `data_quality: partial` 而非放弃全任务
12. **每日去重**必须读前一日文件的 top_news
13. **市场心态主题**必须按当日星期映射，不可错位

# 第三部分：休市日

## 3.1 核心理念

**休市日≠信息真空，而是"回顾整理+前瞻预期"的黄金窗口。** 回答三个问题：
1. **本周市场验证了什么？**（周六型·周度审计）
2. **下周市场可能发生什么？**（周日型·策略推演）
3. **我们的判断框架是否需要修正？**（月度元复盘）

## 3.2 休市类型判断

```
休市类型判断：
├── 周六（或节假日首日）→ 【周六型·周度审计】
├── 周日（或节假日第二/三日）→ 【周日型·策略推演】
├── 节假日连续第3天及以上 → 【长假守望型】
├── 距下一交易日 ≤ 1天 → 【收假前交易计划】（强制覆盖）
└── 每月第一个周六 → 附加【SOP健康度自检报告】
```

### 重大突发事件触发重定向

与第一部分 1.1 节同。

## 3.5 休市日七大模块

| 模块 | 说明 |
|:---|:---|
| 1️⃣ 开场 | 休市状态 + 本周核心发现 |
| 2️⃣ 本周行情回顾 | 指数/量能/板块数据表 |
| 3️⃣ 新闻回顾 | 5-10条带情绪标记 |
| 4️⃣ 四维深度拆解 | 定价逻辑→筹码结构→PEG估值→跨周期对标（至少3个维度） |
| 5️⃣ 假设追踪表 | 上周猜测验证 + 新假设注册 |
| 6️⃣ 节后观察点 | 5个关键观察点 |
| 7️⃣ 市场心态主题+信息源 | 休市日变体 + ≥8条来源 |

完整模板参考《A股每日复盘与休市审计 · 操作手册（人类阅读版）》第三部分。核心变更：
- 周六型周度审计 → 假设追踪表必填
- 周日型策略推演 → 情景推演矩阵（≥3个情景）
- 长假守望 → 外盘每日更新
- 收假前 → 仓位管理 + 开盘关注清单

## 3.6 休市日 Pitfalls

1. 假设验证时必须查上周实际数据，不可凭记忆"感觉"验证
2. 四维深度拆解**至少覆盖3个维度**
3. PEG估值必须用真实可查的数据
4. 跨周期对标必须找到**具体年份/行情名称**
5. 北向资金净额禁止编造（已不再按日披露）
6. 数据缺失时禁止编造 → 宁愿标"—"也不造假

# 第四部分：Cron 配置说明（云端 Hermes）

## 4.1 任务配置

```
cronjob(action='create',
  name="每日A股复盘稿生成",
  skills=["a-share-market-review", "a-share-holiday-review"],
  schedule="18 18 * * *",
  deliver="origin,local",
  enabled_toolsets=["web", "terminal", "file", "browser", "search", "delegation"],
  prompt="判断是否为交易日。交易日则生成今日A股复盘。\n\n【数据采集】使用 delegate_task 并行采集...\n\n【文件落盘】write_file 存入：操盘手骑士/04_产出/股市数据播报/<M月>/每日复盘直播稿/YYYY-MM-DD-A股复盘直播稿.md\n\n【回复】干净简报 + --- + 文件路径。"
)
```

## 4.2 关键配置要点

| 项 | 值 | 原因 |
|:---|:---|:------|
| 时间 | `18 18 * * *` | 收盘后30分钟，数据就绪 |
| 双路径 | `deliver: origin,local` | 微信通知 + 文件落盘 |
| toolsets | 含 `delegation` | 必须能并行采数 |
| 技能 | 加载2个 | 交易日判断 + 复盘生成 |

## 4.3 本地 Agent 替代方案

本地 Windows Hermes 不跑 cron，主人手动触发时：
1. 读本 SOP（当前文件）了解完整流程
2. 按【第二部分：数据采集策略】用 delegate_task 并行采数
3. 按【2.5 六大模块】生成报告
4. 按【2.6 交付格式】write_file 落盘
5. 输出干净简报给主人

# 第六部分：全局 Pitfalls 汇总

1. 腾讯API返回GBK编码 → 必须 `iconv -f GBK -t UTF-8`
2. **涨跌分布**：同花顺网页端已403需登录，改用东方财富行情页(quote.eastmoney.com/zs000001.html)通过浏览器提取页面顶部静态文本（上证涨/平/跌数）
3. 东方财富push2.eastmoney.com curl不可用 → 仅浏览器JS
4. 东方财富 global/us/hk/futures 系列 → 全部404（已下线），改用腾讯API+新浪财经
5. 百度搜索弹出验证码 → 不可用
4. 成交额单位：腾讯API返回元 → 需÷1e8转亿
5. browser-heavy任务容易达到50次迭代上限 → 用delegate_task分批
6. **北向资金**自2024年8月起不再按日披露净流入，仅记录成交额（`north_turnover`），**严禁编造净流入数据**
7. **美联储主席信息**必须核实身份+事件日期（沃什2026-05-22就任）
8. **成交额**不可同时写"精确值"和"约"
9. **数据缺失**时禁止编造数据 → 宁愿标"—"也不造假
10. **所有curl调用必须加 `--max-time 15`**
11. **局部数据缺失** → 标记 `data_quality: partial` 而非放弃全任务
12. **每日去重**必须读前一日文件的 top_news
13. **市场心态主题**必须按当日星期映射，不可错位
