## 🔄 核心变化说明

### 一、逻辑架构优化（8 项 P0 + 8 项 P1）

**1. 宪法层级关系重写**
- HERMES 与总纲的关系从「冲突时以 HERMES 为准」变为宪法层最高规范
- HERMES 仅在操作协议层面优先，数据模型层面严格遵循总纲

**2. human_edited 字段语义拆分**
- `human_edited: true` = AI 写入权限锁（禁止 Agent 覆盖正文）
- `deep_reviewed: true` = 已完成至少一轮人工深回流修正（仅适用于语言组块笔记）
- 存量兼容：旧版 `human_edited: true` 不自动推断为已深回流

**3. PARA/ZK 归属裁决链 + 结项萃取检查点**
- 项目产出内容归属判定：纯项目专属 → 10_Projects/；通用可复用 → 31_Atomic_Notes/
- 项目归档前必须执行萃取扫描，输出 Top 5 建议清单
- 人类逐项决策后写入 `extraction_decision` 字段

**4. L3 特化层元数据豁免权**
- 语言组块笔记和食谱笔记允许新增领域专属扩展元字段
- 不计入 META-02 的 12 个字段通用统计上限
- 核心字段（title/date/status/tags/type）必须保留且格式一致

**5. 各层准入标准模板**
- L0 宪法层：总纲 + HERMES
- L1 方法论层：融合架构、原子笔记炼金术、Language Chunk 炼金术士
- L2 操作层：Ingest、归档、双链、MOC、日工作流等操作规范
- L3 素材特化层：食谱笔记、语言组块笔记
- L4 辅助层：速查卡、目录映射表、架构索引、依赖关系图、Skill 清单

**6. 各目录准入状态定义**
- `00_Inbox/`：仅 `draft`
- `10_Projects/`：`draft` / `active`
- `20_Areas/`：`draft` / `active` / `mature` / `deprecated`
- `30_Resources/31_Atomic_Notes/`：`active` / `mature` / `deprecated`（禁止 `draft` 和 `archived`）
- `40_Archive/`：仅 `archived`

**7. Skill 漂移检测规则升级**
- 触发条件基于变更类型（规则类变更 vs 示例类变更）
- 累积提醒升级（首次提醒 → 二次高亮 → 三次强制确认）
- 关键外部依赖清单（API 端点、CLI 命令）

**8. L4 保鲜机制**
- 速查卡头部增加保鲜声明和同步日期
- 依赖关系图增加 L4 保鲜绑定规则
- 循环依赖红线：禁止形成循环依赖链
