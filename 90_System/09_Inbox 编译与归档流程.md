# 17_Inbox 编译与归档流程

> **地位声明**：本文件是 `00_Inbox/` 素材的编译与归档规范。所有外部素材导入、格式转换、提炼、归档操作均以此为准。
>
> **版本**：v1.0.0
> **生效日期**：2026-07-11
>
> **执行层文档**：本文件是规则标准。具体执行流程、脚本、故障排查见 `atomic-note-extraction` Skill。
>
> **对应 Skill**：`atomic-note-extraction`（执行时自动加载）

## 一、核心铁律

### 1.1 归档安全铁律

| 铁律 | 说明 |
|:---|:---|
| **归档时只移动指定文件** | 🔴 禁止清空目标目录 |
| **禁止 `rm -rf`/`rm -f`/`find -delete`** | 这些命令会删除目标目录所有文件 |
| **直接 `mv` 或 `cp` 指定文件** | Bash 会自动覆盖同名文件 |

### 1.2 大文件处理铁律

| 铁律 | 说明 |
|:---|:---|
| **禁止 `write_file` 处理 >300KB 文件** | 易超时失败 |
| **必须使用 `terminal` + Python 脚本** | 直接处理文件，避免工具限制 |

### 1.3 原文保留铁律

| 铁律 | 说明 |
|:---|:---|
| **原文不得直接删除** | 必须校准 YAML 后归档 |
| **归档 ≠ 精简总结** | 保留原文核心内容，只删除营销冗余 |
| **归档文件大小应接近原文** | 不应只有原文的 10-20% |

## 二、Inbox 目录结构

```
00_Inbox/
├── 00_Inbox.md          # MOC 索引
├── _raw/                # 外部导入临时存放
│   ├── 文章标题-日期-来源.md
│   └── ...
└── 外部导入/            # 批量导入临时存放
    └── ...
```

### 2.1 `_raw/` 用途

| 场景 | 说明 |
|:---|:---|
| **Ingest 编译输入** | Hermes 自动编译 `_raw/` 中文件 |
| **单文件处理** | 从 Get 笔记、微信等导入的单篇文章 |
| **临时存放** | 处理完成后归档到 `40_Archive/` |

### 2.2 `外部导入/` 用途

| 场景 | 说明 |
|:---|:---|
| **批量导入** | 课程、书籍等批量素材 |
| **人工处理** | 需要人工筛选、去重 |
| **暂存** | 提炼期间留在 Inbox，提炼完成后再归档 |

## 素材入口统一化规则

### 统一入口

所有外部导入（单篇剪藏、批量课程、微信转发、API 抓取）
→ 一律放入 `00_Inbox/_raw/`。

`00_Inbox/外部导入/` 不再作为主动使用的入口。
存量文件保留原位，新建导入不再使用此路径。

### 后置分流标记

素材进入 `_raw/` 后，人类可通过以下方式指示 Hermes 处理方式：

|| 标记方式 | 标记值 | Hermes 行为 |
|:---|:---|:---|
| 文件名含 `_auto` | — | 触发完整 Ingest 流程 |
| 文件名含 `_archive` | — | 仅清理营销冗余 + 校准 YAML + 归档 |
| 文件名含 `_manual` | — | 不自动处理，等待人类显式指令 |
| YAML `ingest_mode` | `auto` / `archive` / `manual` | 同文件名标记 |

### 标记优先级与兜底规则

1. **标记优先级**：`_manual` > `_archive` > `_auto`
   文件名同时含多个标记时，按最高优先级处理。

2. **文件头部标记（兜底方案）**：
   若文件名不含标记，Hermes 检查 **YAML FrontMatter 中是否存在 `ingest_mode` 字段**
   （值为 `auto` / `archive` / `manual`）。YAML 字段优先级低于文件名标记。

3. **无标记文件的默认行为**：
   - 默认按 `_auto` 处理，但增加**冷静期预览**：
     - Agent 先清理冗余 + 生成 AI 摘要预览（放入 `30_Resources/33_Summaries/`）
     - 冷静期以文件的 `ctime`（创建时间）为计算起点，自然日计数
     - 3 天内人类未干预，Agent 自动触发完整 Ingest 流程
   - 冷静期内，每日晚间简报列出"待确认自动处理"的素材清单
   - 人类可在冷静期内通过对话指令中止自动处理
     （示例：`暂缓处理 笔记标题.md`）
   - 无标记素材处理后，记录至当月 Worklog 的「Ingest 操作日志」区块：
     「文件 XX 无分流标记，已按 _auto 处理」

## 三、编译流程

### 3.1 完整流程

```
步骤0：前置确认
  ├─ 触点判定（是否与当前思考相关）
  └─ 输出范围确认（提炼 + 校准 + 归档）

步骤1：格式转换
  ├─ txt → md（大文件用 Python）
  └─ 去除行号、添加章节结构

步骤2：内容分析与去重
  ├─ 识别文件类型（目录/单课/合集/总结/逐字稿）
  └─ 判断重复关系

步骤3：排版与格式优化
  ├─ 添加 YAML frontmatter
  └─ 添加来源说明和用途标注

步骤4：原子笔记提炼
  ├─ 闪念捕捉（零批判）
  ├─ 触点判定（即时/潜在启发）
  ├─ 提纯（一句话概括）
  ├─ 转译（用自己的话重写）
  ├─ 建立对话链接
  └─ 播种（开放问题）

步骤5：校准原文 YAML
  ├─ tags 从 16 种字典选择
  ├─ status 设为 archived
  └─ 删除非标准字段

步骤6：归档原文
  ├─ 删除营销冗余（图片链接、营销话术）
  ├─ 保留核心内容
  └─ 移动到 40_Archive/[领域]/
```

### 3.2 提炼粒度原则

| 原则 | 说明 |
|:---|:---|
| **宁可拆细不拆粗** | 独立概念即使"太窄"也值得成页 |
| **完整覆盖** | 从目录识别所有关键词，不主观筛选 |
| **判断标准** | 是否有独立定义？是否可能被独立引用？ |

## 四、归档路径规范

### 4.1 原子笔记归档

```
原子笔记 → 30_Resources/31_Atomic_Notes/[标签领域]/[type]/笔记名.md
```

**路径规则**：
- 第一层：标签领域（16 种字典之一）
- 第二层：type 类型（概念/模型/实践/批判）
- 文件名：纯概念名（无出处后缀）

### 4.2 原文归档

```
原文 → 40_Archive/[领域]/[原标题].md
```

**领域层级逻辑（技术类特殊处理）**：

```
技术/
  └─ AI/
      └─ Agent/
          └─ Hermes Agent/
```

**归档示例**：
- Hermes Agent 文章 → `40_Archive/技术/AI/Hermes Agent/`
- 心理学文章 → `40_Archive/心理学与行为科学/`
- 国际政治文章 → `40_Archive/国际政治/`

## 五、YAML 校准规范

### 5.1 原文必填字段

```yaml
---
title: [原标题]
date: [原创建日期]
status: archived
tags: [16种字典之一]
source: [来源名称，非URL]
author: [原作者]
aliases: []
related: []
---
```

### 5.2 原子笔记必填字段

```yaml
---
title: [笔记标题]
date: YYYY-MM-DD
status: active
type: concept | model | practice | critique
tags: [16种字典之一]
source: [来源名称]
author: [原作者]
aliases: []
related: []
---
```

### 5.3 校准检查清单

- [ ] `tags` 是否从 16 种字典选择？
- [ ] `status` 是否为正确值？
- [ ] 原子笔记是否填写 `type`？
- [ ] `source` 是否为来源名称（非 URL）？
- [ ] 是否删除了非标准字段？

## 六、删除营销冗余规范

### 6.1 删除内容

| 类型 | 示例 |
|:---|:---|
| **图片链接** | `![](https://...)` |
| **营销话术** | "如果你也受够了..."、"赶紧收藏..." |
| **过度格式** | 多余分隔线、表情符号堆砌 |

### 6.2 保留内容

| 类型 | 说明 |
|:---|:---|
| **核心观点** | 文章的主要论点 |
| **关键步骤/配置** | 技术细节 |
| **机制解释** | 因果关系说明 |
| **论据/依据** | 支撑观点的材料 |
| **案例说明** | 具体例子 |

### 6.3 特殊情况

| 情况 | 处理方式 |
|:---|:---|
| **营销参考文章** | 保留完整原文（含营销话术） |
| **技术教程** | 保留所有代码和配置 |

## 七、检查清单

### ✅ 编译前必检

- [ ] 确认触点判定结果
- [ ] 确认输出范围
- [ ] 大文件确认处理方式（Python 脚本）

### ✅ 归档前必检

- [ ] YAML 是否校准完成？
- [ ] 归档路径是否正确？
- [ ] 目标目录是否有同名文件（会覆盖）？

### ✅ 归档后必检

- [ ] 归档文件大小是否合理（接近原文）？
- [ ] 原子笔记是否按 type 分类到子目录？
- [ ] 双链引用是否可点击跳转？

### 🔴 STOP 信号

遇到以下情况**立即停止**，人工确认：

- ❌ 大文件用 `write_file` 处理
- ❌ 准备执行 `rm -rf`/`rm -f`/`find -delete`
- ❌ 归档文件只有原文 10-20% 大小
- ❌ 不确定是否应该删除某个文件
