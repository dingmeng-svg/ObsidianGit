# 食谱编写标准 (Recipe File Standard) v1.0

> **版本**：v1.1（吸收 Ingest SOP 的 AI 协作规范）
> **最后更新**：2026-07-11
> **规范引用**：完整编码、命名、标签、目录、元数据规范详见 [[01_知识库统一规范总纲|总纲 v3.0]]，本文档仅为专项流程补充，不替代总规范。

> 一份清晰好用的食谱文件，应该包含标准化的元数据、分层的食材清单、清晰的步骤说明以及可选的技术要点。本标准提供了一套可直接复用的模块化模板。
>
> 配套元数据规范 §6：[[知识库元数据规范 (Metadata Specification) v2.0#§6 食谱笔记标准]]

---

## 1. 文件组织

按菜系或餐品类型划分子目录，归类至 `23_生活与健康/食物/` 下：

```
23_生活与健康/食物/
├── 中餐/          # 中式炒菜、炖菜、汤品
├── 烘焙/          # 烤箱菜、油封、面包等
├── 营养/          # 杂粮饭、能量饭等主食配方
├── 甜品/          # 按需扩展
└── 酱料/          # 按需扩展
```

跨类别的食谱归入主类别，目录名使用简洁的中文即可。

---

## 2. 文件命名规则

```
菜名.md
菜名（版本说明）.md          # 存在多个版本时
菜名 – 出处.md               # 有明确来源时
```

**示例：**
- `金汤肥牛.md` ✅
- `炒花菜（脆嫩版）.md` ✅
- `黄金全谷物饭·无豆纯谷物版.md` ✅
- `淮扬菜蟹粉狮子头 – 薛泉生.md` ✅

避免在文件名中使用"食谱""recipe"等冗余字眼。

## 4. 正文模块体系

食谱正文由以下模块按需组合。**必选模块**用 ✅ 标注，推荐用 ⭐，可选用 ◻。

### 模块 A — 一句话核心 ⭐ 推荐

写在正文开头，用引用块概括这道菜的关键。

```markdown
> **核心要点**：一句话点明最关键的 1～2 个技术要点。
```

示例：
```markdown
> **核心要点**：金汤的金色来源于**南瓜泥**和**黄灯笼辣椒酱**，酸辣开胃，肥牛嫩滑。
```

简单食谱（如杂粮饭配方）可用普通段落替代。

### 模块 B — 食材清单 ✅ 必选

至少提供一组清晰的食材列表，建议按主料、辅料、调味料分组。

**表格版（推荐）：**

```markdown
## 食材清单

### 主料
| 材料 | 用量 | 备注 |
|:---|:---|:---|
| 牛肋条 | 1000g | 切 2-3cm 块 |

### 调味料
| 材料 | 用量 | 备注 |
|:---|:---|:---|
| 生抽 | 3 汤匙 | |
| 盐 | 适量 | 最后放 |
```

**简化版（食材较少时）：**

```markdown
## 食材清单
- **鸡腿**：2 个（约 400g）
- **大蒜**：5 瓣（切片）
```

用量精确到克/ml/个，模糊用量用"适量"。每项带备注（处理方式如"切段"、"去皮"）。

### 模块 C — 烹饪步骤 ✅ 必选

按时间顺序描述烹饪流程，每一步用三级标题。

```markdown
## 烹饪步骤

### 1. 预处理
- 具体操作
- ⚠️ **关键提示**：注意事项
```

- 每个标题是明确的动宾短语
- 关键操作 **加粗** 强调
- 技术原理可用 `> *斜体注释*` 附加说明
- 步骤建议不超过 6 个大步

### 模块 D — 技术关键点 ⭐ 推荐

用表格列出易错步骤的正确做法。

```markdown
## ⚠️ 技术关键点

| 关键步骤 | 常见错误 | 正确做法 |
|:---|:---|:---|
| 焯水 | 热水下锅 | 冷水下锅，撇净浮沫 |
| 收汁 | 大火收干 | 中小火至浓稠 |
```

有 3 个以上易错点时就建议使用此模块。

### 模块 E — 可选变种 ◻ 可选

提供同一道菜的不同做法变体。

```markdown
## 🌟 可选变种

### 变种名称
- 与主版本不同的操作（只写差异部分，不必重复完整步骤）
```

### 模块 F — 优化小贴士 ◻ 可选

零散的技巧、经验，不适合放入关键点表格的内容。

```markdown
## 💡 优化小贴士
- **防粘技巧**：煎鱼前用厨房纸彻底擦干水分
```

### 模块 G — 常见问题 ◻ 可选

以 Q&A 形式解答真实试做中可能遇到的问题。多个原因用 ①②③ 编号。

```markdown
## ❓ 常见问题

**Q：为什么肉质发柴？**
A：可能原因：① 火候过大；② 炖煮时间不足。
```

只收录真实试做经验，不要硬编问题。

### 模块 H — 总结口诀 ◻ 可选

用顺口溜总结步骤，便于记忆。

```markdown
## 📌 总结口诀
> 冷水下锅去血沫，小火慢炖莫开锅。
```

2-4 句，押韵优先。

### 模块 I — 保存与食用建议 ◻ 可选

成品保存方法、复热方式和搭配建议。

```markdown
## 📦 保存与食用
- **冷藏**：密封保存 7-10 天
- **冷冻**：可存 3 个月
- **复热**：微波中火 2 分钟
- **搭配建议**：配面包、意面，或作为开胃小菜
```

## 5. 完整示例

```markdown
difficulty: 2
ingredients_main: [牛肋条, 番茄]
diet_type: [低碳, 无麸质]
difficulty_display: "★★"
temperature: "小火慢炖"
rating: 5
source: "自研改良"
date: 2026-07-03
status: active
tags:
- 生活

# 番茄牛肋条

> **核心要点**：牛肋条要**软烂但保持形状**，番茄必须**炒出红油沙**，汤汁**浓稠红亮**。全程小火慢炖，中途不加水（如必须则加开水）。

---

## 食材清单

### 主料
| 材料 | 用量 | 备注 |
|:---|:---|:---|
| 牛肋条 | 1000g | 切 2-3cm 块 |
| 番茄 | 4-5 个（约 600g） | 去皮切丁 |

### 香料
- **花椒**：10-15 粒
- **八角**：1-2 颗
- **桂皮**：1 小段

### 调味料
| 材料 | 用量 | 备注 |
|:---|:---|:---|
| 黄冰糖 | 15-20g | |
| 生抽 | 3-4 汤匙 | |
| 盐 | 适量 | 最后加 |

## 烹饪步骤

### 1. 预处理
- 牛肋条冷水下锅，加花椒，煮沸撇沫，捞出温水洗净
- 番茄烫去皮，切小丁

### 2. 炒香
- 中小火炒香八角、桂皮、花椒，加入番茄丁炒至出红油沙

### 3. 煸炒
- 加入牛肋条翻炒，加冰糖、生抽炒匀

### 4. 焖煮
- 加入**开水**没过食材，转小火微沸焖煮 1.5 小时
- ⚠️ 中途不加水

### 5. 调味收汁
- 牛肉软烂后加盐，开大火收至汤汁浓稠

## ⚠️ 技术关键点

| 关键步骤 | 常见错误 | 正确做法 |
|:---|:---|:---|
| 焯水 | 热水下锅 | 冷水下锅 |
| 番茄处理 | 不去皮直接炖 | 去皮炒出红油沙 |
| 加水 | 加冷水 | 加开水，一次加足 |
| 加盐 | 提前加 | 最后加 |

## 🌟 可选变种

### 高压锅速成版
焯水后所有材料（盐除外）入高压锅，加开水，上汽后压 25-30 分钟，自然泄压后收汁。

## 💡 优化小贴士
- 颜色更红亮可加一小勺番茄酱
- 剩余可冷藏 3 天，冷冻 1 个月

## ❓ 常见问题

**Q：炖了 2 小时牛肉还是硬？**
A：可能用了冷水或火太大，可转高压锅压 15 分钟补救。

## 📌 总结口诀
> 牛肋冷水焯血沫，番茄炒沙红油泼。  
> 开水一次加足量，小火慢炖莫开锅。

---

_本文档为个人整理的中式家常菜谱，归档备查。_
```

## 6. 模块选用建议

| 食谱复杂度 | 必选模块 | 推荐模块 |
|:---|:---|:---|
| 极简（★） | B 食材 + C 步骤 | A 一句话 |
| 简单（★★） | B 食材 + C 步骤 | A 一句话 + D 关键点 |
| 中等（★★★） | B 食材 + C 步骤 | A 一句话 + D 关键点 + G 常见问题 |
| 困难（★★★★★） | B 食材 + C 步骤 + D 关键点 | A 一句话 + G 常见问题 + I 保存建议 |

通用规则：
- 至少包含模块 B + C
- 模块 D 只要有 2 个以上易错点就应该写
- 模块 H（口诀）推荐难度 ★★ 及以上使用
- 正文最后一个模块后加 `---` 分隔线，再接 `_归档尾注_`

## 8. AI 协作规范（Hermes Ingest 集成）

> **来源**：`14_Hermes Ingest 编译与原子笔记生产规范`

### 8.1 核心信条

> **一份食谱，是一次可以反复唤醒的烹饪经验封装。它不是菜谱的复刻，而是你在厨房中与未来自己的一次对话邀请。**

### 8.2 工作哲学

- **书写即思考**：食谱不是烹饪的产物，而是烹饪的载体本身。通过书写来沉淀技艺，而非记录已有技艺。
- **对话优于存储**：每份食谱的价值不取决于它记录了多少步骤，而取决于它能在未来引发多少次成功的复现与改良。
- **张力优于闭合**：宁可保留"待验证"、"疑似可优化"的标记，也不制造虚假的确定性。

### 8.3 Ingest 编译流程

当食谱素材进入 `00_Inbox/_raw/` 时，Hermes Ingest 会自动处理：

1. **识别素材类型**：包含食材清单、烹饪步骤 → 食谱类
2. **生成摘要**：提取核心要点、食材、步骤概览
3. **提炼食谱笔记**：
   - 若已有同名食谱且 `human_edited: true` → 仅文末追加 `## 🤖 Hermes 补充`
   - 若无或无标记 → 新建食谱笔记，执行首次写入协议
4. **归档原文**：校准 FrontMatter 后移入 `40_Archive/生活/`

### 8.4 提炼决策树

```
素材进入 _raw/
    │
    ├─ 是否包含食材清单 + 烹饪步骤？
    │   ├─ 否 → 按「原子笔记」路径处理（观点/概念提炼）
    │   │
    │   └─ 是 → 食谱类判定
    │            │
    │            ├─ 是否为完整菜谱？
    │            │   └─ 是 → 按本标准提炼食谱笔记
    │            │
    │            ├─ 是否仅为烹饪技巧/要点？
    │            │   └─ 是 → 提炼为「实践」类原子笔记
    │            │
    │            └─ 无法判断 → 仅归档，不提炼
```

### 8.5 异常处理（if-then）

|| 触发条件 | 处理方式 |
|:---|:---|
| 素材缺少核心信息（无食材或步骤） | 仅归档，不提炼 |
| 食材用量模糊（"适量"、"少许"） | 标注 `#待精确化`，保留原表述 |
| 已有同名食谱（`human_edited: true`） | 仅文末追加补充，不覆盖正文 |
| 发现更优做法 | 新建变种章节，不替换原有步骤 |
