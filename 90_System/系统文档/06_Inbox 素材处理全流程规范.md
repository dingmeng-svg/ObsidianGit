# 06_Inbox 素材处理全流程规范

> **地位声明**：本文由原 06/09/23/11 四份文档合并而成，替代原文档。本文件是 `00_Inbox/` 素材从入口到归档的完整处理规范。

> **版本**：v1.0.0
> **生效日期**：2026-07-13
>
> **对应 Skill**：`atomic-note-extraction`

## 核心信条（最高原则）

> **一条原子笔记，是你与自己未来的一次对话邀请。它不是答案，而是思想接口。**

Ingest 编译的目标不是"整理信息"，而是生产能够持续对话的思考节点。此信条是所有规则的宪法。

### 工作哲学

| 原则 | 说明 |
|:---|:---|
| **书写即思考** | 笔记不是思考的产物，而是思考的载体本身。通过编译来生产想法，而非记录已有想法。 |
| **对话优于存储** | 每条笔记的价值不取决于它记住了什么，而取决于它能引发什么对话。 |
| **张力优于闭合** | 宁可保留模糊的边界和未解决的矛盾，也不制造虚假的清晰和过早的闭合。 |

## 一、素材入口统一化规则（原 09）

### 1.1 统一入口

所有外部导入（单篇剪藏、批量课程、微信转发、API 抓取）→ 一律放入 `00_Inbox/_raw/`。

`00_Inbox/外部导入/` 不再作为主动使用的入口。存量文件保留原位，新建导入不再使用此路径。

### 1.2 后置分流标记

素材进入 `_raw/` 后，通过文件名或 YAML 字段指示 Hermes 处理方式：

| 标记方式 | 标记值 | Hermes 行为 |
|:---|:---|:---|
| 文件名含 `_auto` | — | 触发完整 Ingest 流程 |
| 文件名含 `_archive` | — | 仅清理营销冗余 + 校准 YAML + 归档 |
| 文件名含 `_manual` | — | 不自动处理，等待人类显式指令 |
| YAML `ingest_mode` | `auto` / `archive` / `manual` | 同文件名标记，优先级低于文件名 |

### 1.3 标记优先级与兜底规则

| 规则 | 说明 |
|:---|:---|
| **标记优先级** | `_manual` > `_archive` > `_auto`。文件名含多个标记时按最高优先级处理。 |
| **文件头部标记（兜底）** | 文件名不含标记时，检查 YAML FrontMatter 中 `ingest_mode` 字段。YAML 字段优先级低于文件名标记。 |
| **无标记默认行为** | 默认按 `_auto` 处理，但增加冷静期预览：Agent 先清理冗余 + 生成 AI 摘要预览（放入 `30_Resources/33_Summaries/`）。冷静期以文件 `ctime` 为起点，自然日计数。3 天内人类未干预，Agent 自动触发完整 Ingest 流程。冷静期内，每日晚间简报列出"待确认自动处理"的素材清单。人类可通过对话指令中止自动处理（示例：`暂缓处理 笔记标题.md`）。处理后记录至当月 Worklog 的「Ingest 操作日志」区块。 |

### 1.4 Inbox 目录结构

```
00_Inbox/
├── 00_Inbox.md          # MOC 索引
├── _raw/                # 外部导入临时存放（只读不改）
│   ├── 文章标题-日期-来源.md
│   └── ...
└── 外部导入/            # 批量导入临时存放（存量保留，新增不使用）
    └── ...
```

| 目录 | 用途 | 原则 |
|:---|:---|:---|
| `_raw/` | 编译输入源，单文件处理，临时存放 | 外部导入统一入口，系统自动 Ingest |
| `外部导入/` | 批量导入，人工处理，暂存 | 存量保留，新增不再使用 |

## 二、编译触发决策（原 23）

### 2.1 编译触发启发式

编译主动权完全在人类。以下条件是决策启发式——帮助快速判断哪个素材值得优先处理。

| 触发条件 | 判定标准 | 信号含义 |
|:---|:---|:---|
| **重复引用触发** | 同一素材内容/概念/观点在日记、周/月复盘、讨论记录中被提及 ≥ 3 次 | 素材已在思考和行动中反复出现，值得提炼为永久知识 |
| **季度确认触发** | Quarterly Review 中标记为"对当下核心目标有重要参考价值"或"解答了长期困惑的问题" | 素材与战略方向对齐，提炼后可直接支持决策 |
| **项目需求触发** | 正在推进的活跃项目直接需要该素材中的概念、方法论或数据 | 素材有即时实用价值，编译后能直接转化为产出 |
| **闪念升级触发** | 日记中围绕同一主题的闪念出现 ≥ 3 次（非外部素材，是你自己的想法） | 自己的思考已成熟，可以写原创原子笔记，`_raw` 素材为引用补充 |

### 2.2 编译反触发

以下情况建议暂不编译：

| 情况 | 处理方式 |
|:---|:---|
| 素材收藏后从未在日记中被提及 | 收藏冲动，非真实知识需求，暂不处理 |
| 素材观点与所有活跃项目无关，且短期内不会被用到 | 保持收藏，等待未来触发 |
| 素材内容已在其他原子笔记中充分覆盖 | 冗余，可直接删除 Raw 文件 |

### 2.3 冷静期机制（7 天）

| 规则 | 说明 |
|:---|:---|
| 冷静期起点 | 以文件 `ctime`（创建时间）为计算起点，自然日计数 |
| 冷静期预览 | 进入 `_raw/` 后，Agent 先清理冗余 + 生成 AI 摘要预览（放入 `30_Resources/33_Summaries/`） |
| 自动触发 | 3 天（无标记素材）/ 7 天（冷静期完整周期）内人类未干预，Agent 自动触发完整 Ingest 流程 |
| 人类干预 | 可在冷静期内通过对话指令中止自动处理（示例：`暂缓处理 笔记标题.md`） |

### 2.4 AI 主动提醒机制

即使未手动触发编译，Lint 健康检查在以下情况主动提醒：

| 条件 | 提醒内容 |
|:---|:---|
| Raw 素材被 ≥ 3 条笔记引用 | 提醒"建议编译" |
| Raw 素材闲置超过 60 天未被任何笔记引用 | 提醒"建议清理" |

> **注意**：AI 仅做提醒，不主动执行编译。是否编译始终由你决定。

### 2.5 编译执行

决定编译后，向 Hermes 发送指令：`请编译 00_Inbox/_raw/[文件名]`

执行流程：
1. 生成结构化摘要 → 归档至对应领域
2. 提取概念 → 查重后新建或追加 → `31_Atomic_Notes/`
3. 建立双向链接 → 更新 MOC
4. 被动推荐 → 从 Archive 检索相关旧笔记

## 四、AI 编译流程（原 06）

### 4.1 Ingest 编译规则

**四条铁律**（任何输出必须同时满足）：

| 铁律 | 要求 | Ingest 执行要点 |
|:---|:---|:---|
| **原子独立** | 一条笔记只承载一个不可再拆的思想单元 | 若需用"和"、"此外"、"另外"连接 → 拆分为多条笔记 |
| **问题/关系驱动** | 每条笔记必须能回答一个问题，或明确自己在知识网络中的角色 | 回应已有观点 / 界定新概念 / 提出开放疑问 |
| **对话导向** | 笔记内容必须是一个可被未来唤醒的对话接口 | 主张、疑问、反例、悖论，拒绝空洞口号 |
| **链接有理** | 任何强对话链接必须用一句话注明理由 | 链接格式：`链接至 [[笔记X]] \| 理由：提供了机制解释` |

**Ingest 编译步骤**：

1. 只处理 `_raw/` 中文件，或人类明确指定的路径
2. 生成摘要 → `33_Summaries/`
3. 提取概念 → 查 `31_Atomic_Notes/` 是否已有：
   - `human_edited: true` → 仅文末追加 `## 🤖 Hermes 补充`
   - 无标记 → 增量更新正文，记录 `last_ai_edit`
   - 不存在 → 新建，执行首次写入协议
4. 更新 MOC 链接，从 Archive 推荐 ≤3 篇历史笔记

### 4.2 提炼质量标准

**正文五种万能结构**：

| 类型 | 句式模板 | 适用场景 |
|:---|:---|:---|
| **主张/规律** | X现象的本质是Y。前提是Z。 | 提出明确的判断或规律 |
| **机制/因果** | 之所以A，是因为B导致了C。关键环节是D。 | 解释因果链条 |
| **疑问/猜想** | 为什么会出现X？一个可能的解释是Y，但这无法解释Z部分。待验证。 | 提出尚无法解答的问题 |
| **反例/边界** | 普遍认为A适用于B，但在情况C下，A会失效，因为D。 | 限定观点的适用范围 |
| **现象/隐喻** | X感觉像Y，虽然它们在逻辑上无关。这暗示了一种可能的关系是Z。 | 容纳前逻辑的思想 |

**链接类型区分**：

| 类型 | 要求 | 格式 |
|:---|:---|:---|
| **强对话链接** | 必须注理由（包含动词）。禁止空洞词汇："相关"、"类似"、"有意思" | `链接至 [[笔记X]] \| 理由：提供了机制解释` |
| **弱索引链接** | 允许留白，但必须标注 `#待补理由` | 用于直觉链接的占位符 |

**播种**（为涌现预留接口）：

在每篇原子笔记末尾，刻意留下开放问题：

```markdown
**播种**：
1. [浅层：如何落地应用？]
2. [中层：什么条件下失效？]
3. [深层：前提被推翻会怎样？]
```

**提炼决策树**（什么值得提炼）：

```
素材进入 _raw/
    │
    ├─ 是否包含明确观点/概念？
    │   ├─ 否 → 仅生成 Summary，不提炼原子笔记
    │   │        （如纯新闻、事实陈述）
    │   │
    │   └─ 是 → 触点判定
    │            │
    │            ├─ 即时启发：直接回应当前思考问题？
    │            │   └─ 是 → 提炼
    │            │
    │            ├─ 潜在启发：具备跨界冲突、反常识、新机制？
    │            │   └─ 是 → 提炼
    │            │
    │            └─ 两者皆否 → 仅归档，不提炼
    │                         （标注：#待用户确认 是否需要提炼）
```

**提炼粒度原则**：

| 原则 | 说明 |
|:---|:---|
| **宁可拆细不拆粗** | 提取出的独立概念不要因为"看起来太窄"就跳过。姜枣茶、曲荷丸、五运六气等具体概念在各自领域有独立引用价值。 |
| **判断标准** | 该概念是否有独立的定义和论述？是否可能被其他笔记独立引用？如果两者都是肯定则值得成页。 |
| **完整覆盖** | 从目录识别所有关键词，不主观筛选。 |
| **碰撞测试优先** | 投喂一篇已做过笔记的文章入 `_raw/`，一次测试验证新建路径和碰撞路径两条核心链路。 |

### 4.3 异常处理（if-then 三段式）

| 触发条件 | 一线修复 | 仍失败兜底 |
|:---|:---|:---|
| **素材极度模糊**（无明确观点） | 仅生成 Summary，不提炼原子笔记 | 标注 `#待澄清`，建议用户提供上下文 |
| **找不到强对话链接对象** | 使用虚拟对话对象："若存在关于X的笔记，本笔记将..." | 仅保留弱链接，标注 `#待补理由` |
| **素材包含多个独立观点** | 立即拆分为多条笔记，每条一个观点 | 标注 `#待拆分`，列出拆分清单 |
| **碰撞保护触发**（`human_edited: true`） | 仅文末追加 `## 🤖 Hermes 补充` | 在 `audit/resolved/` 生成建议文档 |
| **提炼后篇幅超过原文 50%** | 检查是否保留冗余案例，删除 | 标注 `#待精简`，展示可删除段落 |

### 4.4 通用 AI 协作规则

#### 首次写入协议

新建 AI 页面时：`ai_generated: true` + `status: draft` + 顶部 Callout：

> [!note] 🤖 Hermes 自动生成 · 待人类审核
> 如需保留并防止 AI 后续覆盖，请在 YAML 中添加 `human_edited: true`。

#### 碰撞保护

| 规则 | 说明 |
|:---|:---|
| `human_edited: true` | 人类编辑保护锁，AI 禁止覆盖正文。若 YAML 中无此字段，视为 `false`。 |
| 碰撞保护触发 | 仅文末追加 `## 🤖 Hermes 补充`，不修改正文。 |
| 增量更新 | 无 `human_edited` 标记的笔记，AI 可增量更新正文，记录 `last_ai_edit` 和 `ai_edit_summary`。 |

#### YAML 字段（v1.4）

| 字段 | 用途 | 适用 |
|:-----|:------|:-----|
| `ai_generated: true` | 标记 AI 编译产物 | 原子笔记/摘要 |
| `human_edited: true` | 人类编辑保护锁，AI 禁止覆盖正文 | 原子笔记（若无此字段视为 `false`） |
| `last_ai_edit: YYYY-MM-DD` | 最近 AI 增量修改日期 | 被更新的原子笔记 |
| `ai_edit_summary: "..."` | AI 修改内容简述 | 被更新的原子笔记 |
| `audit: "high: ..."` | 反馈信号 | 全库 |

#### AI 能力边界

| 边界 | 规则 |
|:---|:---|
| **判断权边界** | AI 只负责执行"如何提炼"，不代替用户决定"什么值得提炼"。触点判定模糊时，必须追问用户确认。 |
| **幻觉防护** | 建立链接时只能基于知识库检索结果。❌ 禁止凭空编造不存在的笔记标题或链接对象。 |
| **张力保护** | 面对高度混沌、悖论共生的文本时，宁可保留张力也不强行理顺。允许在笔记中标注"此处存在未解决的矛盾"。 |

#### 数据安全红线

**归档移动铁律**（2026-07-11 数据丢失事故教训）：

| 规则 | 说明 |
|:---|:---|
| ❌ **禁止清空目标目录** | 绝不允许使用 `rm -rf`、`rm -f`、`find -delete` 等命令删除目标目录文件 |
| ✅ **只移动指定文件** | 直接 `mv` 或 `cp` 指定文件到目标目录，bash 会自动覆盖同名文件 |
| ✅ **保留目标目录原有文件** | 目标目录的其他文件必须保持不动 |

**大文件处理铁律**：

| 规则 | 说明 |
|:---|:---|
| ❌ 禁止 `write_file` 处理 >300KB 文件 | 易超时失败 |
| ✅ 必须使用 `terminal` + Python 脚本 | 直接处理文件，避免工具限制 |

**原文保留铁律**：

| 规则 | 说明 |
|:---|:---|
| 原文不得直接删除 | 必须校准 YAML 后归档 |
| 归档 ≠ 精简总结 | 保留原文核心内容，只删除营销冗余 |
| 归档文件大小应接近原文 | 不应只有原文的 10-20% |

**命名规范**：

| 规则 | 说明 |
|:---|:---|
| ✅ 文件名只保留纯概念名 | 出处下沉到 YAML `source` 字段 |
| ❌ 禁止在文件名中使用出处后缀 | 如 `概念名（那多）.md` |
| 消歧后缀 | 仅在同名冲突时使用，优先级：书名 > 作者 > 领域 |

#### 特殊素材类型处理规范

**A. 食谱类素材**

触发条件：素材包含食材清单、烹饪步骤、餐品制作方法。

YAML 元数据字段（食谱专用）：

| 字段 | 用途 | 示例 |
|:---|:---|:---|
| `菜系` | 菜系分类 | `[中式, 川菜]`、`[日式]` |
| `餐品类型` | 餐品类别 | `[主菜]`、`[配菜, 汤品]` |
| `准备时间` | 准备时长（分钟） | `15`（纯数值） |
| `烹饪时间` | 烹饪时长（分钟） | `30`（纯数值） |
| `份量` | 服务人数 | `"2-3人份"` |
| `难度等级` | 1-5 难度 | `2`（对应 ★★） |
| `主料` | 主要食材 | `[牛肉, 番茄]` |
| `饮食类型` | 饮食偏好（可选） | `[生酮, 低碳, 纯素]` |
| `温度` | 烹饪温度（可选） | `"180°C"` |

正文模块体系（按需组合）：

| 模块 | 必须 | 用途 |
|:---|:---:|:---|
| A. 一句话核心 | ⭐ 推荐 | 概括关键技术要点 |
| B. 食材清单 | ✅ 必选 | 主料/辅料/调味料分组 |
| C. 烹饪步骤 | ✅ 必选 | 按时间顺序，不超过 6 大步 |
| D. 技术关键点 | ⭐ 推荐 | 易错步骤的正确做法表格 |
| E. 可选变种 | ◻ 可选 | 不同做法变体 |
| F. 优化小贴士 | ◻ 可选 | 零散技巧 |
| G. 常见问题 | ◻ 可选 | Q&A 形式 |
| H. 总结口诀 | ◻ 可选 | 顺口溜便于记忆 |
| I. 保存与食用 | ◻ 可选 | 保存方法、复热方式 |

提炼产出路径：`食谱笔记 → 20_Areas/23_生活与健康/食物/[菜系]/菜名.md`

命名规范：✅ `金汤肥牛.md`、`炒花菜（脆嫩版）.md`；❌ 避免冗余字眼如 `金汤肥牛食谱.md`

**B. 语言组块类素材**

触发条件：素材包含外语表达、语境、用法说明。
边界判定：若素材是"观点 + 论据 + 思想单元" → 使用原子笔记提炼；若素材是"外语表达 + 语境 + 用法" → 使用语言组块提炼。

词典引用规范（AI 联网查证，强制执行）：

| 内容 | 来源 | 执行方式 |
|:---|:---|:---|
| **音标** | **Cambridge Dictionary** | AI 联网查询 |
| **核心释义** | **Collins Dictionary** | AI 联网查询 |

兜底机制：若 AI 无法访问上述网址，必须显式声明"网络不可用，以下音标/释义基于训练数据，标注 `#待验证`"。

禁止行为：❌ 使用其他词典的音标体系；❌ 混用多部词典的释义；❌ 使用机器翻译生成释义或音标。

YAML 元数据字段（语言组块专用）：

| 字段 | 合法值 | 说明 | 必填 |
|:---|:---|:---|:---:|
| `target_lang` | `en`/`ja`/`fr`/... | 目标语言 ISO 码 | ✅ |
| `source_lang` | `zh`/`en`/... | 母语/中介语 ISO 码 | ✅ |
| `chunk_type` | `word`/`polyword`/`collocation`/`fixed`/`semi_fixed` | Lewis 组块分类 | ✅ |
| `cefr_level` | `A1`–`C2` | 组块难度等级 | ◻ |
| `register` | `formal`/`neutral`/`informal`/`slang` | 语域 | ◻ |
| `frequency` | `high`/`mid`/`low` | 语料库频率 | ◻ |

四条铁律（语言组块判定标尺）：

| 铁律 | 要求 |
|:---|:---|
| **原子独立** | 只承载一个不可再拆的语义-语用单元 |
| **语境驱动** | 必须绑定一个明确的语用场景（认知事件优先） |
| **网络可嵌** | 必须在语义网络中找到至少一个强对话对象 |
| **可间隔重复** | 必须具备卡片生成潜力 |

间隔重复卡片类型（五种）：

| 卡片类型 | 正面 | 背面 | 适用条件 |
|:---|:---|:---|:---|
| **释义卡** | 英文组块 | 中文核心释义 + 1个例句 | 初次习得 |
| **例句完形卡** | 挖空例句 | 完整例句 + 释义 | 强化语境 |
| **近义辨析卡** | 语境 + 候选组块 | 最恰当组块 + 理由 | 近义网络 |
| **搭配卡** | 中文情境 | 英文搭配 | 产出训练 |
| **反向输出卡** | 中文情境 | 英文组块 + 例句 | 主动产出 |

提炼产出路径：`语言组块笔记 → 31_Atomic_Notes/语言/[type]/组块名.md`

#### 视频素材 Ingest 专属路径

视频素材不走 T_Video_Source 模板（已归档），改走以下流水线：

1. 外部工具转录（Get 笔记等）→ 在 `00_Inbox/_raw/` 新建文件
2. Templater 插入 `_Raw_Video_Metadata` 模板片段（`90_System/91_Templates/_Raw_Video_Metadata.md`）：含 `tp.file.cursor(0/1)` 自动定位光标到正文区和平台字段；元数据：平台 / 博主 / 链接 / 采集日期
3. 粘贴转录正文 → Hermes Ingest 编译为 Summary + Atomic Notes

5. Ingest 后检查 Archive 中的相关笔记，在 Summary 末尾以 `## 📚 可能相关的历史笔记` 列出 ≤3 篇推荐

#### 流程中断与恢复

| 规则 | 说明 |
|:---|:---|
| **中断时** | Hermes 在当月 Worklog 中记录进度快照，包含当前步骤、已完成项、待处理项。快照统一前缀 `【流程快照】`，便于检索。 |
| **恢复时** | 人类发送「继续上次的 [流程名]」→ Hermes 读取最新快照，从断点继续。 |

| **快照生命周期** | 30 天未恢复的快照：月度 Lint 中提示「有 N 条过期快照待清理」，人类确认后清理。Agent 不自主删除 Worklog 内容。重要快照可手动在行末添加 `#lock-snapshot` 标记，不受清理限制。 |

## 六、归档（原 09 + 原 06 数据安全红线）

### 6.1 核心铁律

| 铁律 | 说明 |
|:---|:---|
| **归档安全铁律** | 原封不动移动，不删除内容。禁止 `rm -rf`/`rm -f`/`find -delete`。直接 `mv` 或 `cp` 指定文件。 |
| **大文件处理铁律** | 超过 300KB 不直接写入笔记，使用 `terminal` + Python 脚本处理。 |
| **原文保留铁律** | 完整保留原文，提炼产物作为独立原子笔记。归档文件大小应接近原文，不应只有原文的 10-20%。 |

### 6.2 删除营销冗余规范

**删除内容**：

| 类型 | 示例 |
|:---|:---|
| **图片链接** | `![](https://...)` |
| **营销话术** | "如果你也受够了..."、"赶紧收藏..." |
| **过度格式** | 多余分隔线、表情符号堆砌 |

**保留内容**：

| 类型 | 说明 |
|:---|:---|
| **核心观点** | 文章的主要论点 |
| **关键步骤/配置** | 技术细节 |
| **机制解释** | 因果关系说明 |
| **论据/依据** | 支撑观点的材料 |
| **案例说明** | 具体例子 |

**特殊情况**：

| 情况 | 处理方式 |
|:---|:---|
| 营销参考文章 | 保留完整原文（含营销话术） |
| 技术教程 | 保留所有代码和配置 |

### 6.3 归档路径规范

**原子笔记归档**：

```
原子笔记 → 30_Resources/31_Atomic_Notes/[标签领域]/[type]/笔记名.md
```

路径规则：
- 第一层：标签领域（16 种字典之一）
- 第二层：type 类型（concept / model / practice / critique）
- 文件名：纯概念名（无出处后缀）

**原文归档**：

```
原文 → 40_Archive/[领域]/[原标题].md
```

领域层级逻辑（技术类特殊处理）：

```
技术/
  └─ AI/
      └─ Agent/
          └─ Hermes Agent/
```

归档示例：
- Hermes Agent 文章 → `40_Archive/技术/AI/Hermes Agent/`
- 心理学文章 → `40_Archive/心理学与行为科学/`
- 国际政治文章 → `40_Archive/国际政治/`

### 6.4 YAML 校准规范

**原文必填字段**：

```yaml
---
title: [原标题]
date: [原创建日期]
status: archived
tags: [16种字典之一]
source: [来源名称，非URL]
author: [原作者]
aliases: []
related: []
---
```

**原子笔记必填字段**：

```yaml
---
title: [笔记标题]
date: YYYY-MM-DD
status: active
type: concept | model | practice | critique
tags: [16种字典之一]
source: [来源名称]
author: [原作者]
aliases: []
related: []
---
```

### 6.5 Lint 健康检查

| 检查项 | 说明 |
|:---|:---|
| 孤儿页面 | 未被任何笔记引用的页面 |
| 断链 | 指向不存在页面的链接 |
| 跨层概念矛盾 | 不同层级的概念定义冲突 |
| 人类编辑陈旧 | 超过 90 天未更新的人为编辑笔记 |
| Raw 素材被 ≥ 3 条笔记引用 | 提醒建议编译 |
| Raw 素材闲置超过 60 天 | 提醒建议清理 |

### 6.6 Audit 反馈处理

| 优先级 | 处理方式 |
|:---|:---|
| `high` | 立即处理 |
| `low` | 批量处理 |
| `human_edited: true` 的页面 | 不直接修改，在 `audit/resolved/` 生成建议文档 |

## 七、检查清单

### ✅ 编译前必检

- [ ] 确认触点判定结果（是否与当前思考相关）
- [ ] 确认输出范围（提炼 + 校准 + 归档）
- [ ] 大文件确认处理方式（Python 脚本）

### ✅ 归档前必检

- [ ] YAML 是否校准完成？（tags 从 16 种字典选择？status 正确？原子笔记是否填写 type？source 是否为来源名称非 URL？是否删除非标准字段？）

- [ ] 目标目录是否有同名文件（会覆盖）？

### ✅ 归档后必检

- [ ] 归档文件大小是否合理（接近原文）？
- [ ] 原子笔记是否按 type 分类到子目录？
- [ ] 双链引用是否可点击跳转？

### 🔴 STOP 信号

遇到以下情况**立即停止**，人工确认：

- ❌ 大文件用 `write_file` 处理
- ❌ 准备执行 `rm -rf`/`rm -f`/`find -delete`
- ❌ 归档文件只有原文 10-20% 大小
- ❌ 不确定是否应该删除某个文件
- ❌ 准备清空目标目录
