# 13_健身方案编写标准

> **规范引用**：[[系统文档/01_知识库统一规范总纲|总纲 v3.0]]，本文为领域专项补充，不替代总规范。
> **层级**：L3 · 素材特化层 | **版本**：v1.0.0 | **生效日期**：2026-07-13
> **编号规则**：编号按历史新增顺序排列，层级归属以本文档声明为准。

> 一份清晰好用的健身文档，应让你在力量房里打开手机就能照着练。本标准覆盖四类健身文档的写法——单次方案、周期计划、动作标准、复盘记录。

---

## 一、文件组织与命名

### 1.1 存放位置（Areas/Resources 分层）

健身内容按**使用场景**分为执行层和知识层：

#### Areas — 执行层（20_Areas/23_生活与健康/健身/）

你正在做的事，需要主动执行、跟踪、复盘的健身内容。

```
20_Areas/23_生活与健康/健身/
├── 健身 MOC.md       # 统一入口
├── 方案/              # 训练方案（照着练）
├── 动作/              # 动作标准（练时查）
├── 记录/              # 训练复盘（练完写）
└── 习惯/              # 习惯打卡（每日）
```

#### Resources — 知识层（30_Resources/31_Atomic_Notes/健身/）

你参考的知识，需要时查阅，不需要时放着。

```
30_Resources/31_Atomic_Notes/健身/
├── 原则/              # 训练方法论（理解了就行）
└── 理论/              # 运动理论/解剖/生理知识
```

#### 分类判定标准

| 内容特征 | 放 Areas | 放 Resources |
|:---|:---:|:---:|
| 你要照着练的（训练方案） | ✅ | |
| 练的时候要查的（动作标准） | ✅ | |
| 练完要写的（复盘记录） | ✅ | |
| 理解了就行，不常翻阅的（原则/方法论） | | ✅ |
| 理论知识/外部引用（解剖/运动科学） | | ✅ |

**素材规范**：GIF/视频素材统一存放于 `20_Areas/23_生活与健康/健身/_assets/`，命名格式为 `动作英文名_视角.gif`（如 `bench_press_front.gif`），正文使用 `![[健身/_assets/bench_press_front.gif]]` 引用。对齐 [[系统文档/09_图床与多端同步基础设施规范|21 号图床规范]] 的附件管理原则。

### 1.2 命名规则

```
方案名.md
方案名（版本说明）.md          # 多版本时
方案名 – 出处.md               # 有明确来源时
```

**示例**：`上肢推拉分化训练.md`、`5x5 力量入门（精简版）.md`、`核心稳定性 – McGill 三大项.md`

避免在文件名中使用"健身""训练方案""workout plan"等冗余字眼。

## 二、YAML 元数据规范

所有健身文档统一使用英文蛇形命名。通用核心字段（9 个）与 AI 字段遵从总纲与 07_YAML 规范。健身领域特化字段已纳入全局白名单，不计入 12 字段上限。

### 2.1 特化字段表

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---:|:---|
| `fit_type` | 枚举 | ✅ | `力量训练` / `有氧训练` / `柔韧性训练` / `综合训练` / `康复训练` |
| `fit_content_type` | 枚举 | ✅ | `program` — 综合训练方案 / `exercise` — 单个动作标准 / `principle` — 训练原则/方法论 / `theory` — 纯理论/知识性内容 / `anatomy` — 解剖/生理学知识 / `log` — 单次训练日志/周期复盘记录。与 `type` 字段交叉验证（见下方规则） |
| `fit_cycle` | 枚举 | ✅ | `单次` / `周计划` / `月计划` / `季度计划` / `长期稳态` |
| `target_muscle` | 数组 | ✅ | YAML 数组，如 `[胸, 肩, 三头]` |
| `fit_level` | 枚举 | ✅ | `新手` / `进阶` / `高阶`（判定标准见下方） |
| `train_duration` | 数字 | ✅ | 单次训练时长（分钟） |
| `train_frequency` | 字符串 | ⚠️ 周期必填 | 单次方案留空，由周期计划统筹定义。如 `每周3次` |
| `fit_goal` | 枚举 | ✅ | `增肌` / `减脂` / `塑形` / `体能` / `康复` / `体态` |
| `rest_rule` | 字符串 | 可选 | 如 `组间60-90s`、`超级组30s` |
| `equipment` | 数组 | 可选 | YAML 数组，如 `[哑铃, 弹力带]`，无器械填 `[徒手]` |
| `injury_note` | 字符串 | ⚠️ 防呆必填 | 伤病备注。若无伤病，须显式填 `"无伤病限制"` |
| `diet_strategy` | 字符串 | 可选 | 仅写训练期窗口策略（练前/练后怎么吃），具体食谱双链 [[系统文档/12_食谱编写标准]] |
| `demo_gif` | 字符串 | 可选 | 动作演示图/动图链接，统一存放于 `20_Areas/23_生活与健康/健身/_assets/`，命名格式 `动作英文名_视角.gif` |
|| `training_date` | 日期 | ⚠️ 复盘推荐 | 类型 D（复盘记录）推荐填写实际训练日期，与笔记创建日期 `date` 区分 |
|| `pain_score` | 数字(0-10) | ⚠️ 复盘推荐 | 当日训练后肩颈疼痛评分。0=无痛，1-3=轻微酸胀，4-6=持续酸痛，7-10=尖锐刺痛。配合 Weekly Dataview 查询使用 |
|| `complete_level` | 数字(0-3) | ⚠️ 复盘推荐 | 当日完成等级。0=未做，1=仅晨间，2=晨间+工位，3=全套完整执行。配合 Weekly Dataview 查询使用 |
|| `training_week` | 数字 | ⚠️ 训练记录推荐 | 当前训练周数（如 1、2）。用于 Weekly Log Dataview 按周筛选 |
|| `training_day` | 数字 | ⚠️ 训练记录推荐 | 当前训练日序号（如 1、2）。用于追踪周期内进度 |

**`fit_level` 判定标准**：

| 等级 | 判定标准 |
|:---|:---|
| `新手` | 训练经验 ≤ 1 个月，无法标准完成基础复合动作（深蹲/卧推/划船） |
| `进阶` | 掌握基础动作，可稳定渐进超负荷，训练经验 1 个月–1 年 |
| `高阶` | 具备精准肌群控制，可执行细分分化训练、大重量（> 1.5 倍体重）复合动作 |

### 2.1.5 非力量训练内容分类映射决策矩阵

当笔记内容不涉及"力量训练"时（如拉伸、松解、瑜伽、呼吸、放松），按下表将内容属性映射到特化字段：

| 你的笔记内容 | `fit_type` | `fit_content_type` | `fit_goal`（选最匹配） | `target_muscle` |
|:---|:---|:---|:---|:---|
| **静态拉伸 / PNF拉伸 / 柔韧性练习** | `柔韧性训练` | `exercise` 或 `program` | `康复` 或 `体态` | 填写具体拉伸部位 |
| **筋膜松解 / 泡沫轴 / 扳机点按压** | `康复训练` | `exercise` | `康复` | 填写松解部位 |
| **瑜伽体式序列（流/哈他）** | `综合训练` | `program` | `塑形` 或 `体态` | 填写主要激活肌群 |
| **阴瑜伽 / 修复瑜伽** | `柔韧性训练` | `program` | `康复` | 填写拉伸/放松肌群 |
| **呼吸训练（腹式/鸟鸣式/调息）** | `有氧训练` 或 `康复训练` | `exercise` 或 `principle` | `体能` 或 `康复` | 填写涉及肌肉（如 `[膈肌, 腹横肌]`） |
| **放松 / 身体扫描 / 冥想** | `康复训练` | `practice` | `康复` 或 `体态` | 若无则填 `[]` |

**强约束**：以上所有类型的笔记，`tags` 字段**统一填写 `[健身]`**，不得使用矩阵中的动作名称作为标签。

### 2.3 类型 C 动作标准 YAML 模板（独立补充）

动作标准（类型 C）统一使用以下模板，与通用模板的区别在于 `fit_content_type` 和 `fit_goal` 为必填：

```yaml
---
title: "动作名"
date: YYYY-MM-DD
status: active
type: practice
tags: [健身]
source: ""
author: ""
aliases: []
related: []

# 健身特化
fit_type: 康复训练
fit_content_type: exercise
fit_cycle: 单次
target_muscle: [目标肌群]
fit_level: 新手
train_duration: 5
fit_goal: 康复
equipment: [徒手]
injury_note: "伤病提示"
moc_exempt: true
---
```

**必填说明**：
- `fit_content_type: exercise` — 标识为单个动作标准
- `fit_goal: 康复` — 动作标准统一目标为 `康复`（非训练方案，不设增肌/减脂等目标）

**📌 示例：一篇"大腿后侧静态拉伸"动作标准笔记的完整 YAML**

```yaml
---
title: "腘绳肌静态拉伸（仰卧举腿式）"
date: 2026-07-18
status: active
type: practice
tags: [健身]                      # ← 仅此一项，不写『拉伸』
source: 自研整理
author: ""
aliases: []
related: []

human_edited: true
ai_generated: false

fit_type: 柔韧性训练               # ← 训练类型
fit_content_type: exercise        # ← 单个动作标准
fit_cycle: 单次
target_muscle: [股二头肌, 半腱肌, 半膜肌]
fit_level: 新手
train_duration: 5
fit_goal: 康复
equipment: [徒手]
injury_note: "腰部有伤者避免弯腰前屈，改为仰卧举腿拉伸"
---
```

### 2.4 标签规则（强制）

- 健身类笔记 **严格统一使用 `tags: [健身]`**，遵循 TAG-02 互斥规则（打 `健身` 即不打 `生活` 父标签）。
- **绝对禁止**在 `tags` 字段中使用以下细分类标签：`拉伸`、`松解`、`瑜伽`、`呼吸`、`放松` 等。这些内容属性必须通过下文 §2.1 的特化字段（`fit_type`、`fit_goal`、`fit_content_type`）来承载。
- 示例：
  - ✅ `tags: [健身]`
  - ❌ `tags: [健身, 拉伸]`
  - ❌ `tags: [拉伸]`
- 功能标签（如 `归档`）仅用于状态管理，不参与领域分类。

## 三、四类文档的标准结构

### 类型 A：单次训练方案（今天照着练）

1. **训练概述** — 目标、适配人群、难度、时长、器械
2. **热身（5-10分钟）** — 动态热身 + 关节激活，写具体动作
3. **正式训练** — 表格：动作名 | 组数 | 次数/时长 | 休息 | 要点
4. **拉伸放松** — 目标肌群静态拉伸，每个动作 15-30 秒
5. **训练备注** — 重量建议、呼吸节奏、伤病规避、下次复盘点
6. **可选变种**（可选）— 哑铃版、杠铃版、新手简化版等，仅写差异部分

### 类型 B：周期训练计划（几周的整体布局）

1. **周期总览** — 时长、核心目标、整体逻辑
2. **周度排布** — 每天练什么、怎么轮换
3. **单次方案链接** — [[双链]] 关联到类型 A 的具体方案
4. **进阶规则** — 什么时候加重、加次数、换动作
5. **饮食作息** — 配合训练目标的吃和睡（精简，不冗余）
6. **复盘机制** — 周期末怎么考核、怎么调整
7. **可选变体**（可选）— 同一周期的不同难度/器械/伤病适配版本，仅写差异
8. **版本快照** — 重大调整时，复制当前文档为新版本（命名加版本号），旧文档 `status: archived` 并双向互链，保证溯源唯一

### 类型 C：动作标准笔记（单个动作的"标准答案"）

1. **基础信息** — 动作名、技法分类（力量/柔韧/康复/有氧）、目标肌群、难度、适用场景
2. **动作图解**（推荐）— `![[健身/_assets/动作英文名_视角.gif]]`
3. **标准发力流程** — 起始姿态 → 发力过程 → 顶峰收缩 → 还原节奏
4. **发力要点** — 关键肌肉、呼吸节奏、体态控制
5. **常见错误** — 高频错误 + 危害 + 纠正方法
6. **适配与禁忌** — 适合谁、谁不能做、替代动作
7. **替代动作对比表**（如有替代）— 当训练方案中用新动作替换原动作时，必须附对比表，说明替代理由。格式：

```markdown
| 维度 | 原动作 | 替代动作 |
|:---|:---|:---|
| 安全性 | ⚠️ 风险说明 | ✅ 安全说明 |
| 精准度 | 局限说明 | ✅ 优势说明 |
| 可操作性 | 局限说明 | ✅ 优势说明 |
| 证据等级 | 经验性说明 | ✅ 文献/临床支持说明 |

**替代理由**：一段话说明为什么替换，涵盖原动作的风险、替代动作的循证优势。
```

### 类型 D：健身复盘记录（每次练完的反思）

1. **训练数据** — 实际时长、完成组数、重量、状态评分（1-10），记录实际训练日期至 `training_date`
2. **亮点与进步** — 发力感知、重量突破、动作更标准了
3. **问题与不足** — 动作瑕疵、体能短板、异常酸痛
4. **下次优化** — 怎么调整重量、换什么动作、休息怎么改

### 训练记录文件（fit_content_type: log）的 status 取值约定

训练记录文件遵循 `01_总纲` 定义的全局 `status` 合法值：`draft / active / mature / deprecated / archived`。

- 推荐使用 `active` 表示"当前周期正在使用的训练记录"，`archived` 表示"已完成/已归档"
- 如需区分"待执行"与"已完成"，可通过 `complete_level` 字段判定：`0` 表示待执行，`1-3` 表示不同程度的已完成
- **Agent Lint 校验规则**：训练记录文件中若出现 `pending` 或 `complete` 作为 `status` 值，视为字段值违规，输出修正提醒，建议改为 `active` 或 `archived`

```markdown
target_muscle: [胸, 肩, 三头]
fit_level: 新手
train_duration: 50
train_frequency: ""
fit_goal: 增肌

equipment: [哑铃]

# 上肢推拉分化·推日

> **一句话**：推日练胸肩三头，四个动作搞定，组间休息 90 秒。

---

## 热身（5 分钟）

- 肩关节绕环 × 10
- 弹力带扩胸 × 15
- 轻重量哑铃卧推 × 10（用正式重量的 50%）

---

## 正式训练

| 动作 | 组数 | 次数 | 休息 | 要点 |
|:---|:---:|:---:|:---:|:---|
| 哑铃卧推 | 4 | 8-10 | 90s | 肩胛骨收紧，触胸停顿 |
| 哑铃推举 | 3 | 10-12 | 60s | 站姿，核心收紧 |
| 侧平举 | 3 | 15-20 | 45s | 轻重量，控制离心 3 秒 |
| 凳上臂屈伸 | 3 | 12-15 | 45s | 顶峰收缩 1 秒 |

---

## 拉伸（5 分钟）

- 胸大肌静态拉伸 × 30s
- 三角肌前束静态拉伸 × 30s
- 三头肌静态拉伸 × 30s

---

## 备注

- **重量选择**：选一个你每组只能做 8-10 次的重量，最后一组做到力竭
- **呼吸**：发力时呼气，还原时吸气
- **下次复盘点**：卧推时肩膀有没有不舒服？侧平举有没有借力？

---

_本文档为个人整理的健身训练方案，归档备查。_
```

## 五、内容编写规范

### 5.1 铁律

1. **能照着做**：所有动作、参数必须可直接执行，不写空话。
2. **数字说话**：组数、次数、重量、休息时间，都用具体数字，不说"适量"。
3. **安全第一**：`injury_note` 不可留空；若无伤病，须显式填写"无伤病限制"。
4. **越界声明**：具体食谱、营养学方案请双链至 [[系统文档/12_食谱编写标准]]，本文仅记录训练期窗口策略。

### 5.2 双链关联

- 周期计划 → 链到单次方案
- 单次方案 → 链到动作标准笔记
- 复盘记录 → 链回训练方案
- 饮食策略 → 链到 14 号食谱规范

**双链强约束**：禁止无意义双链。仅允许关联以下类型：动作标准笔记 / 周期计划 / 同类替代方案 / 食谱训练期策略。杜绝"相关""有意思"等空洞关联。

### 5.3 迭代更新

- 参数调整后更新 `last_ai_edit` 日期
- 重大变更（如分化方式改变）在 `ai_edit_summary` 中标注核心变更点
- `ai_edit_summary` 统一书写范式：
  - 正常优化：`优化：补充动作参数、细化训练要点`
  - 人工校验完成：`[已校验] 伤病适配/大重量动作方案人工复核通过`
  - 版本迭代：`迭代：周期计划更新至 v2.0，适配当前体能等级`
- 周期计划重大调整时创建新版本文档，旧文档 `status: archived` 并双向互链

## 六、生命周期与归档

所有健身文档遵循全库统一状态定义：

| 状态 | 定义 | 触发条件 |
|:---|:---|:---|
| `draft` | 草稿 | AI 生成未人工审核、或未经过落地验证 |
| `active` | 使用中 | 正在执行、持续迭代优化的方案 |
| `mature` | 成熟 | 经过 3 次以上落地验证、参数稳定、无需频繁调整 |
| `archived` | 归档 | 过时、不再适配当前状态、被新方案替代。移入 `40_Archive/生活/健身/` |

## 八、安全红线

> ⚠️ 本章节为通用健身安全提示，不构成医疗建议。有基础疾病或伤病的人群，请务必先咨询专业医生或物理治疗师。

1. **特殊人群**：有心脏病、高血压、关节伤病的人，需在医生指导下训练。健身方案仅作参考。
2. **同一肌群间隔**：至少休息 48 小时再练同一块肌肉。
3. **循序渐进**：新手不要一上来就大重量。从轻重量、简单动作开始，慢慢加。
4. **女性力量训练**：女性睾酮水平远低于男性，不会练成"肌肉女"。力量训练会让身材更紧致。
5. **运动后不要立刻洗澡**：休息 15-30 分钟，等心率和体温降下来再洗。

## 九、AI 协作规则

### 9.1 通用规则

AI 写入权限、碰撞保护、首次写入协议、数据安全红线等通用规则，统一见 [[系统文档/06_Inbox 素材处理全流程规范]]。

AI 首次生成的健身方案，默认 `status: draft`、`ai_generated: true`，顶部添加标准「🤖 AI 待审核」Callout，规则完全对齐 06 号规范。

### 9.2 健身领域专属规则

**提炼决策树**：

```
素材进入 _raw/
    │
    ├─ 包含训练动作 + 组数/次数 + 训练逻辑？
    │   ├─ 否 → 按「原子笔记」处理
    │   │
    │   └─ 是 → 判定文档类型
    │            │
    │            ├─ 完整的单次训练 → 按类型 A 提炼
    │            ├─ 多周规划 → 按类型 B 提炼
    │            ├─ 单个动作教学 → 按类型 C 提炼
    │            └─ 训练后反思 → 按类型 D 提炼
```

**AI 能力边界**：

| AI 能做 | AI 不能做 |
|----------|-----------|
| 生成训练流程、动作要点、参数配比 | 给出医疗诊断或康复处方 |
| 提供通用伤病适配建议（如"腰伤避免大重量深蹲"） | 替代专业医生或物理治疗师 |
| 生成饮食建议（如"练后补充碳水+蛋白质"） | 给出极端饮食方案或补剂推荐 |

**人工强制校验项**：
- 涉及伤病适配的方案
- 大重量（> 80% 1RM）的训练方案
- 高危动作（如颈后推举、直腿硬拉）的方案

以上内容 AI 生成后必须人类确认。校验通过后，在 `ai_edit_summary` 中添加 `[已校验]` 前缀，例如 `[已校验] 腰伤适配方案已由用户确认`。

**异常处理**：

| 触发条件 | 处理方式 |
|:---|:---|
| 素材缺少组数、次数、动作标准等核心参数 | 仅归档，不提炼为正式方案，标注 `#待精确化` |
| 包含高危动作且无安全提示 | 自动补充通用安全提示，标注 `#待人工校验`，不标记审核通过 |
| 已有同名方案且 `human_edited: true` | 仅在文末追加 `## 🤖 Hermes 补充`，不覆盖正文 |
| 单条素材包含多个独立训练方案 | 拆分为多篇笔记，每条方案一个独立文件 |

## 十、fit_content_type 交叉约束与 Lint 校验

### 10.1 与标准 type 字段的交叉约束

| fit_content_type | 推荐 type | 说明 | 存放位置 |
|:---|:---:|:---|:---|
| `program` | practice | 综合训练方案，含完整训练逻辑 | Areas/方案/ |
| `exercise` | practice | 单个动作标准，教学性质 | Areas/动作/ |
| `principle` | concept | 训练原则/方法论，理解了就行 | Resources/原则/ |
| `theory` | concept | 纯理论/知识性内容 | Resources/理论/ |
| `anatomy` | concept | 解剖/生理学知识 | Resources/理论/ |

### 10.2 向后兼容规则

`fit_content_type` 为**推荐字段而非强制字段**。Lint 规则区分两种场景：

| 场景 | 处理 |
|:---|:---|
| 有值但与 type/目录冲突（错配） | 报错，输出修正建议 |
| 无值（缺失） | 仅提示补全，不标红，不阻塞 |

### 10.3 Agent 月度 Lint 校验逻辑

```yaml
校验范围: 20_Areas/23_生活与健康/健身/ 及 30_Resources/31_Atomic_Notes/健身/
校验频率: 每月一次
校验规则:
  - 检查 fit_content_type 与存放目录是否匹配
  - 检查 fit_content_type 与 type 字段是否匹配
  - 对错配项输出修正提醒，不自动移动文件
  - 人工确认后执行迁移
```

## 十一、替代动作对比模板（可选模块）

**适用**：`fit_content_type: exercise` 类型笔记中，当有替代动作时。

```markdown
| 维度 | 原动作 | 替代动作 |
|:---|:---|:---|
| 安全性 | ⚠️ 风险说明 | ✅ 安全说明 |
| 精准度 | 局限说明 | ✅ 优势说明 |

```
