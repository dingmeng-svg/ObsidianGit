## §总则 {#general-intro}

### 规范适用范围

本规范适用于知识库内所有文件。其中：

- **§命名规则** 中的原子笔记命名规则仅适用于 `30_Resources` 下的知识笔记。系统文档（含本总纲）使用功能性命名，不受纯概念名约束，但应包含文档类型标识与版本号。
- **`00_Inbox/`** 目录下文件豁免所有命名、标签、元数据规范。但文件名禁用系统保留字符的基础兼容规则，Inbox 内也建议遵守。

### 规则分级体系

本规范采用两级规则体系：

- **核心规则**：被分配规则 ID 的条款。是规范的骨架，总量不超过 10 条。修改需记录于变更摘要。
- **细则 / 推荐性规则**：未被分配 ID 的解释性条款、示例、建议。提供操作细节与最佳实践指引，可根据实际情况灵活调整。

核心规则 = 被分配了规则 ID 的规则。未被分配 ID 的条款不纳入核心规则总量计算。规则的升格为核心（分配 ID）或降格为细则（移除 ID）需记录于变更摘要。

### 规则 ID 约定

- 规则 ID 统一使用 `PREFIX-NN` 格式，前缀为全大写英文字母，按规则大类语义缩写。如 `NAMING-01`、`TAG-01`。
- 规则 ID 一经分配，**永久不复用**。被删除的规则 ID 保留为空洞，不填补。
- 新增大类前缀需记录于变更摘要。

### 系统文档跨文档引用规范

**真值源划分**：

| 层级 | 真值源范围 |
|:---|:---|
| L0（总纲、HERMES） | 全局强制规则的真值源：目录分层、命名规范、标签字典、元数据字段定义、Agent 权限分级 |
| L1（方法论） | 方法论与设计哲学的真值源：原子笔记炼金术、融合架构设计 |
| L2（操作 SOP） | 各模块操作规则的真值源：编译流程、归档流程、双链维护、MOC 维护、管理规则 |
| L4（辅助文档） | **不定义新规则**。仅作为台账、索引、速查 |

**引用规则**：
- 跨层级引用规则时，**必须**使用双链锚点指向真值源文档：`[[文档名#锚点]]`，禁止大段复制原文
- 引用处仅允许一句简短复述（≤ 2 行），作为阅读便利性辅助

**引用违规校验规则**：

**源头约束**（Agent 生成规则文本时）：
- Agent 在根据人类指令生成新规则文本时，如果明确知道该规则来源于另一份系统文档，**必须**主动使用锚点引用格式 `[[文档#锚点]]` + ≤ 2 行简述
- 这是生成阶段的约束，而非写入前的全库扫描

**手动触发**（人类按需发起）：
- 人类可发送指令「扫描文档冗余」，Agent 对指定文档或全库系统文档执行一次语义查重
- 输出冗余段落清单及建议替换的锚点引用
- 日常写入不触发此扫描

**并发冲突规避**：
- 若当前正处于月度 Lint 扫描或合规巡检执行期间，Agent 暂停「写入时检查」的自动替换动作
- 此时仅做标记提醒，待巡检流程完全结束后，再恢复正常的写入时自动替换逻辑

**月度合规巡检校验项**——枚举值一致性校验：

**校验白名单**（仅对以下全局固定枚举/阈值做跨文档一致性校验）：
1. 状态枚举：`active` / `mature` / `draft` / `deprecated` / `archived`
2. 熔断阈值：批量操作 5 篇阈值、draft 30 天阈值
3. 合规红线：双标签占比 5%、消歧后缀 10%
4. 健康度预警线：断链率 5%、孤儿页面 15% 等固定指标

**校验机制**（基于真值源表格）：
- Agent 以 `01_知识库统一规范总纲.md` 和 `HERMES.md` 中明确定义的「状态枚举表」「阈值表」为基准
- 在其他系统文档的全文文本中搜索这些枚举值是否出现不一致
- **排除范围**：Agent 通过上下文语义识别代码块（被 ` ``` ` 包裹）和 Callout（`> [!note]` 开头）区块，跳过其中的枚举值校验。利用 LLM 天然的文档结构识别能力处理排除逻辑
- **禁止**对自定义数值、文案参数、局部配置做一致性校验

若白名单内的枚举值不一致 → 标记 P1 结构警告：「[文档A] 与 [文档B] 的 [枚举项名称] 不一致，请确认真值源并同步」

**白名单维护**：若后续新增全局固定阈值或状态枚举，统一补充至本白名单，并同步更新 HERMES §六校验逻辑。不私下新增比对项。

### 术语定义

**原子笔记总数**：指 `30_Resources/31_Atomic_Notes/` 目录下所有 `.md` 文件的数量（不含 MOC、模板、归档文件）。本规范中所有涉及原子笔记总量的统计与占比计算，均以此为统一分母。

### 命名规范过渡期

当前为命名规范过渡期。存量笔记渐进迁移，合规校验仅针对 v3.0 生效后新建笔记。当存量旧命名笔记占 `30_Resources/31_Atomic_Notes` 下原子笔记总数的比例低于 10% 时，可通过月度复盘判定是否结束过渡期（可选触发标准，非强制截止）。

过渡期结束后，合规巡检覆盖全部活跃原子笔记。存量未迁移笔记按遗留问题专项处理，不纳入日常合规考核。

### 速查卡权威声明

速查卡是本规范的操作摘要。当速查卡与本总纲内容不一致时，以本总纲为准。

### 版本命名约定

版本号格式：`v主版本.次版本.修订版本`（如 `v3.0.0`）。

- **主版本**：规则体系重构、核心规则增删。
- **次版本**：细则调整、标签字典更新、附录补充。
- **修订版本**：笔误修正、措辞优化。

主版本与次版本升级后须同步更新速查卡。修订版本升级后速查卡可不同步。

## §命名规则 {#naming}

### 核心规则

**NAMING-01**：原子笔记文件名只保留**纯概念名**。出处、作者、来源等辅助信息统一下沉至 YAML 元数据的 `source` 和 `author` 字段。

```yaml
# 正确
蔡格尼克效应.md
梅拉宾法则.md
习惯堆叠.md

# 错误
蔡格尼克效应（心理学）.md
梅拉宾法则（Mehrabian）.md
习惯堆叠（原子习惯）.md
```

**NAMING-02**：消歧后缀仅在同名冲突时使用。优先级：**书名 > 作者 > 领域 > 流派**。

```yaml
# 示例
认知失调.md
认知失调（社会性动物）.md        ← 同名冲突，用书名消歧
认知失调（Festinger）.md         ← 若书名也相同，用作者名消歧
```

### 命名细则

- **禁止在文件名中使用领域名作为后缀**。如 `（心理学）`、`（个人成长）`、`（知识管理）` 等信息不应出现在文件名中。
- **文件名禁止使用系统保留字符**：`/ \ : * ? " < > |`。
- **废弃 / 过时笔记**：文件名前加 `⚠️` 前缀。两类适用场景：① 内容过时 / 被证伪；② 重复概念合并后的留存副本。若废弃原因为内容过时/被证伪，则 YAML `status` 须设为 `deprecated`。被合并的笔记正文需保留跳转链接指向主笔记。
- **消歧后缀笔记占比红线**：< 10%（指带括号消歧后缀的活跃笔记占活跃原子笔记总数的比例，统计口径与合规巡检一致）。

### 其他文件类型命名

功能性文件（系统文档、日记、MOC 等）不受纯概念名约束，按约定俗成格式命名。以下为推荐格式：

| 文件类型 | 推荐格式 | 示例 |
|:---------|:---------|:-----|
| 每日日记 | `YYYY-MM-DD.md` | `2026-07-09.md` |
| 周复盘 | `YYYY-Www.md` | `2026-W28.md` |
| 月复盘 | `YYYY-MM.md` | `2026-07.md` |
| 季复盘 | `YYYY-QN Review.md` | `2026-Q3 Review.md` |
| 年方向 | `YYYY Annual Compass.md` | `2026 Annual Compass.md` |
| 系统文档 | `功能描述 v主版本.次版本.md` | `知识库统一规范总纲 v3.0.md` |
| MOC | `主题名 MOC.md` | `心理学 MOC.md` |
| 食谱 | `菜名.md` | `番茄牛肋条.md` |
| 模板 | `Template 名称.md` | `Daily Template.md` |

## §标签体系 {#tags}

### 核心规则

**TAG-01**：标签总量 = 20 种（含核心标签 10 个、功能性标签 10 个）。

**TAG-02**：细分标签与父标签互斥。打了细分标签的笔记**不**打父领域标签。父子标签绝对互斥，无任何例外。

```yaml
# 正确
一篇讲情绪调节的笔记 → tags: [心理学]        ← 只打细分标签

# 错误
tags: [个人成长, 心理学]    ← 心理学是个人成长的细分标签，不应同时打
```

父领域全量统计通过联合查询（父标签 + 所有下属细分标签）实现。

### 标签配额计数规则

**领域标签**（核心标签 + 细分标签）受 TAG-01 总量 ≤ 20 种约束。
**功能性标签**（`国际政治`、`科学`、`系统文档`、`归档`、`素材`、`日记`、`习惯`）不计入 TAG-01 总量上限。

当前实际：领域标签 10 个（含细分 4 个），功能性标签 10 个。总计 20 种，已满额。

### 标签字典

### 标签细则

- **双标签例外**：仅当核心议题均衡分属**两个平级领域**时例外使用。占比红线：< 5%。功能性标签与领域标签的组合不计入双标签占比统计。占比仅针对两个平级领域标签同时出现的场景。

  ```yaml
  # 正确示例：平级领域交叉
  一篇讲"工作场景中的心理学应用"的笔记
  → tags: [工作, 心理学]   ← 工作与心理学是两个平级领域
  
  # 不计入双标签占比
  一篇习惯方法论的笔记
  → tags: [个人成长, 习惯]  ← 功能性标签+领域标签，不计入占比统计
  ```

- **项目归属**：项目名写在 YAML `project:` 字段，不作为标签。
- **类型信息**：原子笔记的类型（概念/模型/实践/批判）在 `type:` 字段中，不在标签中。
- **禁用子类格式**：禁止使用 `#领域/子类` 层级格式，全部采用扁平标签。
- **标签扩展缓冲机制**：当某一新标签候选（`pending_tag`）积累 ≥ 5 篇笔记时，可于月度复盘时正式纳入标签字典。

### 标签语义定义

| 标签 | 语义边界 |
|:-----|:---------|
| `个人成长` | 关于个体认知、思维、写作、学习能力提升的方法论与实践。不包含心理学学术概念。 |
| `工作` | 职业角色相关的一切：职场技能、管理实践、创业探索、具体项目产出。 |
| `心理学` | 心理学领域的学术概念、模型、实验、学者。当概念兼具学术与应用双重属性时，以"是否可脱离心理学语境被理解"为判定标准。 |
| `知识管理` | 笔记方法、个人知识库构建、信息组织与检索。使用 Obsidian 的技巧归入 `技术` 而非本标签。 |

## §YAML 元数据规范 {#metadata}

### 核心规则

**META-01**：`source` 字段只填 **1 个**核心主来源。次要来源放正文引用。

```yaml
---
title: 梅拉宾法则
source: 沉默的讯息   # 主要出处
---
```

正文中若需引用次要来源，使用文内链接或脚注，不占用 `source` 字段。

原创整合类笔记，核心观点为个人提炼时填 `原创`。若核心观点源自某一主来源、其余为补充，则填主来源名称。次要参考来源在正文标注。

**META-02**：元数据字段总量 ≤ 12 个。新增字段须同时满足：① 全库通用；② 无法被现有字段或标签替代。

**L3 特化层豁免条款**

语言组块笔记和食谱笔记因领域特殊性，允许新增领域专属扩展元字段，不计入 META-02 的 12 个字段通用统计上限。

约束红线：
1. 所有 L3 笔记必须完整保留总纲强制核心字段：title / date / status / tags / type
2. 核心字段的键名和格式必须与总纲完全一致。必须用 `status` 而非 `状态`，`date` 而非 `日期`。豁免的是「额外字段的数量」，不是「核心字段的命名规范」
3. 任何新增 L3 领域，必须在总纲本条款下备案其豁免字段清单

**L3 特化字段备案表**（索引表，字段定义真值源下沉到各 L3 文档自身）：

| 笔记类型 | 豁免字段清单 | 对应规范文档 |
|:---|:---|:---|
| 语言组块笔记 | 见 `11_Language Chunk 炼金术士` | 11_Language Chunk 炼金术士 |
| 食谱笔记 | 见 `12_食谱编写标准` | 12_食谱编写标准 |
| 健身方案笔记 | 见 `13_健身方案编写标准` | 13_健身方案编写标准 |
| 健身训练记录笔记 | 见 `13_健身方案编写标准` | 13_健身方案编写标准 |
| 习惯体系 | `fit_content_type: habit_design/habit_tracker/habit_audit` | `A2_能力接口/Atomic Habits/` |
| Insight 周期洞察 | `insight_type, period_type, period_range, daily_promise` | 04_Insight 周期复盘体系标准 |

Agent 协作专用字段（`ai_generated`、`human_edited`、`last_ai_edit`、`ai_edit_summary`、`audit`、`pending_delete`，定义详见 Hermes 操作手册）属于系统扩展字段，不计入本条 12 个字段总量限制。这些字段仅出现在 AI 生成或 Agent 处理过的笔记中。

已废弃不再使用的字段，保留历史笔记中的原值，不再新增使用。废弃字段不计入 12 个字段总量统计。是否批量清理历史值由月度复盘按需决定。

**后续 L3 字段前缀规则**：新增 L3 领域特化字段必须加领域前缀（如 `lang_`、`fit_` 已成惯例），避免全局命名冲突。

**食谱 grandfather 条款**：存量食谱文件中的中文键名（`菜系`、`餐品类型` 等）可保留，不做强制迁移。**新创建**的食谱文件必须使用英文键名（`cuisine`、`dish_type` 等）。07_YAML 规范中 Lint 告警对存量中文键名仅输出建议，不报错。

### Agent 协作字段（系统扩展）

以下字段由 HERMES 定义，属于系统扩展字段，不计入 META-02 的 12 个字段通用统计上限：

| 字段 | 类型 | 说明 |
|:-----|:-----|:-----|
| `human_edited` | 布尔 | AI 写入权限锁。`true` = 禁止 Agent 覆盖正文。若 YAML 中无此字段，视为 `false` |
| `ai_generated` | 布尔 | 标记 AI 编译产物 |
| `last_ai_edit` | 日期 | Agent 最近一次修改的日期 |
| `ai_edit_summary` | 字符串 | Agent 最近一次修改的简要说明 |

### 标准字段

| 字段 | 必填 | 说明 | 示例 |
|:-----|:----:|:-----|:-----|
| `title` | ✅ | 笔记标题 | `梅拉宾法则` |
| `date` | ✅ | 创建日期 | `2026-07-09` |
|| `status` | ✅ | `draft` / `active` / `mature` / `deprecated` / `archived` | |
| `tags` | ✅ | 从标签字典选取 | `[心理学]` |
| `type` | 原子笔记必填 | `concept` / `model` / `practice` / `critique`。`moc` 类型专用于 MOC 索引笔记，详见 §MOC笔记标准 | |
| `source` | 推荐 | 核心主来源，单值 | `沉默的讯息` |
| `author` | 选填 | 原作者 | `Albert Mehrabian` |
| `project` | 选填 | 归属项目名 | `操盘手骑士` |
| `archived_date` | 归档必填 | 归档日期 | `2026-07-09` |
| `aliases` | 选填 | 搜索别名 | `["7-38-55法则"]` |
| `related` | 选填 | 关联笔记 | `["[[非语言沟通]]"]` |

`modified`：文件最后修改时间。该字段由 Obsidian 文件系统元数据（`file.mtime`）自动维护，不占用 META-02 的字段配额，无需在 YAML 中手动填写。Agent 进行陈旧检测时以此为准。

### 原子笔记 YAML 标准模板

```yaml
---
title: 概念名
date: YYYY-MM-DD
status: active
type: concept
tags: [领域]
source: 核心来源
author: 原作者
aliases: []
related: []
---
```

### 原子笔记状态流转

```
draft → active → mature → archived
                │
                └──────→ deprecated
```

`deprecated` 与 `archived` 均为终态，可从 `active` 或 `mature` 直接转入，不可逆。

全局 `status` 合法值：`draft` / `active` / `mature` / `deprecated` / `archived`

- `draft` / `active` / `archived`：通用，适用于所有层
- `mature`：适用于资源层（31_Atomic_Notes）和领域层（20_Areas）
- `deprecated`：常用于资源层（31_Atomic_Notes）标记被证伪的概念，也可用于领域层（20_Areas）标记过时方法论。不适用于项目层

### YAML 书写规范

- 枚举值统一全小写（`draft` 而非 `Draft`）。
- 布尔值用 `true/false`。
- 当字段无值时，统一使用空字符串占位，即 `source: ""`。
- `tags` 使用 YAML 数组语法：`tags: [领域]` 或换行列表示。不使用 `#` 前缀。
- 字段排列建议顺序：`title → date → status → tags → project → source → author → aliases → related`。
- `source` 字段首选值约定：中文译本用中文全名（如 `原子习惯` 而非 `Atomic Habits`）。

## §归档操作协议 {#archive}

### 核心规则

**ARC-01**：项目归档须同时执行：① 移入 `40_Archive/`；② YAML 中 `status: archived`；③ 添加 `archived_date: YYYY-MM-DD` 字段。

### 归档细则

- **归档即冻结**。存量归档文件不追溯改造，新归档须执行当前规范。
- **单篇笔记归档**：参照执行上述三步操作，并添加 `归档` 标签。
- **归档操作须谨慎**。归档前确认：① 内容已完成或不再活跃；② 无其他活跃笔记通过双链依赖此内容。
- 项目主文档与单篇笔记归档时，均须同步添加「归档」标签。

### 归档内容复苏

归档内容恢复活跃时，执行以下复苏流程：

1. 移出 `40_Archive/` 至对应活跃目录
2. `status` 改为 `active` 或 `draft`
3. 移除 `archived_date` 字段
4. 移除「归档」标签
5. 项目复苏需同步更新项目主文档的 `status` 字段

## §MOC 笔记标准 {#moc}

### MOC 定位

MOC（Map of Content）是笔记的结构索引，属于精选导航。MOC 仅收录核心、高频、里程碑式笔记。全量检索统一通过标签实现。

两者定位不同，不强制一致：
- **标签** = 全量筛选工具（机器检索）。
- **MOC** = 精选导航工具（人工策展）。

### MOC YAML 模板

```yaml
---
title: 主题名 MOC
date: YYYY-MM-DD
type: moc
status: active
tags: [领域]
---
```

### MOC 创建建议

- 领域大类用标签聚合，细分主题建 MOC 人工精选。
- 同一主题下原子笔记积累较多时，可以考虑创建 MOC，完全按需决定。
- MOC 正文建议包含：主题简述、核心概念列表（含一句话描述）、概念间关系说明。

## §双链使用规范 {#links}

### 链接原则

- **链接须承载语义**：每次添加内链时，应在链接旁保留关联说明。无上下文的裸链接是图谱噪音。

  ```
  推荐：
  这个效应与[[认知失调]]有关——当行为与信念冲突时，人会主动调整信念以减少不适。

  不推荐：
  参见：[[认知失调]]
  ```

- **优先使用原生短名链接**：`[[概念名]]`。非必要不使用别名 `[[概念名|显示名]]`。

- **空链接与断链的区别**：空链接指向尚未创建的笔记（"计划写但还没写"的待办提示），保留不清理。断链指向已删除或重命名的笔记（无效链接），需要修复。月度巡检时顺带核查断链即可。

### 链接维护

- 修改笔记文件名时，Obsidian 设置中的"自动更新内部链接"须保持开启。
- 定期检查断链（可在 Obsidian 的"出链"面板中查看）。

## §内容质量标准 {#quality}

### 推荐原则（非强制）

**笔记粒度**：一条笔记聚焦一个核心概念。若内容超出单一概念范畴，考虑拆分为多篇关联笔记。

**正文结构推荐范式**：建议正文遵循 `核心概念 → 核心理念 → 实践应用 → 关联笔记` 的结构，非强制。

### 重复笔记处置

发现重复概念时，合并核心内容到主笔记。被合并的笔记文件名加 `⚠️` 前缀，正文保留跳转链接指向主笔记。

```
⚠️认知失调（旧版）.md

本文内容已合并至 [[认知失调]]，本文件仅作追溯留存。
```

### 外部导入内容处置

从外部导入的内容（剪藏、导出、迁移）须经以下步骤：
1. 统一放入 `00_Inbox/外部导入/`
2. 人工审核，提取有价值概念
3. 按原子笔记标准重写（纯概念名、YAML 完整、正文聚焦单一概念）
4. 移入 `31_Atomic_Notes/` 对应领域/类型目录
5. 原文归档或删除

## §系统维护 {#maintenance}

### AI Agent 操作权限

AI Agent（含 Hermes）默认仅开放只读权限（检索、总结、合规校验）。以下操作属写入权限，需经人工确认后执行：

- 重命名文件
- 移动目录
- 批量修改标签
- 删除文件
- 覆盖原子笔记正文
- 归档或复苏笔记/项目

含 HERMES 操作手册约定的 `human_edited: true` 标记（Agent 协作专用保护标记，具体定义详见 HERMES 操作手册）的页面绝对禁止覆盖正文。

AI 生成内容须先放入 `00_Inbox/`，经人工审核并按本规范标准化后，方可移入资源库或领域目录。

### 合规巡检

合规巡检已由 Hermes 自动执行。详见 `HERMES.md` §六「月度合规巡检」规则。

人类无需手动发起巡检。每月 1 日自动执行，报告写入当月 Worklog。
手动指令：「生成本月合规报告」。

原有巡检检查项与统计口径已集成至 Hermes 自动化流程中：
- 命名合规率、双标签占比、消歧后缀占比三项指标自动统计
- 扫描范围限定为活跃状态（`active`/`mature`）原子笔记
- 红线阈值自动判定，触及红线时列出违规文件清单

### 单次批量修改

单次批量修改文件数超过 10 个时（含人工操作与 Agent 操作），操作前须完成全库备份。

### 速查卡同步维护 {#maintenance-sync}

总纲主版本或次版本升级时，速查卡必须同步更新（版本戳 + 规则内容）。修订版本升级时速查卡可不同步。

版本升级后须同步更新：速查卡、目录别名映射表（如有变更）、系统演进备忘录（记录变更摘要）。

### 规模复盘阈值

| 文件数 | 动作 |
|:------|:-----|
| 达 1000 份 | 启动架构轻量复盘，评估目录与标签体系是否适配 |
| 达 3000 份 | 启动全面架构评估 |

### §26M-03：Areas 透镜与原子笔记双向关联

> 解决 Areas 透镜无实体内容与 Resources 知识库之间的双向链路问题。

**规范**：每篇原子笔记 YAML `related` 字段追加所属 Areas 透镜 MOC 链接。

```yaml
related:
  - "[[A1_认知算法/A1_认知算法]]"
  - "[[A3_精力底盘/_MOC]]"
```

**透镜映射标准**：

| 原子笔记学科 | 所属透镜 | 说明 |
|:---|:---|:---|
| 个人成长（概念/模型） | A1 + A2 | 认知模型同时属于思维系统和执行系统 |
| 个人成长（实践） | A2 | 实践类属于能力接口 |
| 知识管理 | A2 | 知识管理方法论属于执行系统 |
| 心理学 | A4 | 心理学/哲学属于内核定力 |
| 健身 | A1 + A3 | 训练法则同时属于认知算法和精力底盘 |
| 语言 | A2 | 语言技能属于能力接口 |
| 科学 | A1 | 科学理论属于认知算法 |

**存量维护**：Hermes 批量扫描补全。新增笔记归档时同步填写。

**透镜 MOC 自动检索**：每个 A/D/X 系列 MOC 底部均追加 DataviewJS 查询，自动聚合所有关联的原子笔记。
