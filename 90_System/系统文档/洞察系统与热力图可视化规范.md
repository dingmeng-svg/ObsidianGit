# 洞察系统与热力图可视化规范

> **版本**：v1.1.0（2026-07-18 终审定稿，含后期所有修正）
> **适用**：Hermes Agent 每日洞察生成、首页 Dashboard 嵌入渲染
> **关联系统文档**：`01_知识库统一规范总纲.md`、`13_Language Chunk 炼金术士.md`、`14_Hermes Ingest 编译与原子笔记生产规范.md`
> **关联 Skill**：`hermes-daily-insight`（七维知行循环洞察生成器）
> **位置**：`90_System/系统文档/洞察系统与热力图可视化规范.md`

## 一、七维洞察框架

Insight 文件由七个 H2 子标题组成，每个对应一个维度，顺序固定不可调换：

| 序号 | 标题 | Emoji | 意象 | 数据源 |
|:---:|:---|:---:|:---|:---|
| 1 | 观全局 | 🌐 | 全局拓扑 | 全库扫描指标 |
| 2 | 察潜流 | 🌊 | 水面下的洋流 | 原子笔记 type 分布 |
| 3 | 拂遗珠 | 🪸 | 深海遗珠 | 被遗忘的文件/素材 |
| 4 | 照暗面 | 🔦 | 聚焦光束照亮盲区 | 项目停滞/未完成事项 |
| 5 | 辨风势 | 🍃 | 风向动态 | 标签/领域活跃度排名 |
| 6 | 测热力 | 🌡️ | 温度刻度 | file.day 活跃度 + 注意力分布 |
| 7 | 践一诺 | 🎯 | 靶心落点，唯一承诺 | 前六维综合，唯一行动项 |

### 格式规则

- 所有 H2 子标题统一为 `## [emoji] [三字动词+名词]` 格式
- 不可加前后缀，不可用旧标题
- 每个 H2 下必须有**丰富的文字内容**，不能只靠 dataviewjs 图表
- 精简过头是错误——dataviewjs 图表是增强，不是替代文字内容

### 内容完整性要求

- **拂遗珠**：列出具体文件路径、文件名、数字。不要只说"有几篇"，要说"哪些文件、在哪里、什么状态"
- **照暗面**：列出具体项目名、文件数、未完成事项
- **辨风势**：条形热力图 + 一句趋势判断文字
- **践一诺**：至少 1 条有具体数据支撑的行动项，引用其他维度的数据

| 历史索引 | `历史洞察.md` | `90_System/Insight/` |

### FrontMatter 规范

```yaml
---
title: "🌅 2026年07月18日 知识洞察"
date: 2026-07-18
tags: [洞察, 系统文档]
---
```

### 双写模式

1. **写入归档文件**：`90_System/Insight/每日洞察/YYYY-MM/YYYY-MM-DD-Insight.md`
2. **同时覆盖写入今日入口**：`90_System/Insight/每日洞察/今日知识洞察.md`
3. 两个文件内容完全一致，不可只写入口跳转
4. 页脚时间戳精确到分钟：执行 `date` 命令获取系统当前时间
5. 页脚格式：`*本报告由 Hermes Agent 于 YYYY-MM-DD HH:mm 自动生成。*`

### 数据范围声明

- 全库扫描，**不加后缀说明**。不写「含 90_System/、40_Archive/」也不写「不含」
- 就是「全库扫描」四个字

**意图**：分析原子笔记的 type 分布，判断近期思维模式倾向（概念输入 vs 实践输出）。

**示例**：

## 八、Heatmap Calendar 热力图规范

### 4.1 渲染引擎

使用插件 **Heatmap Calendar v0.7.1** 的 `window.renderHeatmapCalendar` 全局函数，通过 DataviewJS 调用。

**⚠️ 已验证：插件 `onload()` 只挂载了 `window.renderHeatmapCalendar`，未注册 ````heatmap` 代码块处理器。不要建议使用原生 ````heatmap` 代码块。**

### 4.2 标准代码块

```dataviewjs
try {
  const pages = dv.pages('"20_Areas/22_个人成长/Bullet Journal" or "00_Inbox" or "10_Projects" or "20_Areas" or "30_Resources"')
    .where(p => p.file.day);
  const countMap = {};
  pages.forEach(p => {
    const key = p.file.day.toFormat("yyyy-MM-dd");
    countMap[key] = (countMap[key] || 0) + 1;
  });
  const entries = Object.entries(countMap).map(([date, count]) => ({
    date: date,
    intensity: count
  }));
  renderHeatmapCalendar(this.container, { colors: "配色组名", entries: entries });
} catch(e) {
  dv.span("⚠️ Heatmap Calendar 插件未启用，请安装后查看热力图");
}
```

### 4.3 colors 参数规则

| 传值方式 | 说明 | 示例 |
|:---|:---|:---|
| **字符串（推荐）** | 引用插件设置的配色组名 | `"default"`（当前活跃） |
| Hex 数组 | 硬编码 5 色 | `["#c6e48b", "#7bc96f", "#49af5d", "#2e8840", "#196127"]` |

**禁止**：
- ❌ 用 `rgba()` 传 colors 参数——会导致渲染引擎挂掉，格子全空白
- ❌ 用 ````heatmap` 代码块——插件未注册处理器

## 九、进度条系统（renderGreenBar）

### 5.1 通用函数

所有进度条统一使用 `renderGreenBar` 函数，布局为：`左标签 min-width:150px 右对齐 + 进度条 max-width:460px height:8px + 右侧数字外部显示，数字右对齐`。

**CRITICAL: 每个 dataviewjs 代码块必须自己定义 renderGreenBar**——DataviewJS 的 eval 作用域不共享函数定义。三个代码块（观全局、辨风势、注意力分布）各自定义一次同名函数。

```javascript
function renderGreenBar(label, pctOrRank, displayText = null, useRankMode = false) {
    let barColor = "#c6e48b";
    let targetVal = pctOrRank;
    if (useRankMode) {
        if (targetVal > 0.8) barColor = "#196127";
        else if (targetVal > 0.6) barColor = "#2e8840";
        else if (targetVal > 0.4) barColor = "#49af5d";
        else if (targetVal > 0.2) barColor = "#7bc96f";
        else barColor = "#c6e48b";
    } else {
        if (targetVal <= 15) barColor = "#c6e48b";
        else if (targetVal <= 30) barColor = "#7bc96f";
        else if (targetVal <= 45) barColor = "#49af5d";
        else if (targetVal <= 60) barColor = "#2e8840";
        else barColor = "#196127";
    }
    let rightText = displayText !== null ? displayText : `${pctOrRank}%`;
    return `<div style="display: flex; align-items: center; gap: 12px; margin-bottom: 10px;">
        <span style="min-width: 150px; font-size: 13px; color: #4B5563; flex-shrink: 0; text-align: right;">${label}</span>
        <div style="flex: 1; max-width: 460px; height: 8px; background-color: #F3F4F6; border-radius: 99px; overflow: hidden;">
            <div style="width: ${useRankMode ? (targetVal * 100) : targetVal}%; height: 100%; border-radius: 99px; background-color: ${barColor};"></div>
        </div>
        <span style="min-width: 30px; font-size: 13px; font-weight: 600; color: #4B5563; text-align: right; white-space: nowrap; flex-shrink: 0;">${rightText}</span>
    </div>`;
}
```

### 5.2 双模式调用

| 模式 | 用途 | 参数 | 调用方式 |
|:---|:---|:---|:---|
| **普通模式** | 观全局、注意力分布 | `useRankMode=false` | 传百分比（0-100），按 15/30/45/60 阈值分档 |
| **排名模式** | 辨风势（极端数据断崖） | `useRankMode=true` | 传排名系数（0-1），按 0.2/0.4/0.6/0.8 等分 |

**调用示例：**

```javascript
// 观全局（普通模式，显示 val）
for (let d of items) {
    html += renderGreenBar(d.label, d.pct, d.val, false);
}

// 注意力分布（普通模式，显示百分比）
for (let d of data) {
    html += renderGreenBar(d.label, d.pct, null, false);
}

// 辨风势（排名模式，显示 count）
let totalTags = tagsData.length;
for (let i = 0; i < totalTags; i++) {
    let d = tagsData[i];
    let rankPct = (totalTags - i - 1) / (totalTags - 1);
    tagHtml += renderGreenBar(d.label, rankPct, `${d.count} 篇`, true);
}
```

## 十、配色系统与换色流程

### 6.1 当前活跃配色

**当前活跃：default 绿**（插件默认配色 `#c6e48b → #7bc96f → #49af5d → #2e8840 → #196127`）

### 6.2 三处必须统一配色的地方

| 位置 | 控制方式 | 说明 |
|:---|:---|:---|
| **热力图方块** | `renderHeatmapCalendar` 的 `colors` 参数 | 引用插件配色组名（字符串），当前 `"default"` |
| **观全局进度条** | 硬编码 5 色分档，在 `renderGreenBar` 函数内 | 按百分比分档，最深色兜底 |
| **测热力进度条** | 同上（共用 `renderGreenBar` 函数） | 颜色逻辑在函数内部，无需外部数组 |

### 6.3 换色三步法

当用户说"帮我改成 X 配色"时，按以下步骤执行：

1. **热力图**：`colors: "配色组名"`（引用插件设置）
2. **观全局进度条**：修改 `renderGreenBar` 函数内的 5 色硬编码值（注意普通模式和排名模式各 5 个，共 10 处颜色值）。文字颜色通过 `textColor` 变量控制，浅底用最深色值，深底用白色。
3. **测热力进度条**：与观全局共用 `renderGreenBar`，改函数即可。注意测热力代码块中多余的 `colors` 数组要删除（`renderGreenBar` 内部自己算颜色，不需要外部数组）。
4. **同步归档**：`cp 今日知识洞察.md → 2026-07/YYYY-MM-DD-Insight.md`

**注意**：`renderGreenBar` 在三个代码块中各定义一次，三处必须同步修改。热力图引用的是插件配色名，改进度条函数时不需要改热力图那行，反之亦然。

### 6.4 文字颜色规则

文字颜色由 `renderGreenBar` 函数内部通过 `textColor` 变量控制，当前实现为统一深灰色 `#4B5563`（数字在进度条外部，不受背景色影响）。

### 6.5 颜色迭代历史

| 迭代 | 配色 | 结果 |
|:---|:---|:---:|

| 1 | Apple 灰度 #6B7280 | ❌ 用户回滚 |

## 十一、踩坑记录

### 8.1 rgba() 导致热力图渲染引擎挂掉

**问题**：`renderHeatmapCalendar` 的 `colors` 参数传 `rgba()` 数组 → 格子全空白
**根因**：插件解析 `rgba()` 时渲染引擎挂掉
**解法**：必须用 Hex 数组或引用插件配色名

### 8.2 CSS 无法覆盖进度条颜色

**问题**：想用 CSS `!important` 覆盖进度条背景色
**根因**：进度条是 DataviewJS 内联 `div style` 渲染，CSS 选择器优先级不够
**解法**：直接修改 JS 源码中的颜色值

### 8.3 ```heatmap 代码块不可用

**问题**：尝试用原生 ````heatmap` 代码块替代 DataviewJS
**根因**：插件 v0.7.1 未注册代码块处理器，`onload()` 只挂载了 `window.renderHeatmapCalendar`
**解法**：保持 DataviewJS 方案

### 8.4 renderGreenBar 跨代码块不可用

**问题**：函数定义在第一个代码块，后面代码块报 `ReferenceError`
**根因**：DataviewJS 每个代码块独立作用域
**解法**：每个代码块各自定义一次

### 8.5 热力图月份标签截断

**问题**：`Jan` 显示为 `Ja`，`Mar` 显示为 `M`
**根因**：容器 `min-width` 不足，字符被截断
**解法**：CSS `min-width:0` + `white-space:nowrap` + `overflow-x:auto`

### 8.6 星期标签被遮挡

**问题**：Tue/Thu/Sat 显示不完整
**根因**：CSS 未对 `.heatmap-calendar-days li` 设置样式
**解法**：CSS `white-space:nowrap; font-size:10px; padding-left:2px`

### 8.7 图片粘贴导致 GUI 卡死

**问题**：消息附件直接粘贴图片 → Hermes GUI 线程 GIL 卡死
**根因**：`image_input_mode: auto` 时，有 `auxiliary.vision` 配置 → 走文本预处理 → 同步阻塞 GUI
**解法**：改为 `image_input_mode: native`，跳过预处理

### 8.8 User Profile 溢出导致性能下降

**问题**：memory 满 99%（1375/1375 chars），操作变慢
**解法**：删除冗余大条目，清理至 66%
