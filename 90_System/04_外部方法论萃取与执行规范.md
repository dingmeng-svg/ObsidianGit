## 2. Inbox 处理协议更新

### 2.1 人类缓冲区：`Inbox_快速捕获.md`
- **定位**：手动临时缓冲区，**非** Hermes 编译源。
- **结构**：采用 `#type/` 标签做软分区，降低收集阻力。
  - `#type/task` → 每周整理至当日 BuJo 日记
  - `#type/note` → 对应素材移入 `00_Inbox/_raw/` 触发编译
  - `#type/habit` → 提炼至 `Habit Design Reference.md` 孵化池
- **⚠️ AI 禁令**：Agent **不得**主动读取或修改此文件，除非用户在对话中显式引用。

### 2.2 编译源保持不变
- Hermes 的唯一自动编译入口仍为 `00_Inbox/_raw/` 下的独立文件。
- 任何关于"单文件 Inbox 承载所有内容"的建议均视为**无效输入**。

## 3. 习惯系统双轨制规范
习惯系统严格拆分为"设计"与"执行"两个独立文件，禁止混合。

### 3.1 设计层：`Habit Design Reference.md`
- **路径**：`20_Areas/.../22_个人成长/Habit Tracking/Habit Design Reference.md`
- **内容**：习惯叠加公式、孵化清单表格、坏习惯阻断器表格。
- **触发场景**：仅在用户主动要求"设计新习惯"、"分析坏习惯"或"审视孵化池"时读取。
- **⚠️ AI 禁令**：晨间/晚间简报**不得**扫描此文件。

### 3.2 执行层：`Habit Scorecard.md`
- **路径**：`20_Areas/.../22_个人成长/Habit Tracking/Habit Scorecard.md`
- **内容**：**仅包含**极简打卡表格。
- **设计上下文链接**：若需查阅新习惯设计或阻断策略，通过以下 Obsidian 双链跳转，**不在本文件中嵌入任何设计区块**：
  > 新习惯设计或阻断策略 → 见 [[Habit Design Reference]]
- **触发场景**：晨间简报提取今日待打卡项；晚间复盘对照完成情况。

### 4.1 Copilot Prompts 完整定义

```markdown
---
name: 晨间简报
description: 从今日日记、习惯记分卡、活跃项目提取当日执行要点
---
你现在是 Hermes Agent。请执行晨间简报任务。
**任务目标**：生成今日执行简报，不修改任何文件。
**执行步骤**：
1. 读取今日日记（路径：`20_Areas/22_个人成长/Bullet Journal/{{date:YYYY-MM-DD}}.md`），查看昨日复盘内容。
2. 读取 `20_Areas/22_个人成长/Habit Tracking/习惯记分卡.md`，确认今日待打卡习惯。
3. 扫描 `10_Projects/` 下活跃项目的近期更新。
4. 输出简洁简报：
   - 🎯 今日三件事建议
   - 🔥 今日待打卡习惯
   - ⚠️ 昨日未完成的提醒
```

#### `evening_review.md`
```markdown
---
name: 晚间复盘辅助
description: 回顾今日日记，生成复盘洞察建议
---
你现在是 Hermes Agent。请执行晚间复盘辅助任务。
**任务目标**：基于今日日记内容，生成复盘洞察建议，不修改任何文件。
**执行步骤**：

3. 输出建议：
```

## 附件与图床分流管理

> **上位规则**：本地附件存放遵循 [[01_知识库统一规范总纲#directories|总纲 DIR-02]]。图床图片以纯文本 URL 存在于笔记正文，不构成本地附件。

### 一、本地附件存放规则

| 类型 | 存放路径 | 说明 |
|:---|:---|:---|
| 全局通用附件 | `90_System/Assets/` | 系统架构图、规范截图、食谱成品图、隐私图片、离线必需素材 |
| 项目专属附件 | `10_Projects/{项目}/_attachments/` | 项目截图、交付文档、调研素材 |

禁止在 `00_Inbox/`、`20_Areas/`、`30_Resources/`、`31_Atomic_Notes/` 下散落任何附件。本地附件总量突破 200 张时，按需新增子分类目录。

### 二、图床标准链路与硬性校验

> **详细规范**：详见 [[21_图床与多端同步基础设施规范#二、图床层规范]]。
> 以下为硬性校验要点，实际配置以 21 号文档为准。

固定链路：**PicGo + 腾讯云 COS + Image Auto Upload Pro + Paste Image Rename**

#### 硬性落地校验（必须全部通过）

1. COS 存储桶权限：**公有读私有写**
2. 上传后 URL 必须为**永久公开链接**，无 `Expires`、`Signature` 等签名参数
3. 插件加载顺序：Paste Image Rename 优先于 Image Auto Upload Pro
4. 上传失败策略：**保留本地附件至 Assets/**，禁止丢弃、禁止空链接

#### 存储桶与密钥隔离

图床应使用**独立存储桶**，与 Remotely Save 同步桶物理隔离。在腾讯云 CAM 中创建**子账号**，关联自定义策略仅授权图床桶的读写权限，PicGo 中填写子账号密钥。不复用主账号密钥或 Remotely Save 的桶。

#### 可选安全加固（建议在发布场景下配置）

进入 COS 控制台 → 存储桶 → 安全管理 → 防盗链设置，配置 Referer 白名单：
- **必须**允许空 Referer（Obsidian 本地访问不携带 Referer 请求头。若禁止，本地笔记内所有图床图片加载失败）
- 允许自己的发布域名

纯本地使用阶段可不配置防盗链。

#### 命名规范（仅约束新增素材）

- 本地系统素材：`sys_简短描述.png`
- 图床素材：默认时间戳模板，可手动自定义语义名称

### 三、素材分层兜底策略

| 等级 | 素材类型 | 兜底规则 |
|:---|:---|:---|
| 高 | 系统架构图、核心规范配图 | 图床+本地双备份 |
| 中 | 食谱成品图、关键封面图 | 建议本地留存备份 |
| 低 | 教程临时截图、演示配图 | 仅云端存储，不做本地冗余 |

### 四、生命周期与清理机制

1. 本地附件：每半年系统体检，Agent 输出孤立附件清单，人工确认清理
2. COS 图床：每半年人工清理 6 个月内无笔记引用的死图
3. Agent 权限：**仅输出清单，不自动删除**，所有删除必须人工终审
