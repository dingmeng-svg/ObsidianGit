# Hermes 知识库操作规则 v3.0 (生产版)

> **地位声明**：本文件是 Hermes Agent 在知识库中执行编译、维护、纠错任务的最高准则与 SOP。所有 Agent 操作均以此为准。
>
> **版本**：v3.3
> **生效日期**：2026-07-09
> **替代**：HERMES.md v2.3
>
> **相关规范**：
> - [[01_知识库统一规范总纲]] — 文件规范（命名、标签、目录、元数据）
> - **本文件是 Agent 行为规范**，总纲是**文件规范**，两者为**平行关系**
> - Agent 写出的文件必须符合总纲标准，但 Agent 的行为边界由本文件定义
> - 本文件定义 Agent 的权限分级、写入协议、编译规则；总纲定义合规判定的标准
>
> **核心策略**：所有 AI 产物与人类笔记通过 YAML 元数据分级控制，实现"融合但不混淆"。
> **核心原则**：低维护成本优先。AI 辅助的底线是不制造额外人工负担。
>
> **受众分层原则**（新增内容严格遵守）：
> - HERMES.md **永久禁止** 新增纯理念、原则性、方法论类长篇阐释。本层面向 Agent，保留权限分级、触发条件、执行逻辑和阈值参数
> - 人类原则和设计哲学统一由总纲和 L1 方法论承载
> - L2 操作文档人机分区固化：上半部分人类 SOP，下半部分 Agent 执行规则。新增内容严格分区

## 一、核心铁律

> **层级关系与仲裁规则**
>
> 1. [[01_知识库统一规范总纲]] 是知识库最高宪法。所有文件、Skill、Agent 操作
>    均不得违背总纲的通用强制规则（命名、标签、目录、元数据、归档）。
>
> 2. 本文件（HERMES）是 Agent 专属行政执行法。仅在以下四类场景中，
>    HERMES 的规则优先于总纲：
>    - Agent 写入权限分级与碰撞保护机制
>    - Ingest 编译的首次写入协议
>    - 批量操作的安全边界（如禁止 rm -rf、归档时只移动指定文件）
>    - Agent 日志记录与审计义务
>
> 3. HERMES 的特权仅限于操作协议层面，绝不僭越数据模型层面
>    （字段定义、文件命名、目录结构、标签字典的解释权归总纲）。
>
> 4. 交叉场景仲裁：同一操作同时触及数据模型与 Agent 操作协议时，
>    **数据模型标准**（命名、字段、路径、标签）严格遵循总纲；
>    **操作执行规则**（是否分批、是否备份、是否需人工确认）遵循 HERMES。
>    写入权限、碰撞保护、批量安全边界类操作，以 HERMES 为准。

1. **Raw 只读原则**：`00_Inbox/_raw/` 是唯一的编译输入源。永远只读、不改、不删、不移。

2. **人类领地尊重原则**：
   - `30_Resources/31_Atomic_Notes/` 中 `human_edited: true` 的页面 → **绝对禁止覆盖正文**。Hermes 仅可在文末 `## 🤖 Hermes 补充` 区块追加内容，并标注 `suggested_at: YYYY-MM-DD`。
   - 上述目录中无此标记的页面 → 允许增量更新，但须遵守本规则 §二 定义的权限分级。

3. **AI 产物隔离原则**：
   - AI 生成的编译产物**须先放入 `00_Inbox/`**，经人工审核并按总纲标准化后，方可移入正式目录。
   - AI 产物最终按内容属性落入现有 PARA 结构：
     - 概念/模型/批判/实践/人物 → `30_Resources/31_Atomic_Notes/` 对应子类
     - 摘要 → `30_Resources/33_Summaries/`
     - 综合分析/MOC → `30_Resources/32_MOCs/` 或 `30_Resources/34_Synthesis/`
   - 所有 AI 生成页面必须包含 `ai_generated: true` 字段。

4. **日志强制记录**：
   - 任何 Ingest、Lint、Audit 操作完成后，必须按日期追加记录到 `90_System/Worklogs/`，并更新 `90_System/记忆交接快照/` 中的知识库状态摘要。
   - **并发写入保护（通用）**：修改任意正式笔记前，先读取文件最新修改时间，若距读取时刻 < 5 秒，等待 3 秒后重试。写入 Worklogs 时，若当日文件已存在，必须先读取全文 → 在内存中追加新条目 → 再整体写回。**禁止使用 append-only 模式直接追加**。

5. **双节点写入纪律**：
   - Agent 自身的观察、推断、建议 → **禁止写入用户日记正文或原子笔记正文**
   - Agent 推断的合法出口：Worklog / 日记中的 `[!note]` Callout 区块（标注"待验证"）
   - 发现另一个 Agent 的可疑陈述 → 按 `Agent跨实例纠正工作流.md` 执行：先问用户，确认后修正

6. **Agent 操作风险分级与熔断规则**：

| 操作类型 | 风险等级 | 熔断规则 |
|:---|:---|:---|
| 删除文件 | 高危 | **Agent 禁止自主执行**。仅可在 YAML 中添加 `pending_delete: true`，由人工确认后删除 |
| 批量修改正文（> 5 篇） | 高危 | 执行前必须列出完整文件清单，等待人类确认「确认执行」 |
| 修改系统文档核心规则（总纲/HERMES） | 高危 | 执行前须完成全量备份并校验备份完整性，在对话中明确告知修改内容。未经人类显式指令禁止自主修改 |
| 修改 `20_Areas/` 下 `human_edited: true` 的笔记正文 | 高危 | **绝对禁止覆盖正文**。仅可在文末追加 `## 🤖 Hermes 补充` 区块。若笔记 YAML 中无 `human_edited` 字段，视为 `false`，Agent 可按低危增量更新规则执行 |
| 批量重命名（> 5 篇） | 中危 | 执行前列出完整清单，等待人类确认 |
| 批量标签修改（> 5 篇） | 中危 | 执行前列出完整清单，等待人类确认 |
| 单篇笔记的增量更新 | 低危 | **仅限两种场景** Agent 可自动执行：① 文末追加 `## 🤖 Hermes 补充` 区块；② YAML 中新增或修改少量字段（非批量改写元数据）。正文段落新增、改写、结构调整 → 视为中危操作，需人工确认 |
| 纯注释补充（追加事实注释、补充参考来源） | 低危 | 不视为正文改写，Agent 可自动执行 |

**防拆分原则**：
- 批量操作的阈值（如 > 5 篇）以人类发起的**单次任务意图**为计算单位，禁止 Agent 将单次高危任务拆分为多个低危子任务以规避确认
- **显式批量指令豁免**：若人类在指令中显式包含「全部」「所有」「批量」等意图词，视为已授权，不触发 > 5 篇的熔断确认
- **修饰范围限定**：仅当关键词修饰本次操作的完整目标集合时触发豁免；局部子集批量（如「批量归档其中的 3 份」）仍执行阈值确认
- Agent 在执行大批量操作时应采用分批写入（每批 5 篇）以防上下文溢出，每批完成后输出进度
- **模糊指令防御**：若人类指令缺乏明确范围限定（仅针对修改/执行类意图），Agent 在批量操作前必须先输出预估影响范围（如「此操作将影响 N 篇笔记」），等待人类确认。查询/扫描意图可直接执行并输出报告
- **连续指令累计提醒**：若人类短时间内连续下达多条同类型批量操作，累计总量超阈值，Hermes 主动提醒合并单次执行

> **备注**：仅修改/写入类批量指令计入累计统计，纯查询、扫描、导出类指令不计入，不会触发合并提醒。

**批量操作豁免**：
目标目录为 `40_Archive/` 的批量移动操作，及其配套的元数据校准（`status` 改为 `archived`、添加 `archived_date`、标签清理），不受 > 5 篇人工确认约束。

**备份校验**：
修改系统文档核心规则前，执行 `cp` 备份后，Agent 必须校验备份目录中的文件数量和总大小是否与源目录一致。校验通过后方可执行覆盖写入。校验失败则中断操作，并在 Worklog 中记录阻断日志。

> **备注**：备份完整性抽样校验固定抽取 3 份核心系统文档（01_总纲、HERMES.md、05_Vault Management），校验 YAML 无语法报错。抽样失败直接阻断修改操作。

**月度提醒**：
- 每月 Lint 统计所有带 `pending_delete: true` 的文件，在 P1 警告区列出清单提醒人工确认清理
- 每月 1 日，Agent 提醒人类手动备份 `90_System/` 目录

### 系统文档废弃前置校验规则

人类发起删除或废弃某系统文档的指令时，Hermes 自动执行双向依赖检索：

1. **Skill 依赖扫描**：搜索所有 Skill 的 `related_system_docs` 字段，列出包含本文档的 Skill 清单
2. **文档依赖扫描**：搜索所有系统文档的 `related_docs` 字段和正文中的 `[[wikilink]]`，列出引用本文档的文档清单
3. **输出依赖清单**：若存在依赖，禁止直接删除。输出完整清单并提示：
   「以下 N 个 Skill 和 M 份文档依赖此文件，请先解绑依赖后再执行废弃」

4. **废弃标记**：仅在全部依赖解绑后，方可标记 `status: deprecated`，并在文档头部添加：
   > **废弃说明**：废弃时间 / 替代文档 / 废弃原因

5. **已废弃文档的管理规则**：
   - 已废弃文档完全退出文档治理体系，不参与同步校验、断链检测、版本比对
   - 季度快照中汇总统计废弃文档数量
   - 重新启用已废弃文档时，须重置 `status: active`、更新 `version`、更新 `last_sync`，并重新校验全部依赖关系

## 二、Agent 写入权限分级

为平衡安全与效率，将写入操作按风险等级分为三级：

| 级别 | 操作范围 | 是否需要人工确认 |
|:-----|:---------|:----------------:|
| **L0 · 自动执行** | 文末追加关联说明、新增参考链接、补全 `aliases` 字段 | 否 |
| **L1 · 有条件自动** | 修正笔误、补充缺失的 `source`/`author` 字段、在 MOC 文末追加候选链接（标注「待确认收录」） | 否（单篇修改字数 ≤ 正文 10%） |
| **L2 · 必须确认** | 修改核心概念定义、重构段落结构、批量改标签、重命名文件、移动目录、删除文件、归档或复苏笔记/项目 | 是 |

**L1 增量更新边界**：单篇单次增量修改字数不超过正文的 10%，且仅允许补充信息、关联链接，不得修改核心概念定义。超出阈值自动升级为 L2，触发人工确认流程。

## 三、Hermes 专用字段定义

以下字段属于 Agent 协作元数据，不计入总纲 META-02 的 12 个业务元数据字段总量限制。这些字段仅出现在 AI 生成或 Agent 处理过的笔记中。

|| 字段 | 类型 | 说明 |
|:-----|:-----|:-----|
| `ai_generated` | 布尔 | `true` 表示该笔记由 AI 编译生成，尚未经人类审阅 |
| `human_edited` | 布尔 | `true` = **AI 写入权限锁**。禁止 Agent 覆盖正文，仅允许文末追加 `## 🤖 Hermes 补充`。与内容质量、修订深度无关。 |
| `deep_reviewed` | 布尔 | `true` 表示语言组块笔记已完成至少一轮人工深回流修正。仅适用于 `31_Atomic_Notes/语言/`，不计入 META-02 字段配额。 |
| `last_ai_edit` | 日期 | Agent 最近一次修改该笔记的日期 |
| `ai_edit_summary` | 字符串 | Agent 最近一次修改的简要说明 |
| `suggested_at` | 日期 | Hermes 在文末 `🤖 Hermes 补充` 区块追加补充内容的标记日期 |
| `audit` | 字符串 | Lint 检查发现的问题标记，格式 `"high/low: 描述"` |
| `pending_delete` | 布尔 | `true` 表示该文件已被 Agent 标记为建议删除，等待人工确认 |

**与 `status` 字段的关系**：以上字段仅控制 Agent 权限与协作流程，`status` 控制内容生命周期。两者独立，互不替代。

## 四、首次写入协议

当 Hermes 首次在 `00_Inbox/` 中创建 AI 生成页面时，除标记 `ai_generated: true` 和 `status: draft` 外，必须在页面顶部添加以下 Callout：

> [!note] 🤖 Hermes 自动生成 · 待人类审核
> 本文由 Hermes 从原始资料编译生成，尚未审核。
> 请审核后执行以下操作之一：
> - 确认内容无误 → 在 YAML 中添加 `human_edited: true`，移入 `30_Resources/` 对应目录
> - 需修改 → 直接在正文修改，修改完成后添加 `human_edited: true`
> - 不适用 → 删除本文件

## 五、Ingest 编译规则

- **触发条件**：当 `00_Inbox/_raw/` 中有新增文件，或收到人类针对特定文件的显式编译指令时。
- **工作流**：
  1. **路径解析**：若显式指令中的文件路径变量（如 `{{file_path}}`）未被自动替换或为空，必须立即停止并询问："请提供需要编译的原始文件完整路径。"**禁止猜测或扫描整个 `_raw/` 目录。**
  2. 读取目标原始资料，生成结构化摘要。摘要 YAML 必须包含 `source: 文件名` 和 `ai_generated: true`。
  3. 提取概念/实体 → **先查 `30_Resources/31_Atomic_Notes/` 是否已有同名或近义页面**：
     - 已有 + `human_edited: true` → 仅在文末追加 `## 🤖 Hermes 补充` 区块。
     - 已有 + 无此标记 → 按 §二 权限分级执行增量更新，记录 `last_ai_edit` 和 `ai_edit_summary`。
     - 不存在 → **新建页面放入 `00_Inbox/`**，严格执行【首次写入协议】。
  4. 建立双向链接：优先链接到 `30_Resources/31_Atomic_Notes/` 中的人类笔记，其次才是其他 AI 生成页。
  5. **MOC 更新**：Agent 不再主动修改 MOC。笔记只要打了对应标签，自动出现在该领域 MOC 的 Dataview 列表中。
  6. 被动推荐：基于语义相似度，从 `40_Archive/` 检索 ≤3 篇相关旧笔记，在 Summary 末尾以 `## 📚 可能相关的历史笔记` 列出（仅标题+链接）。

### Lint 检查项分级规则

Hermes 的 Lint 扫描将检查项按严重程度分为三级：

| 级别 | 定义 | 包含项 | 处理方式 |
|:---|:---|:---|:---|
| **P0 · 致命错误** | 影响系统正常运行或数据完整性 | 双链完全断裂（目标文件不存在）、YAML 语法无法解析、文件卡在 `draft` 超 30 天（**仅限** `00_Inbox/` 下的文件，或 `10_Projects/` 下**非项目主文档**的文件） | 立即报告，在对话中主动提醒。P0 错误同步纳入审计问题闭环清单，按月持续追踪直至标记已闭环 |
| **P1 · 结构警告** | 影响知识网络健康度 | 核心字段缺失（title/date/status/tags/type）、目录准入状态违规、孤儿页面（无入链且创建超过 14 天） | 月度 Lint 报告中列出明细 |
| **P2 · 格式提示** | 不影响功能，仅偏离推荐规范 | 标签非标准命名、行内字段格式不规范、`source` 字段缺失、消歧后缀可优化 | 月度报告中仅显示总数，不展开明细 |

**时间豁免规则**：
- 对于近 90 天无**人工编辑**（非 Agent 追加 `## 🤖 Hermes 补充` 区块）的笔记，豁免全部 P2 级检查
- **mtime 判定逻辑**：
  - 若笔记 YAML 中无 `last_ai_edit` 字段，直接看 `mtime` 是否 ≥ 90 天
  - 若笔记 YAML 中有 `last_ai_edit` 字段，比较 `mtime` 与 `last_ai_edit`：
    - 如果 `mtime` > `last_ai_edit`，说明人类在 Agent 最后一次修改后又动过该文件，视为「有效人工更新」，不豁免 P2
    - 如果 `mtime` = `last_ai_edit`，说明自 Agent 最后一次修改后人类未动过，豁免 P2 检查
- P0 和 P1 级检查不受时间豁免影响，全库适用

- 「全量深度扫描」：扫描全库，输出完整 P0/P1/P2 明细
- 「近期深度扫描」：仅扫描近 180 天内修改的文件，输出完整 P0/P1/P2 明细

### 月度合规巡检

**触发机制**：
- 每月 1 日，Hermes 自动执行合规巡检扫描

**输出格式**：

|:---|:---|:---|:---|
| 命名合规率 | X% | — | ✅/⚠️ |
| 双标签占比 | X% | < 5% | ✅/⚠️ |
| 消歧后缀占比 | X% | < 10% | ✅/⚠️ |

- 若触及红线 → 列出违规文件清单

- `deprecated` 笔记单独统计合规率，在报告末尾一行展示，不列入违规整改清单

**人类角色**：
- 阅读报告，自行决定是否修复
- 若连续 3 个月同一指标触及红线，Hermes 升级提醒为 ⚠️

**Agent 权限边界**：只做扫描和报告，不做任何自动修正。

**合规红线阈值**：记录于本规则末尾，人类可直接修改数值。年度 Skill-文档校验时同步核对阈值合理性。

### 审计问题闭环跟踪

**隐式闭环判定**：

Agent 不维护显式的工单状态表。每月 Lint 扫描时，直接拿上月报告中列出的违规文件清单进行重新检测：

1. 若该文件的问题已不存在（如双链接上、YAML 补全、文件已归档）→ 自动视为「已闭环」
2. 若问题仍在 → 直接带入本月报告，并在问题描述前追加 `[连续 N 月未闭环]` 前缀
3. 若人类明确表示某问题「废弃不修」→ Agent 在对应笔记 YAML 中写入 `lint_ignore` 字段

**问题唯一标识**：`文件名-问题分类`，如 `31_Atomic/认知模型.md-缺失source`。Lint 检查项使用标准化短代码：

| 检查项 | 短代码 |
|:---|:---|
| 双链断裂 | `broken_link` |
| YAML 语法错误 | `yaml_invalid` |
| draft 超 30 天 | `draft_stale` |
| 核心字段缺失 | `missing_core_field` |
| 目录准入违规 | `dir_violation` |
| 孤儿页面 | `orphan_page` |
| 标签非标准 | `tag_nonstandard` |
| 行内字段格式不规范 | `format_inline_field` |

> **备注**：所有 Lint 短代码统一存放于本对照表。新增校验项时同步补充对应短代码。

**废弃标记的持久化**：

人类可通过指令 `废弃问题 [文件名]-[短代码]` 显式标记。Agent 在对应笔记的 YAML 中写入：

```yaml
lint_ignore: ["short_code_A", "short_code_B"]
```

后续 Lint 扫描时，若检测到此字段且包含对应短代码，自动跳过该项检查，不列入月度报告。仅在季度快照中汇总统计被忽略的问题数量。

- **作用域**：`lint_ignore` 仅作用于当前单文件。如需批量屏蔽，仅能逐文件手动添加，无全局目录屏蔽配置
- **合并策略**：当需要追加新的忽略项时，Agent 必须先读取现有 `lint_ignore` 数组，将新短代码追加至数组中（去重），严禁直接覆盖整个字段

**长期未闭环问题的降级出口**：

本降级规则**仅适用于 P1 结构警告**。所有 P0 致命错误永久参与月度追踪，不会自动降级为已知风险。

若某 P1 问题连续 3 个月未闭环：
- 第 4 个月起，Agent 自动将其降级为「已知风险」，**静默执行，不主动弹窗**
- 仅在当月 Lint 报告的「已知风险」区块汇总展示
- 不再出现在月度 Lint 报告的 P1 明细中
- 仅在季度健康度快照中汇总展示
- 人类可通过手动指令「重新激活 [问题标识]」恢复追踪

### Skill-文档一致性校验

**半年度简易校验**（每年 7 月自动执行）：
仅核对 Skill 声明的 `related_system_docs` 是否真实存在、Skill 是否在 17_Skill 清单中备案。

**年度完整校验**（每年 1 月自动执行）：
比对以下硬性元数据项（不做自然语言语义对比）：

1. Skill 声明的 `related_system_docs` 字段中的文档是否真实存在
2. 文档中声明的 Skill 输入参数名/格式是否与 Skill 代码中的一致
3. Skill 是否在 17_Skill 清单的「Skill-文档映射」表格中备案
4. 对应系统文档中是否反向记录了该 Skill 的依赖关系（双向绑定检查）。
   单向引用标记为「高危差异」。
   修复标准：Skill 在 `related_system_docs` 写入对应文档，文档内 Skill 依赖列表同步登记该 Skill 名称，双方互存记录即合规

输出差异清单时分级：
- **高危差异**（规则逻辑冲突、输入输出参数不一致、单向引用）→ 前置高亮
- **低危差异**（措辞微调、非功能性描述差异）→ 后置汇总，供人工选阅

人类逐项标记「已修复 / 暂不处理 / 非问题」。

### 系统文档交叉引用校验

月度 Lint 断链检测对系统文档进行两级细分：

| 级别 | 类型 | 判定 | 处理 |
|:---|:---|:---|:---|
| **P0** | 文件级断链 | `[[目标文件]]` 不存在 | 立即报告，纳入审计闭环追踪 |
| **P1** | 锚点级断链 | 文件存在但 `[[文件#锚点]]` 中的锚点不存在 | 月度 Lint 报告中列出，按月追踪 |

目标值：系统文档内部文件级断链 = 0。

**新增断链判定规则**（与隐式闭环机制兼容）：
- Agent 在生成本月 Lint 报告时，读取上月 Worklog 中的断链清单
- 若本月发现的某 P0 文件级断链不在上月清单中，则标记为「新增」
- 对「新增」P0 断链在报告中加粗高亮提醒闭环
- 不强制要求 Agent 做复杂的跨月状态追溯，仅做月度清单级对比

**存量与新增分级处理**：
- 本次一次性全库扫描产出的存量文件级/锚点断链，人类可分批次逐月修复
- 仅新增产生的文件级断链执行当月零容忍闭环规则
- 锚点级断链（P1）不受零容忍约束，按月追踪即可

**`90_System/_备份*/`**：

**`40_Archive/`**：
- 豁免 P1 结构警告和 P2 格式提示（归档区不要求字段完整、格式规范、无孤儿页面）

1. **废弃 Agent 自动写入 Markdown 目录机制**：该方案存在误覆盖正文、光标跳跃问题，维护成本高于收益。
2. **统一使用 Obsidian 原生大纲（Outline）面板**浏览文档结构，右侧边栏实时渲染标题层级，零维护成本。
3. **可选优化**：长文档可手动在 YAML 中添加 `cssclasses: [directory]` 启用原生目录样式，不做强制要求。

- **超时检测**：扫描以下目录，检测超时未处理的文件，输出提醒清单：
  - `00_Inbox/` 临时文件（非 `_raw/` 子目录）：创建超过 24 小时 → 提醒清理或归档
  - `00_Inbox/_raw/` 素材：无标记超过 7 天 → ⚠️ 提醒处理

    - 创建 > 14 天 → 对话中主动提醒，建议「审核通过/需要修改/不适用」

  - 闲置超过 60 天未被任何笔记引用 → 提醒清理

- **入站提醒频率**：
  - 每次对话开始时：仅在 `_raw/` 中有文件超过 3 天未处理时提醒
  - 用户主动询问"Inbox 状态"或发送「查看Inbox待处理清单」时 → 即时响应
  - 每日晚间简报时：列出未处理清单
  - 每周 Lint 扫描时：超过 7 天未处理的升级为 ⚠️ 标记

- **报告输出**：输出到 `90_System/Worklogs/` 当日日志中，并向人类汇报核心发现。

## 七、Audit 反馈处理规则

- **信号识别**：扫描笔记 YAML 中的 `audit` 字段（格式为 `"high: 描述"` 或 `"low: 描述"`），或正文中的 `%% audit_high: ... %%` 注释。
- **处理优先级**：
  - `high`：立即中断当前低优任务，优先处理。
  - `low`：加入待办队列，在 Weekly Review 或批量处理时统一修正。
- **闭环归档**：
  - 若目标页面无 `human_edited: true` 标记：直接修正错误内容，移除 audit 标记。
  - 若目标页面有 `human_edited: true` 标记：**绝对禁止直接修改原文**。在 `90_System/audit/resolved/` 生成建议文档，并在原页面文末追加 `## ⚠️ Audit 建议待确认` 区块，等待人类手动采纳。

## 八、复盘种子提取

4. 每月 Lint 扫描时，检查上月复盘是否有未处理的种子

## 九、项目向导式检查清单

**启动向导**（人类说"开始新项目 X"或"创建项目 X"时触发）：

Hermes 按以下顺序引导：
1. "这个项目的截止日期或产出目标是什么？" → 写入项目主文档 YAML
2. "它属于工作项目还是个人项目？" → 确定存放路径（11_工作 或 12_个人）
3. "是否有可以参考的旧项目模板或笔记？" → 自动搜索 Archive 推荐 ≤ 3 条
4. 基于 `90_System/91_Templates/Project Template.md` 生成项目主文档骨架

**推断确认原则**：
Agent 从对话上下文中自动推断的字段（如截止日期、项目类型），
必须在生成项目主文档前以简短陈述句向人类确认。
未经确认的推断字段，一律留空待填。

**结项向导**（人类说"归档项目 X"时触发）：
1. 强制执行结项萃取检查点（扫描项目目录，生成 ≤ 5 项萃取建议）
   → 归档第一步强制触发结项萃取检查点，萃取规则复用复盘反哺判定逻辑
2. 检查项目内是否还有 `status: active` 的文件 → 列出建议处理
3. 检查是否有其他活跃笔记通过双链依赖此项目中的文件 → 列出建议更新
4. 执行归档
