# 行为追踪系统说明书

> **系统类型**：Bullet Journal + Habit Tracking 融合系统
> **数据源**：日记文件中的习惯打卡行
> **自动化程度**：90%（日记生成 + 数据聚合）

## 一、系统架构概览

### 核心理念

这是一个**单一数据源**的习惯追踪系统：
- ✅ 所有习惯数据都记录在每日日记中
- ✅ Habit Scorecard 只是 Dataview 自动聚合的看板
- ✅ 不需要手动维护独立的习惯表格

### 三个关键组件

| 组件 | 路径 | 作用 |
|:---|:---|:---|
| **Daily Template** | `90_System/91_Templates/Daily Template.md` | 日记模板（含习惯打卡区） |
| **日记文件** | `20_Areas/22_个人成长/Bullet Journal/Daily/YYYY-MM/` | 每日日记（数据源） |
| **Habit Scorecard** | `20_Areas/22_个人成长/Habit Tracking/Habit Scorecard.md` | Dataview 看板（展示层） |

## 二、日记生成流程

### 自动生成机制

**触发方式**：
1. 使用 Obsidian 的 **Periodic Notes** 插件
2. 点击左侧日历图标 → 选择日期 → 自动生成日记
3. 或使用快捷键 `Ctrl+P` → "Create daily note"

**生成过程**：
```
Periodic Notes 插件
    ↓
调用 Daily Template.md
    ↓
Templater 执行动态内容填充
    ↓
生成 YYYY-MM-DD.md 文件
    ↓
自动移动到正确目录（YYYY-MM/子目录）
```

### 日记文件结构

**文件名**：`YYYY-MM-DD.md`（如 `2026-07-11.md`）

**存放路径**：
```
20_Areas/22_个人成长/Bullet Journal/Daily/
    ├── 2026-06/              # 按月份归档
    │   ├── 2026-06-01.md
    │   ├── 2026-06-02.md
    │   └── ...

    │   ├── 2026-07-01.md
    │   ├── 2026-07-10.md
```

## 三、日记内容结构（PDCA 模式）

### P - 今日计划（Plan）

**内容**：
- 🎯 今日优先任务（最多 3 件）
- 📅 事件 / 日程
- 📋 任务清单（待办）

**使用方式**：
```markdown
## 🎯 今日优先任务（最多3件）
- [ ] 任务1
- [ ] 任务2
- [ ] 任务3

## 📅 事件 / 日程
- ! 上午 10:00 会议
- ! 下午 3:00 健身

## 📋 任务清单（待办）
- [ ] 长期任务
- [ ] 临时任务
```

### D - 执行记录（Do）

**内容**：
- ⚡ 今日闪念捕获
- 📝 快速笔记
- D 区域随手记录

**闪念捕获格式**：
```markdown
- [ ] 时间 来源/关键词 ｜ 触动点 ｜ 待处理动作
```

**示例**：
```markdown
- [ ] 14:00 读《原子习惯》｜ 身份认同改变行为 ｜ 提炼为原子笔记
- [ ] 16:00 操盘手骑士讨论｜ 用户画像与价值主张不匹配 ｜ 记录到项目笔记
```

## 四、习惯打卡区

### 打卡位置

位于日记底部的「习惯打卡」区域：

```markdown
## ✅ 习惯打卡（Day 13/14 冻结期）
- [x] ☀️ 晨间：靠墙天使 2min
- [x] 🌤️ 午饭后：快步走 15min
- [x] 🌙 23:30 手机离卧室
```

### 冻结期机制

**规则**：
- 系统采用 14 天冻结期机制
- 标记 `Day N/14` 表示当前第 N 天
- 14 天期满后，习惯进入稳定期

**冻结期意义**：
- 前 14 天是习惯形成的关键期
- 允许中断但不允许连续中断超过 2 天
- 14 天后自动解除冻结期标记

### 习惯打卡区 vs `[habit::]` 格式

**共存规则**：
日记模板中**同时存在**两种格式：

```markdown
## ✅ 习惯打卡（Day 13/14 冻结期）
- [x] ☀️ 晨间：靠墙天使 2min
- [x] 🌤️ 午饭后：快步走 15min
- [x] 🌙 23:30 手机离卧室

## 周报种子（选填）
[本周复盘时我想记住的一件事]
```

以及顶部的旧格式（模板中保留但实际使用较少）：

```markdown
## 习惯打卡
- [ ] [habit:: 读书] -
- [ ] [habit:: 运动] -
- [ ] [habit:: 冥想] -
```

**理解**：
- `[habit::]` 格式是 Dataview 可查询的标准化格式
- 带表情符号的格式是更人性化的呈现方式（带具体动作描述）
- 两条路线可以并存，核心是保持每日书写习惯

```dataview
  any(map(filter(file.tasks, (t) => contains(t.text, "habit:: 运动") AND t.completed), (t) => "✅")) AS "运动",

WHERE file.day >= date(2026-07-01) AND file.day <= date(2026-07-31)
SORT file.day ASC
```

### 工作原理

1. Dataview 查询所有日记文件
2. 在每个日记文件中搜索 `[habit::]` 格式的任务行
3. 检查该任务是否已完成（`- [x]`）
4. 聚合为本月的习惯打卡完成情况看板

### 注意事项

**⚠️ 当前看板查询的是 `[habit:: 读书]` / `[habit:: 运动]` / `[habit:: 冥想]` 格式**

但是实际日记中写入的是：

```markdown
- [x] ☀️ 晨间：靠墙天使 2min
- [x] 🌤️ 午饭后：快步走 15min
- [x] 🌙 23:30 手机离卧室
```

**这意味着**：当前看板的 Dataview 查询结果与实际习惯数据**不匹配**。

**历史说明**：模板中保留了 `[habit::]` 格式的习惯打卡区，但实际使用中已经演变为带表情符号的详细格式。这是系统升级中已知的待修复问题。

## 六、完整的日常流程

### 每日流程

```
打开日记 → 填写今日计划 → 任务执行 → 晚间反思 → 习惯打卡 → 睡前三口气
```

**详细步骤**：

1. **早上打开日记**
   - 使用 Periodic Notes 插件生成（或打开已有）
   - 自动迁移未完成的闪念和任务
   - 查看 🎯 今日优先任务区

2. **白天工作**
   - 在 ⚡ 今日闪念捕获区记录灵感
   - 在 📝 快速笔记区记录观察
   - 勾选已完成的任务

3. **晚上反思**
   - 填写 A – 🌙 晚间反思
   - 勾选 ✅ 习惯打卡（所有习惯）
   - 填写 🌙 睡前三口气

### 每周流程

```
周复盘 → 检查习惯趋势 → 调整下周计划
```

**周复盘模板**在 Weekly Template 中，会调用本周日记数据。

### 每月流程

```
月复盘 → 查看 Habit Scorecard 本月概览 → 调整习惯列表
```

**Habit Scorecard** 自动显示本月所有习惯打卡完成情况。

## 七、BuJo 符号系统

| 符号 | Markdown 写法 | 含义 |
|:---|:---|:---|
| • | `- [ ]` | 任务（未完成） |
| ✔ | `- [x]` | 任务完成 |
| > | `>` 或 `- [ ] >` | 迁移到未来/其他日期 |
| < | `- [ ] <` | 计划中（日程待定） |
| 👁 | `- !` | 事件（用感叹号或表情） |
| 📝 | `- Note` | 普通笔记 |
| * | `*` 重点 / C 检查 | 优先标记或检查确认项 |

## 八、常见问题

### Q1：日记文件存在哪里？

```
20_Areas/22_个人成长/Bullet Journal/Daily/
    ├── 2026-06/          ← 按月份子目录
    ├── 2026-07/
    └── BuJo Daily MOC.md ← 日记索引
```

### Q2：习惯打卡到底写在哪里？

**答案**：日记底部的 ✅ 习惯打卡区。

**格式**：
```markdown
## ✅ 习惯打卡（Day N/14 冻结期）
- [x] ☀️ 晨间：动作描述
- [x] 🌤️ 午饭后：动作描述  
- [x] 🌙 夜间：动作描述
```

### Q3：Habit Scorecard 看板为什么不显示数据？

**可能原因**：
- 看板查询的是 `[habit::]` 格式，但实际打卡用的是带表情符号的格式
- 需要手动更新看板的 Dataview 查询语句

### Q4：习惯冻结期是什么？

14 天习惯形成期，标记 `Day N/14`。前 14 天是关键期，允许中断但不允许连续中断超过 2 天。14 天后自动解除标记。

### Q5：闪念捕获写在哪里？

⚡ **今日闪念捕获** 区域。格式：
```
- [ ] 时间 来源/关键词 ｜ 触动点 ｜ 待处理动作
```
超 14 天未动的闪念会自动删除。
