# 14_Hermes Ingest 编译与原子笔记生产规范

> **版本**：v2.6.0
> **最后更新**：2026-07-11
> **来源**：`hermes-ingest-sop.md`（`vault-management` Skill 参考文件），吸收 `11_食谱编写标准 v1.0`、`13_Language Chunk 炼金术士 v1.0`
> **核心策略**：AI 产物与人类笔记通过 YAML 元数据分级控制，实现"融合但不混淆"。

---

## 核心信条（最高原则）

> **一条原子笔记，是你与自己未来的一次对话邀请。它不是答案，而是思想接口。**

Ingest 编译的目标不是"整理信息"，而是生产能够持续对话的思考节点。此信条是所有规则的宪法。

---

## 工作哲学

- **书写即思考**：笔记不是思考的产物，而是思考的载体本身。Ingest 通过编译来帮助用户生产想法，而非记录已有想法。
- **对话优于存储**：每条笔记的价值不取决于它记住了什么，而取决于它能引发什么对话。
- **张力优于闭合**：宁可保留模糊的边界和未解决的矛盾，也不制造虚假的清晰和过早的闭合。

## 新增 YAML 字段（v1.4）

| 字段 | 用途 | 适用 |
|:-----|:------|:-----|
| `ai_generated: true` | 标记 AI 编译产物 | 原子笔记/摘要 |
| `human_edited: true` | 人类编辑保护锁，AI 禁止覆盖正文 | 原子笔记（若 YAML 中无此字段，视为 `false`） |
| `last_ai_edit: YYYY-MM-DD` | 最近 AI 增量修改日期 | 被更新的原子笔记 |
| `ai_edit_summary: "..."` | AI 修改内容简述 | 被更新的原子笔记 |
| `audit: "high: ..."` | 反馈信号 | 全库 |

## Ingest 编译

1. 只处理 `_raw/` 中文件，或人类明确指定的路径
2. 生成摘要 → `33_Summaries/`
3. 提取概念 → 查 `31_Atomic_Notes/` 是否已有：
   - `human_edited: true` → 仅文末追加 `## 🤖 Hermes 补充`
   - 无标记 → 增量更新正文，记录 `last_ai_edit`
   - 不存在 → 新建，执行首次写入协议
4. 更新 MOC 链接，从 Archive 推荐 ≤3 篇历史笔记

### 🎯 提炼质量标准（吸收自 `atomic-note-extraction` Skill）

**四条铁律**（任何输出必须同时满足）：

| 铁律 | 要求 | Ingest 执行要点 |
|:---|:---|:---|
| **原子独立** | 一条笔记只承载一个不可再拆的思想单元 | 若需用"和"、"此外"、"另外"连接 → 拆分为多条笔记 |
| **问题/关系驱动** | 每条笔记必须能回答一个问题，或明确自己在知识网络中的角色 | 回应已有观点 / 界定新概念 / 提出开放疑问 |
| **对话导向** | 笔记内容必须是一个可被未来唤醒的对话接口 | 主张、疑问、反例、悖论，拒绝空洞口号 |
| **链接有理** | 任何强对话链接必须用一句话注明理由 | 链接格式：`链接至 [[笔记X]] \| 理由：提供了机制解释` |

**正文五种万能结构**（优先选择）：

| 类型 | 句式模板 | 适用场景 |
|:---|:---|:---|
| **主张/规律** | X现象的本质是Y。前提是Z。 | 提出明确的判断或规律 |
| **机制/因果** | 之所以A，是因为B导致了C。关键环节是D。 | 解释因果链条 |
| **疑问/猜想** | 为什么会出现X？一个可能的解释是Y，但这无法解释Z部分。待验证。 | 提出尚无法解答的问题 |
| **反例/边界** | 普遍认为A适用于B，但在情况C下，A会失效，因为D。 | 限定观点的适用范围 |
| **现象/隐喻** | X感觉像Y，虽然它们在逻辑上无关。这暗示了一种可能的关系是Z。 | 容纳前逻辑的思想 |

**链接类型区分**：

- **强对话链接**：必须注理由（包含动词）
  - 格式：`链接至 [[笔记X]] | 理由：提供了机制解释`
  - 禁止空洞词汇："相关"、"类似"、"有意思"

- **弱索引链接**：允许留白，但必须标注 `#待补理由`
  - 用于直觉链接（"感觉有关联"的占位符）

**播种**（为涌现预留接口）：

在每篇原子笔记末尾，刻意留下开放问题：

```markdown
**播种**：
1. [浅层：如何落地应用？]
2. [中层：什么条件下失效？]
3. [深层：前提被推翻会怎样？]
```

```
素材进入 _raw/
    │
    ├─ 是否包含明确观点/概念？
    │   ├─ 否 → 仅生成 Summary，不提炼原子笔记
    │   │        （如纯新闻、事实陈述）
    │   │
    │   └─ 是 → 触点判定
    │            │
    │            ├─ 即时启发：直接回应当前思考问题？
    │            │   └─ 是 → 提炼
    │            │
    │            ├─ 潜在启发：具备跨界冲突、反常识、新机制？
    │            │   └─ 是 → 提炼
    │            │
    │            └─ 两者皆否 → 仅归档，不提炼
    │                         （标注：#待用户确认 是否需要提炼）
```

### 🔴 异常处理（if-then 三段式）

| 触发条件 | 一线修复 | 仍失败兜底 |
|:---|:---|:---|
| **素材极度模糊**（无明确观点）| 仅生成 Summary，不提炼原子笔记 | 标注 `#待澄清`，建议用户提供上下文 |
| **找不到强对话链接对象** | 使用虚拟对话对象："若存在关于X的笔记，本笔记将..." | 仅保留弱链接，标注 `#待补理由` |
| **素材包含多个独立观点** | 立即拆分为多条笔记，每条一个观点 | 标注 `#待拆分`，列出拆分清单 |
| **碰撞保护触发**（`human_edited: true`） | 仅文末追加 `## 🤖 Hermes 补充` | 在 `audit/resolved/` 生成建议文档 |
| **提炼后篇幅超过原文 50%** | 检查是否保留冗余案例，删除 | 标注 `#待精简`，展示可删除段落 |

### 🔴 AI 能力边界（必须严格遵守）

**1. 判断权边界**：
- AI 只负责执行"如何提炼"，**不代替用户决定"什么值得提炼"**
- 触点判定模糊时，必须追问用户确认

**2. 幻觉防护**：
- 建立链接时，只能基于知识库检索结果
- ❌ 禁止凭空编造不存在的笔记标题或链接对象

**3. 张力保护**：
- 面对高度混沌、悖论共生的文本时，宁可保留张力也不强行理顺
- 允许在笔记中标注"此处存在未解决的矛盾"

### ⚠️ Ingest 粒度原则（2026-06-28 首次实测沉淀）

- **宁可拆细不拆粗**：提取出的独立概念不要因为"看起来太窄"就跳过。姜枣茶、曲荷丸、五运六气等具体概念在各自领域有独立引用价值。
- **判断标准**：该概念是否有独立的定义和论述？是否可能被其他笔记独立引用？如果两者都是肯定则值得成页。
- **Worklog 中必须列出全部提取的概念**，标注哪些已建笔记、哪些未建及原因。人类审核后可要求补拆。
- **碰撞测试优先选已有笔记的文章**：投喂一篇你已做过笔记的文章入 `_raw/`，一次测试验证两条核心链路：新建路径（AI 能否正确创建 Summary + Atomic Note + Callout）和碰撞路径（提取的概念与你已有 `human_edited: true` 笔记重合时，是否触发"仅追加补充"保护）。

### B. 语言组块类素材处理规范

> **来源**：`13_Language Chunk 炼金术士 v1.0`
> **触发条件**：素材包含外语表达、语境、用法说明
> **边界**：若素材是"观点 + 论据 + 思想单元" → 使用原子笔记提炼；若素材是"外语表达 + 语境 + 用法" → 使用语言组块提炼

**词典引用规范**（AI 联网查证，强制执行）：

| 内容 | 来源 | 执行方式 |
|:---|:---|:---|
| **音标** | **Cambridge Dictionary** | AI 联网查询 |
| **核心释义** | **Collins Dictionary** | AI 联网查询 |

**兜底机制**：
- 若 AI 无法访问上述网址，必须显式声明"网络不可用，以下音标/释义基于训练数据，标注 `#待验证`"

**禁止行为**：
- ❌ 使用其他词典的音标体系
- ❌ 混用多部词典的释义
- ❌ 使用机器翻译生成释义或音标

**YAML 元数据字段**（语言组块专用）：

| 字段 | 合法值 | 说明 | 必填 |
|:---|:---|:---|:---:|
| `target_lang` | `en`/`ja`/`fr`/... | 目标语言 ISO 码 | ✅ |
| `source_lang` | `zh`/`en`/... | 母语/中介语 ISO 码 | ✅ |
| `chunk_type` | `word`/`polyword`/`collocation`/`fixed`/`semi_fixed` | Lewis 组块分类 | ✅ |
| `cefr_level` | `A1`–`C2` | 组块难度等级 | ◻ |
| `register` | `formal`/`neutral`/`informal`/`slang` | 语域 | ◻ |
| `frequency` | `high`/`mid`/`low` | 语料库频率 | ◻ |

**四条铁律**（语言组块判定标尺）：

| 铁律 | 要求 |
|:---|:---|
| **原子独立** | 只承载一个不可再拆的语义-语用单元 |
| **语境驱动** | 必须绑定一个明确的语用场景（认知事件优先） |
| **网络可嵌** | 必须在语义网络中找到至少一个强对话对象（近义/反义/搭配/语域对位等） |
| **可间隔重复** | 必须具备卡片生成潜力 |

**间隔重复卡片类型**（五种）：

| 卡片类型 | 正面 | 背面 | 适用条件 |
|:---|:---|:---|:---|
| **释义卡** | 英文组块 | 中文核心释义 + 1个例句 | 初次习得 |
| **例句完形卡** | 挖空例句 | 完整例句 + 释义 | 强化语境 |
| **近义辨析卡** | 语境 + 候选组块 | 最恰当组块 + 理由 | 近义网络 |
| **搭配卡** | 中文情境 | 英文搭配 | 产出训练 |
| **反向输出卡** | 中文情境 | 英文组块 + 例句 | 主动产出 |

**提炼产出路径**：
```
语言组块笔记 → 31_Atomic_Notes/语言/[type]/组块名.md
```

**FrontMatter 示例**：

## 🔴 数据安全红线

### 归档移动铁律（2026-07-11 数据丢失事故教训）

- ❌ **禁止清空目标目录**：绝不允许使用 `rm -rf`、`rm -f`、`find -delete` 等命令删除目标目录文件
- ✅ **只移动指定文件**：直接 `mv` 或 `cp` 指定文件到目标目录，bash 会自动覆盖同名文件
- ✅ **保留目标目录原有文件**：目标目录的其他文件必须保持不动

### 命名规范

- ✅ 文件名只保留**纯概念名**，出处下沉到 YAML `source` 字段
- ❌ 禁止在文件名中使用出处后缀（如`概念名（那多）.md`）
- 消歧后缀仅在同名冲突时使用（优先级：书名 > 作者 > 领域）

### 流程中断与恢复

**中断时**：
Hermes 在当月 Worklog 中记录进度快照，包含：当前步骤、已完成项、待处理项。
快照统一前缀 `【流程快照】`，便于检索。

**恢复时**：
人类发送「继续上次的 [流程名]」→ Hermes 读取最新快照，从断点继续。

**快捷查询**：
可发送指令「列出本月全部流程快照」快速筛选当月所有 `【流程快照】` 记录。

**快照生命周期**：
- 30 天未恢复的快照：月度 Lint 中提示「有 N 条过期快照待清理」，人类确认后清理
- Agent **不自主删除** Worklog 内容
- 重要快照可手动在行末添加 `#lock-snapshot` 标记（精确匹配此拼写，拼写错误不识别锁定），不受清理限制
