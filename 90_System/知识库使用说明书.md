## 一、这是什么知识库？

这是一个 **PARA × Zettelkasten × Bullet Journal × AH（反向层级）** 四体系融合的个人知识管理系统。

**核心理念**：
- 知识库不是仓库，而是**思想接口**
- 每一条笔记都是**与自己未来的一次对话邀请**
- 书写即思考，AI 辅助但不替代

```

│   └── ...
│
├── 20_Areas/              # 领域（长期责任）
│   ├── 22_个人成长/       # 健身、习惯、学习
│   ├── 23_健康与医疗/     # 医疗记录
│   ├── 24_关系/           # 人际关系
│   └── ...
│
├── 30_Resources/          # 资源（可复用知识）
│   ├── 31_Atomic_Notes/   # 原子笔记（概念卡片）
│   ├── 32_参考资料/       # 外部素材
│   └── 33_Summaries/      # AI 编译产物
│
```

**核心原则**：
- **项目**：有明确截止日期的任务（如：操盘手骑士项目）
- **领域**：长期持续的责任（如：健康、关系、个人成长）
- **资源**：跨项目可复用的知识（如：概念笔记、方法论）
- **归档**：已完成或不活跃的内容

## 三、日常使用流程

### 每天早上

1. **打开日记**：`20_Areas/22_个人成长/Habit Tracking/Daily/` 中当天的日记
2. **查看习惯打卡区**：使用 `- [ ] [habit:: 习惯名]` 格式勾选
3. **记录今日待办**：在 BuJo 区域填写

### 工作过程中

1. **闪念捕捉**：随时在 `00_Inbox/` 创建笔记
2. **项目工作**：在 `10_Projects/对应项目/` 下记录进展
3. **知识提炼**：发现可复用的概念时，提炼为原子笔记存入 `31_Atomic_Notes/`

### 每周五/月末

1. **周复盘**：使用 Weekly Template
2. **月复盘**：使用 Monthly Template
3. **季度复盘**：使用 Quarterly Template

### 项目结项时

1. 告诉 Agent：「归档项目 XXX」
2. 系统自动扫描项目内容，提出萃取建议
3. 逐项决策哪些提炼为原子笔记
4. 自动归档到 `40_Archive/`

## 四、笔记规范（核心铁律）

### YAML 头部（必填字段）

```yaml
---
title: 笔记标题
date: 2026-07-11
status: active        # draft / active / mature / deprecated / archived
tags:
  - 标签1
  - 标签2
related:
  - "[[相关笔记A]]"
  - "[[相关笔记B]]"
---
```

### 命名规范

- **文件名**：最简 + 一眼看懂 + 永不再改
- **原子笔记**：纯概念名，不带出处（如 `认知负荷理论.md`）
- **项目文件**：项目名 + 文件类型（如 `操盘手骑士-项目规划.md`）

### 标签系统

**9 个核心标签**：
- `#MOC` - 索引页
- `#project` - 项目
- `#area` - 领域
- `#resource` - 资源
- `#note` - 笔记
- `#concept` - 概念
- `#method` - 方法论
- `#person` - 人物
- `#tool` - 工具

**16 个细分标签**：`#想法`、`#待办`、`#复盘`、`#习惯`、`#健身`、`#饮食`、`#学习`、`#阅读`、`#写作`、`#编程`、`#设计`、`#投资`、`#创业`、`#管理`、`#沟通`、`#决策`

## 五、特殊笔记类型

### 原子笔记（Atomic Notes）

**位置**：`30_Resources/31_Atomic_Notes/`

**特点**：
- 一条笔记只讲一个概念
- 独立可理解，脱离上下文仍有价值
- 通过 `related` 字段连接其他笔记

**示例**：
```markdown
---
title: 认知负荷理论
date: 2026-07-11
status: active
tags:
  - concept
  - 学习
related:
  - "[[工作记忆]]"
  - "[[学习科学]]"
---

# 认知负荷理论

认知负荷理论指出，工作记忆容量有限（约 4-7 个组块），过高的认知负荷会阻碍学习。

## 核心观点

- 内在认知负荷：任务本身的复杂度
- 外在认知负荷：呈现方式不当导致的额外负担
- 相关认知负荷：用于构建图式的认知努力

## 实践应用

- 分段学习：降低内在负荷
- 清晰呈现：减少外在负荷
- 提供示例：促进相关负荷
```

### MOC（Map of Content）

**位置**：各目录下的 `MOC.md` 或 `文件夹名 MOC.md`

**作用**：作为该目录的索引页，汇总该目录下所有笔记

**示例**：`20_Areas/MOC.md` 汇总所有领域

### 语言组块笔记（Language Chunk）

**位置**：`30_Resources/31_Atomic_Notes/语言/实践/`

**特点**：
- 提炼语言表达（单词、短语、句型）
- 用于间隔重复学习
- 有专门的炼金术士 Skill 处理

## 九、常见问题

### Q1：文件应该放在哪个目录？

**判断流程**：
1. 有明确截止日期？→ `10_Projects/`
2. 是长期责任？→ `20_Areas/`
3. 是可复用的知识？→ `30_Resources/`
4. 是临时想法？→ `00_Inbox/`
5. 已完成？→ `40_Archive/`

### Q2：如何命名文件？

**原则**：最简 + 一眼看懂 + 永不再改

**示例**：
- ✅ `认知负荷理论.md`
- ✅ `操盘手骑士-项目规划.md`
- ❌ `2026-07-11-关于认知负荷理论的一些思考-v2.md`

### Q3：标签怎么打？

**原则**：
- 从 9 个核心标签中选择 1-2 个
- 从 16 个细分标签中选择 0-N 个
- 标签不是分类，是属性标记

**示例**：
```yaml
tags:
  - concept      # 核心标签
  - 学习         # 细分标签
  - 认知科学     # 细分标签
```

### Q4：related 字段怎么填？

**原则**：
- 填写与本笔记直接相关的其他笔记
- 使用 `[[]]` 双链格式
- 数组格式，每条一个字符串

**示例**：
```yaml
related:
  - "[[认知负荷理论]]"
  - "[[工作记忆]]"
```

### Q5：如何修复断链？

1. 使用 Agent 命令：「修复所有断链」
2. Agent 会列出断链清单，逐个确认后修复
3. 或手动查找：使用 Obsidian 的「未链接提及」功能
