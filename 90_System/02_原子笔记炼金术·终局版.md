## 核心信条（最高原则）

> **一条原子笔记，是你与自己未来的一次对话邀请。它不是答案，而是思想接口。**

此信条是所有规则的宪法。凡违背此信条的操作，一律禁止。凡服务此信条的操作，即使打破常规，亦被允许。

## 🔴 与其他 Skill 的边界（重要）

### ❌ 原子笔记炼金术 ≠ 语言组块提炼

**本 Skill（原子笔记炼金术）** 用于：
- ✅ 提炼**思想单元**（概念、观点、模型、方法论）
- ✅ 构建**知识网络**（Zettelkasten）
- ✅ 处理**知识管理**场景（Inbox 归档、外部素材知识化）

**Language Chunk 炼金术士** 用于：
- ✅ 提炼**语言组块**（单词、短语、句型）
- ✅ 构建**间隔重复卡片**（Anki/SuperMemo）
- ✅ 处理**语言学习**场景（英语/日语/法语学习）

**区分标准：**
- 若素材是"外语表达 + 语境 + 用法" → 使用 **Language Chunk 炼金术士**
- 若素材是"观点 + 论据 + 思想单元" → 使用 **原子笔记炼金术**

## 工作哲学

- **书写即思考**：笔记不是思考的产物，而是思考的载体本身。通过书写来生产想法，而非记录已有想法。
- **对话优于存储**：每条笔记的价值不取决于它记住了什么，而取决于它能引发什么对话。
- **张力优于闭合**：宁可保留模糊的边界和未解决的矛盾，也不制造虚假的清晰和过早的闭合。

### 场景触发

用户批量导入外部素材到 `00_Inbox/外部导入/` 或 `00_Inbox/_raw/`，需要：
1. 格式转换（如 txt → md）

5. 归档

### 📥 Ingest 编译机制（Hermes 系统层）

> **来源**：`90_System/HERMES.md` v2.2 - Hermes Ingest/Lint/Audit SOP

Hermes Agent 具有系统级的 Ingest 编译管线，可自动处理 `00_Inbox/_raw/` 中的素材：

**Ingest 核心流程**：
1. 只处理 `_raw/` 中文件，或人类明确指定的路径
2. 生成摘要 → `33_Summaries/`（`ai_generated: true`）
3. 提取概念 → 查 `31_Atomic_Notes/` 是否已有：
   - `human_edited: true` → 仅文末追加 `## 🤖 Hermes 补充`
   - 无标记 → 增量更新正文，记录 `last_ai_edit`
   - 不存在 → 新建，执行首次写入协议
4. 更新 MOC 链接，从 Archive 推荐 ≤3 篇历史笔记

**首次写入协议**：
新建 AI 页面时：`ai_generated: true` + `status: draft` + 顶部 Callout：
```markdown
> [!note] 🤖 Hermes 自动生成 · 待人类审核
> 如需保留并防止 AI 后续覆盖，请在 YAML 中添加 `human_edited: true`。
```

**碰撞保护机制**：
- `human_edited: true` → 人类编辑保护锁，AI 禁止覆盖正文，仅追加补充
- 无标记 → AI 可增量更新正文
- 这是实现"AI 产物与人类笔记融合但不混淆"的关键

**新增 YAML 字段（Ingest 专用）**：

| 字段 | 用途 | 适用 |
|:-----|:------|:-----|
| `ai_generated: true` | 标记 AI 编译产物 | 原子笔记/摘要 |
| `human_edited: true` | 人类编辑保护锁，AI 禁止覆盖正文 | 原子笔记（存量默认 true） |
| `last_ai_edit: YYYY-MM-DD` | 最近 AI 增量修改日期 | 被更新的原子笔记 |
| `ai_edit_summary: "..."` | AI 修改内容简述 | 被更新的原子笔记 |
| `audit: "high: ..."` | 反馈信号 | 全库 |

**⚠️ Ingest 粒度原则（2026-06-28 首次实测沉淀）**：
- **宁可拆细不拆粗**：提取出的独立概念不要因为"看起来太窄"就跳过。姜枣茶、曲荷丸、五运六气等具体概念在各自领域有独立引用价值。
- **判断标准**：该概念是否有独立的定义和论述？是否可能被其他笔记独立引用？如果两者都是肯定则值得成页。
- **Worklog 中必须列出全部提取的概念**，标注哪些已建笔记、哪些未建及原因。人类审核后可要求补拆。
- **碰撞测试优先选已有笔记的文章**：投喂一篇你已做过笔记的文章入 _raw/，一次测试验证两条核心链路：新建路径（AI 能否正确创建 Summary + Atomic Note + Callout）和碰撞路径（提取的概念与你已有 human_edited: true 笔记重合时，是否触发"仅追加补充"保护）。

**🎯 视频素材 Ingest 专属路径（2026-06-29 新增）**：

视频素材不走 T_Video_Source 模板（已归档），改走以下流水线：
1. 外部工具转录（Get 笔记等）→ 在 `00_Inbox/_raw/` 新建文件
2. **Templater 插入 `_Raw_Video_Metadata` 模板片段**（`90_System/91_Templates/_Raw_Video_Metadata.md`）
3. 粘贴转录正文 → Hermes Ingest 编译为 Summary + Atomic Notes
4. 同一条 Raw 可产出多张笔记：Summary 1篇 + 概念/实践 N 篇
5. **Ingest 后检查 Archive 中的相关笔记**（如亲密关系类→`40_Archive/关系/`），在 Summary 末尾以 `## 📚 可能相关的历史笔记` 列出 ≤3 篇推荐

**📋 Ingest 产出示例（2026-06-29 纸片人恋爱 × 冲突管理）**：

### 标准工作流

#### 步骤1：格式转换

**场景**：用户导入非 Markdown 文件（txt、docx、pdf 等）

**⚠️ 大文件处理原则**（>300KB）：

- ❌ **禁止使用 `write_file`**：大文件写入易超时，导致失败
- ✅ **必须使用 `terminal` + Python 脚本**：直接处理文件，避免工具调用限制

**大文件转换模式**（详见 `references/txt-to-md-conversion-patterns.md`）：

```bash
# 在 terminal 中执行 Python 脚本
cat > /tmp/convert.py << 'PYEOF'
#!/usr/bin/env python3
# -*- coding: utf-8 -*-

input_file = r"D:\路径\源文件.txt"
output_file = r"D:\路径\输出文件.md"

with open(input_file, 'r', encoding='utf-8') as f:
    lines = f.readlines()

output_lines = []
for line in lines:
    line = line.rstrip('\n\r')
    
    # 去除行号（格式：数字|内容）
    if '|' in line:
        parts = line.split('|', 1)
        if len(parts) == 2 and parts[0].strip().isdigit():
            line = parts[1]
    
    # 处理章节标题
    if line.startswith('第') and ('章' in line or '讲' in line):
        if '章' in line:
            output_lines.append(f"\n## {line}\n\n")
        elif '讲' in line:
            output_lines.append(f"\n### {line}\n\n")
    elif line.startswith('先导'):
        output_lines.append(f"\n## {line}\n\n")
    elif not line.strip():
        output_lines.append("\n")
    else:
        output_lines.append(f"{line}\n")

with open(output_file, 'w', encoding='utf-8') as f:
    f.writelines(output_lines)

print(f"转换完成！总行数: {len(lines)}")
PYEOF

python /tmp/convert.py
```

**小文件转换**（<300KB）：

```python
# 简单转换（使用 hermes_tools）
from hermes_tools import write_file

content = read_file(path="原文件.txt")['content']
write_file(path="目标文件.md", content=content)
```

**注意**：Obsidian 无法直接渲染 txt 文件，必须转换

#### 步骤2：内容分析与去重

**场景**：导入的文件可能包含重复内容

**分析方法**：
1. **识别文件类型**：
   - 目录类（课程索引、大纲）
   - 单课内容类（每节课的独立笔记）
   - 合集类（所有课程的完整笔记）
   - 总结类（方法提炼、要点浓缩）
   - 逐字稿类（原始口语记录）

2. **判断重复关系**：
   - 单课内容 vs. 合集：通常合集已包含所有单课内容，单课文件可删除
   - 合集 vs. 总结：互补关系，都保留（合集=素材，总结=提炼）
   - 逐字稿 vs. 合集：互补关系，都保留（逐字稿=原始素材，合集=结构化）

3. **去重决策**：
   - ✅ 保留：合集、总结、逐字稿（不同用途，互补）
   - ❌ 删除：单课文件（如果合集已包含）

**用户偏好固化**：
- 提出整理方案，说明去重逻辑
- 等待用户确认后再执行（"先提出方案吧，不要执行"原则）
- 展示：文件分类、重复关系、保留/删除建议

## 一、原子笔记的判定标尺（四条铁律）

任何输出必须同时满足以下四个条件，缺一不可：

### 铁律1：原子独立

一条笔记只承载一个不可再拆的思想单元。

**判断标准：**
- 若需用"和"、"此外"、"另外"连接 → 说明需要拆分
- 原子 ≠ 简短 — 追求"最小自足"，而非"越短越好"
- 允许为支撑单一议题保留关键情境、微小案例、限定条件

**示例：**
```
❌ 错误：WeChat Obsync 支持多设备同步和自动Markdown转换和图片归档
✓ 正确：拆分为三条笔记
  1. WeChat Obsync 的多设备同步机制
  2. 公众号文章的自动Markdown转换
  3. 图片归档与微信7天过期问题
```

---

### 铁律2：问题/关系驱动

每条笔记必须能回答一个问题，或明确自己在知识网络中的角色。

**角色类型：**
- 回应某个已有观点（反驳、支撑、修正）
- 界定一个新概念
- 提出一个悖论或开放疑问

**判断标准：**
无法说清自己"在干什么"的笔记，不进入永久层（31_Atomic_Notes）。

---

### 铁律3：对话导向

笔记内容必须是一个可被未来自己唤醒的对话接口。

**有效类型：**
- 主张（带限定条件）
- 疑问（可验证）
- 反例（边界清晰）
- 悖论（保持张力）
- 功能重定义

**拒绝：**
- 含糊的感悟
- 空洞的总结
- 无确定知识增量的口号

---

### 铁律4：链接有理

任何强对话链接，必须用一句话注明链接理由。

**强链接格式：**
```markdown
链接至 [[笔记X]] | 理由：证伪了Y的主张
```

**禁止空洞词汇：**
- ❌ "相关"、"类似"、"有意思"
- ✓ 必须包含动词或关系名词："证伪了"、"提供了机制解释"、"是……的特例"

**弱链接允许留白：**
- 标注 `#待补理由`
- 允许直觉链接（"感觉有关联"的占位符）

## 二、标准工作流（强制执行）

> **⚠️ 完整工作流顺序：提炼原子笔记 → 校准原文 FrontMatter → 归档原文**

### 阶段0：前置确认（用户偏好）

**触发条件**：用户提供任何输入材料（文本、片段、灵感）。

**必问确认**：
1. **触点判定**：这篇文章与用户当前思考问题相关吗？
2. **输出范围**：提炼原子笔记 + 校准原文 FrontMatter + 归档原文（默认执行）

**用户偏好固化**：
- 原文必须校准 FrontMatter 后归档（不得直接删除）
- 原子笔记的 FrontMatter 必须符合 obsidian-yaml-spec 规范（15种标签字典）
- Skill 更新后，同步更新系统文档 `90_System/12_原子笔记炼金术·终局版.md`

---

### 阶段1：闪念捕捉（零批判、保心流）

**动作：**
- 快速记录原文中引发注意的核心信号
- 保留原始措辞和情绪词
- 不得评判、筛选、提炼

**特别保留：**
- 反常识表述
- 隐喻
- 悖论
- 情绪化但直觉重要的词汇

**输出格式：**
```
闪念捕捉：
- [信号1：原文措辞]
- [信号2：情绪词]
- [信号3：反常识点]
```

**禁止行为：**
- ❌ 说"这段话的核心是……"
- ❌ 过滤"不够清晰"的内容
- ❌ 合并多个信号

---

### 阶段2：原子炼金（严苛筛选）

#### 步骤1：触点判定

对每一条闪念信号，执行双标尺判定：

| 标尺 | 问题 | 通过标准 |
|:-----|:-----|:---------|
| **即时启发** | 是否直接回应当前思考的问题？ | 是 → 进入下一步 |
| **潜在启发** | 是否具备跨界冲突、反常识、新机制等长期对话潜力？ | 是 → 进入下一步 |

**判定结果：**
- 通过任一标尺 → 进入提炼
- 两条都不通过 → **勇敢丢弃**

**AI 边界：**
- 若用户未提供当前思考问题 → 默认以"潜在启发"判定
- **必须追问用户确认**，不可自行最终裁决

---

#### 步骤2：提纯

**方法：** 一句话概括法反复切割

**判断标准：**
如果草稿需要用"和"、"另外"、"此外"连接两个独立观点 → 立刻拆分

**输出：** 一个不可再分的单一思想单元

---

#### 步骤3：转译（用自己的话重写）

**绝对禁止：**
- ❌ 复制粘贴原文
- ❌ 同义词替换式伪改写

**操作方式：**
合上原材，以"写给十年后的自己解释这个概念"的口吻，用自己的语言重新表述。

**五种万能结构：**

| 类型 | 句式模板 | 适用场景 | 示例 |
|:-----|:---------|:---------|:-----|
| **主张/规律** | X现象的本质是Y。前提是Z。 | 提出明确的判断或规律 | "阳春面的'少即是多'本质在于把功夫藏在看不见的汤底细节里。前提是食材配比精准。" |
| **机制/因果** | 之所以A，是因为B导致了C。关键环节是D。 | 解释因果链条 | "之所以阳春面能喝出海鲜锅的鲜，是因为湖虾籽富含天然呈味核苷酸，触发了鲜味倍增效应。" |
| **疑问/猜想** | 为什么会出现X？一个可能的解释是Y，但这无法解释Z部分。待验证。 | 提出尚无法解答的问题 | "为什么温油取香比大火爆香更适合阳春面？一个可能的解释是芳香分子的脂溶性需要低温慢浸，但这无法解释为何其他菜系多用高温爆香。" |
| **反例/边界** | 普遍认为A适用于B，但在情况C下，A会失效，因为D。 | 限定观点的适用范围 | "普遍认为WeChat Obsync适合所有微信同步场景，但在需要实时同步的场景下，它会因几秒延迟而失效。" |
| **现象/隐喻/悖论** | X感觉像Y，虽然它们在逻辑上无关。这暗示了一种可能的关系是Z。 | 容纳前逻辑的、模糊但直觉重要的思想 | "阳春面的克制感觉像日本侘寂美学，虽然它们在逻辑上无关。这暗示了'少即是多'可能是一种跨文化的烹饪哲学。" |

**关键限定：**
每条笔记必须主动声明该思想的适用边界，防止未来的自己误用为普遍真理。

**篇幅原则：**
以"写完一个完整想法的最小必要篇幅"为准。追求晶体般的锐度，而非膨胀的解释。

---

#### 步骤4：建立对话链接

**强对话链接（强制执行）：**

```markdown
**强对话链接**：
- 链接至 [[笔记X]] | 理由：提供了机制解释
- 被 [[笔记Y]] 链接 | 理由：作为反例证伪了Y
```

**弱索引链接（允许留白）：**

```markdown
**弱索引链接**：
- 待链接：[概念/领域/案例] #待补理由
- 待链接：WeChat Obsync 与 Messager 的适用场景对比 #待结构化
```

**冷启动方案：**
若卡片盒中尚无足够笔记 → 构建虚拟对话对象：

```markdown
若存在关于"微信多设备同步方案对比"的笔记，本笔记将补充WeChat Obsync的实现机制。
```

---

#### 步骤5：播种（为涌现预留接口）

在笔记末尾，刻意留下开放问题。**播种应多样化：**

| 层次 | 问题类型 | 示例 |
|:-----|:---------|:-----|
| **浅层** | 如何落地应用？ | WeChat Obsync 如何与 Hermes 的 multi-platform-content-sync skill 并存？ |
| **中层** | 什么条件下失效？ | 温油取香在什么火候下会失败？ |
| **深层** | 前提被推翻会怎样？ | 如果湖虾籽的呈味核苷酸被证明有副作用，整个阳春面鲜味机制会怎样重组？ |
| **跨界** | 与哪个无关领域同构？ | 阳春面的"藏功夫"与极简主义设计有何同构？ |
| **颠覆** | 什么证据可能证伪？ | 有什么证据可能证明"温油取香"不是最佳方案？ |

**质量检查：**
若连续三条笔记的播种都呈现同质化倾向 → 必须主动切换播种类型。

## 四、原文归档流程（提炼后必执行）

> **⚠️ 原文不得直接删除，必须校准 FrontMatter 后归档**

### 步骤1：校准原文 FrontMatter

**必填字段模板：**
```yaml
---
title: [原标题]
date: [原创建日期，非发表日期]
status: archived
tags: [15种字典之一]
source: [来源名称，非URL]
author: [原作者]
aliases: []
related: []
---
```

**校准规则：**
1. ✅ `tags` 必须从 15 种标签字典选择（见上文第五章）
2. ✅ `status` 必须为 `archived`
3. ✅ `source` 填来源名称（如 `微信公众号「XX」`），非 URL
4. ❌ 删除非标准字段（如 `description`、`version`、`clippings` 标签）
5. ❌ 删除自创标签（如 `营销`、`品牌`）
6. ⚠️ **标题中的引号处理**：YAML 标题中禁止英文双引号嵌套，使用中文引号「」替代
   - ❌ 错误：`title: "教育的"成功""`（语法错误）
   - ✅ 正确：`title: "教育的「成功」"`（使用中文引号）
6. ⚠️ **标题中的引号处理**：YAML 标题中禁止英文双引号嵌套，使用中文引号「」替代
   - ❌ 错误：`title: "教育的"成功""`（语法错误）
   - ✅ 正确：`title: "教育的「成功」"`（使用中文引号）

### 步骤2：归档路径

**原子笔记归档规则：**
```
原子笔记 → 31_Atomic_Notes/[标签领域]/[type]/笔记名.md
```

**归档规则：**
- 第一层：标签领域（15 种字典之一，如 `技术`、`知识管理`）
- 第二层：type 类型（`概念`、`模型`、`实践`、`批判`）
- 文件名：笔记标题

**示例：**
- `tags: [技术], type: practice` → `31_Atomic_Notes/技术/实践/笔记名.md`
- `tags: [知识管理], type: concept` → `31_Atomic_Notes/知识管理/概念/笔记名.md`

**原文归档规则：**
```
原文 → 40_Archive/[领域]/[原标题].md
```

**路径规则（⚠️ 重要）：**
- **使用现有的长名目录**：`40_Archive`（PARA 标准目录）
- **禁止创建短名目录**：`40_Archive`（会导致重复文件夹）
- **按领域分类归档**：国际政治/技术/生活/工作/个人成长/关系/...
- **文件名保持原标题**：不加日期前缀
- **⚠️ 目录冲突检查**：归档前检查目标领域是否已有子目录（如 `个人成长/知识管理/`），如果根目录下已有同名目录（如 `知识管理/`），统一使用根目录版本，避免创建重复目录结构导致文件分散

**领域层级逻辑（技术类特殊处理）：**

对于技术相关内容，遵循严格的层级逻辑：

```
技术（标签字典）
  └─ AI（子领域）
      └─ Agent（AI的应用形态）
          └─ Hermes Agent（具体实例）
```

**归档路径示例：**
- Hermes Agent 专属内容 → `40_Archive/技术/AI/Hermes Agent/`
- 其他 Agent（客服机器人） → `40_Archive/技术/AI/客服机器人/`
- 通用 AI 文章 → `40_Archive/技术/AI/`
- Obsidian 技巧 → `40_Archive/技术/Obsidian/`

**原子笔记路径示例：**
- Hermes Agent 实践笔记 → `31_Atomic_Notes/技术/实践/Hermes Agent/笔记名.md`
- AI 概念笔记 → `31_Atomic_Notes/技术/概念/笔记名.md`

**为什么这样分类：**
1. **语义一致性**：AI 是技术的子集，Agent 是 AI 的子集，具体实例是 Agent 的子集
2. **扩展友好**：未来可能有多个 Agent，都在 `AI/` 下不混淆
3. **浏览高效**：查看 `技术/AI/` 时能看到所有 AI 相关内容

**示例：**
- 国际政治类文章 → `40_Archive/国际政治/文章标题.md`
- 技术类文章 → `40_Archive/技术/文章标题.md`
- 关系类文章 → `40_Archive/关系/文章标题.md`
- Hermes Agent 文章 → `40_Archive/技术/AI/Hermes Agent/文章标题.md`

### 步骤3：删除营销冗余（⚠️ 关键原则）

**删除内容：**
- 图片链接（`![](https://...)`）
- 营销话术（"如果你也受够了..."、"赶紧收藏..."）
- 过度格式（多余的分隔线、表情符号堆砌）

**保留内容：**
- 核心观点
- 关键步骤/配置说明
- 机制解释
- 论据/依据
- 案例说明
- 原文完整内容（⚠️ 重要：不要过度精简，只删除营销冗余）

**⚠️ 关键原则：**
- ✅ **保留原文核心内容**：不要只保留精简总结，要保留原文的主要观点、论据、案例
- ❌ **禁止过度精简**：删除图片链接和营销话术，但不删除原文的实质性内容
- ✅ **归档文件大小**：应该接近原文大小（删除图片链接后），不应该只有原文的 10-20%
- ✅ **营销参考文章特殊处理**：如果文章用途是"营销手法参考"，必须保留完整原文内容（含营销话术），便于对比学习营销手法

**归档文件用途标注：**
在归档文件 FrontMatter 后添加用途说明：
```markdown
**用途**：[营销软文参考 + 方法论借鉴 | 知识萃取 | 技术参考]
**核心价值**：[一句话说明保留的价值]
```

## 五、原子笔记 FrontMatter 规范（obsidian-yaml-spec 整合）

> **⚠️ 每次输出原子笔记，FrontMatter 必须符合以下规范，无需二次校准**

### 必填字段模板

```yaml
---
title: [笔记标题]
date: YYYY-MM-DD
status: active
type: concept | model | practice | critique
tags: [15种字典之一]
source: [来源名称，非URL]
author: [原作者]
aliases: []
related:
  - "[[相关笔记]]"
---
```

### 标签字典（16 种，只能从中选择）

**核心标签（9 个）：**
- `个人成长` — 认知、学习、写作、传统文化
- `工作` — 职场、管理、创业、项目文件
- `生活` — 日常、烹饪、运动、健康、旅行
- `关系` — 人际、亲密关系、家庭、沟通
- `财务` — 投资、理财、记账、资产
- `技术` — 编程、架构、AI、工具、软件
- `心理学` — 细分标签（父领域：个人成长）
- `知识管理` — 细分标签（父领域：个人成长）
- `语言` — 语言习得、外语学习、语言学、翻译

**功能性标签（7 个）：**
- `国际政治` — 时政、国际关系、地缘
- `科学` — 物理、生物、化学、数学
- `系统文档` — 90_System/ 下所有文件
- `归档` — 40_Archive/ 下所有文件
- `素材` — 外部摘抄、灵感收集
- `日记` — 每日日记
- `习惯` — 习惯方法论专用

**标签规则：**
1. ❌ 禁止自创标签（如 `工具`、`微信`、`Obsidian`、`营销`）
2. ❌ 细分标签与父标签互斥（打 `心理学` 不打 `个人成长`）
3. ✅ 从上述 16 种中选择最接近的领域标签

### type 合法值（4 种）

| 值 | 适用场景 | 示例 |
|:---|:---------|:-----|
| `concept` | 概念定义、理论框架 | "第二大脑的本质" |
| `model` | 模型、方法论框架 | "PARA方法论" |
| `practice` | 实践方法、工具使用 | "WeChat Obsync 的核心机制" |
| `critique` | 批判性思考、反例 | "微信同步插件的选择边界" |

### status 合法值（5 种）

| 值 | 适用阶段 |
|:---|:---------|
| `draft` | 灵感碎片，概念尚未成型 |
| `active` | 概念清晰，仍在打磨中（新建笔记默认） |
| `mature` | 提炼完成，内容稳定 |
| `deprecated` | 内容已过时、被证伪 |
| `archived` | 已完结项目或内容 |

**❌ 非法值：** `standard`、`reference`、`final`

### source 字段规则

- ✅ 中文译本用中文全名：`微信公众号「obsidian指南」`
- ✅ 原创内容填：`原创`
- ❌ 禁止填 URL：`https://mp.weixin.qq.com/s/...`

### related 字段规则

- ✅ 使用双链 + 引号：`- "[[笔记名]]"`
- ❌ 禁止无引号：`- [[笔记名]]`

### 🔴 FrontMatter 校准检查清单（输出前必检）

每次输出原子笔记前，必须确认：

1. ✅ `tags` 是否从 15 种字典中选择？
2. ✅ `status` 是否为 `active`（新建笔记）？
3. ✅ `type` 是否填写？（`concept/model/practice/critique`）
4. ✅ `source` 是否为来源名称（非 URL）？

### 🔴 原文归档致命错误（必须避免）

**⚠️ 历史教训（2026-07-10）：**

在处理原子笔记提炼时，曾犯过以下致命错误，导致用户需要重新导入原文：

1. **❌ 过度精简原文**：只保留了精简总结，删除了原文的核心内容
   - 错误示例：原文 24000 字节 → 归档文件仅 2000 字节（仅保留摘要）
   - 正确做法：删除图片链接和营销话术，保留原文核心内容
   - 归档文件大小应接近原文大小（删除图片后），不应只有 10-20%

2. **❌ 混淆提炼与归档**：将提炼过程当作归档内容
   - 错误示例：归档文件只包含"已提炼的原子笔记清单"和"核心观点总结"
   - 正确做法：归档文件应保留原文完整内容（删除营销冗余），提炼的原子笔记单独存放

3. **❌ 创建重复目录结构**：在不同位置创建同名目录
   - 错误示例：同时存在 `40_Archive.../知识管理/` 和 `40_Archive.../个人成长/知识管理/`
   - 正确做法：归档前检查目录结构，统一使用根目录版本

**✅ 正确的归档原则：**
- 保留原文核心内容（观点、论据、案例、步骤）
- 只删除营销冗余（图片链接、营销话术、过度格式）
- 归档文件大小应接近原文（删除图片后）
- 归档 ≠ 精简总结，归档 = 保留原文（清理营销冗余）

- 扫描 `#待补理由` 的弱链接 → 深化或删除

- 两条笔记标题或核心思想高度重叠 → 建议合并
- 一条笔记被频繁引用但内容过长 → 建议拆分

## 五、避坑清单

### 绝对禁忌（触碰即废）

- ❌ 大段摘抄原文或同义词替换式伪改写
- ❌ 一条笔记塞多个独立观点
- ❌ 写无确定知识增量的感悟、口号、鸡汤
- ❌ 脱离网络仍不知所云的孤岛笔记
- ❌ 强行将模糊直觉塞入不匹配的模板
- ❌ 未经用户确认即代替用户判断"是否有启发"
- ❌ **写清单/计划文件到 `00_Inbox/` 目录**（Inbox 是外部导入临时存放地，不是工作清单区）
- ❌ **用文件替代 `todo` 工具**（任务清单用 `todo` 工具管理，不写文件）

### 工作流禁忌

| 用户问 | ❌ 错误做法 | ✅ 正确做法 |
|:-------|:------------|:------------|
| "该修改哪些文件" | 写清单文件到 Inbox | 口头列出清单 → 用户确认 → 直接执行 |
| "需要做什么" | 写计划文件到 Inbox | 使用 `todo` 工具创建任务列表 |

### 质量控制红线

| 优先级 | 内容类型 |
|:-------|:---------|
| **优先记录** | 因果、机制、边界、误区、方法、条件 |
| **谨慎记录** | 单纯的现象描述、无上下文的断言、无法追溯来源的二手转述 |
| **避免** | 过度结构化以致扼杀思想的混沌活力 |

### 哲学警戒线

- 不要追求"确定性"而牺牲开放性——好的笔记可以是完美的疑问
- 不要追求"整洁"而消除张力——思想网络的价值在于冲突与涌现
- 不要追求"全面"而稀释锐度——一条笔记只解决一个认知点

## 六、失败模式与fallback（if-then三段式）

> **⚠️ 当以下情况发生时，按三段式处理：触发条件 → 一线修复 → 仍失败兜底**

| 触发条件 | 一线修复 | 仍失败兜底 |
|:---------|:---------|:-----------|
| **用户输入极度模糊**（如"提炼这个"但材料无明确观点）| 追问："这篇文章的核心观点是什么？用一个句子回答我" | 标注 `#待澄清`，建议用户先完成闪念捕捉阶段 |
| **无法确定触点判定**（即时启发/潜在启发都模糊）| 提供选项让用户选择："这篇文章是解决你当前问题？还是只是有趣？" | 默认以"潜在启发"判定，标注 `#待用户确认` |
| **转译后仍像原文**（同义词替换式伪改写）| 合上原文，用"写给十年后的自己"的口吻重写 | 标注 `#待重写`，暂停进入下一步 |
| **找不到强对话链接对象**（卡片盒中无相关笔记）| 使用虚拟对话对象句式："若存在关于X的笔记，本笔记将..." | 仅保留弱链接，标注 `#待补理由` |
| **播种问题同质化**（连续3条都是"如何区分X与Y"）| 主动切换播种类型：从浅层→中层→深层→跨界→颠覆 | 提示用户"播种类型过于集中，建议多样化" |
| **用户拒绝确认触点判定**（说"不确定"或"你决定"）| 再次追问："这篇文章如果不提炼，一周后你还记得吗？" | **🔴 STOP**：暂停优化，等待用户提供当前思考问题 |
| **材料包含多个无关观点**（需用"和""此外"连接）| 立即拆分为多条笔记，每条一个观点 | 标注 `#待拆分`，列出拆分清单让用户确认 |
| **提炼后篇幅超过原文50%**（压缩率不足）| 检查是否保留冗余案例或过渡段落，删除 | 标注 `#待精简`，展示可删除段落清单 |
| **五种结构都不匹配**（内容介于多种类型之间）| 选择最接近的结构，标注 `#待结构化` | 允许自由文本，不强求模板匹配 |
| **用户提供的材料是新闻/资讯**（仅事实无观点）| 判断：是否需要提炼？→ 多数情况应归档到Archive | 建议用户："这篇文章适合归档而非提炼，确认继续？" |

### 🔴 关键检查点（CHECKPOINT）

以下情况必须**暂停并等待用户确认**：

1. **触点判定阶段** — 用户未提供当前思考问题，且潜在启发判定模糊时
2. **转译完成前** — 无法用自己的话重写，仍依赖原文措辞时
3. **建立链接前** — 无法找到强对话链接对象，需确认虚拟对话对象方案时
4. **播种阶段** — 连续3条笔记播种问题同质化时

**🛑 STOP 信号：宁可暂停等待用户输入，也不要继续制造低质量笔记。**

## 七、AI 能力边界（必须严格遵守）

### 1. 判断权边界

AI 只负责执行"如何提炼"，**不代替用户决定"什么值得提炼"**。

**触点判定阶段：**
- 必须追问用户确认
- 或提供选项让用户选择
- 不可自行最终裁决

### 2. 幻觉防护

建立链接时，**只能基于用户提供的现有笔记列表或知识库检索结果**。

**禁止：**
- ❌ 凭空编造不存在的笔记标题或链接对象

**允许：**
- ✓ 使用虚拟对话对象句式："若存在关于X的笔记，本笔记将……"

### 3. 张力保护

面对高度混沌、模糊、悖论共生的文本时，**宁可保留张力也不强行理顺**。

**允许：**
- 在笔记中标注"此处存在未解决的矛盾"
- 让它成为对话的持续源泉

## 八、实战范例

### 范例1：工具评测提炼（示例场景）

**原文：**《某工具的插件评测文章》（约5000字节，含营销话术、图片链接）

**闪念捕捉：**
```
- 该工具支持多设备指向一个本地库
- 完全免费，无条数限制
- 转发即收藏，免打扰
- 本地解析，不经第三方服务器
- 竞品A 免费10条/天限制
```

**触点判定：**
- 即时启发：是（用户正在考虑某工具同步方案）
- 潜在启发：是（工具评测对比框架可复用）

**提纯：**
某工具的核心优势在于"转发即收藏"的免打扰机制与本地隐私安全。

**类型：** 机制/因果

**转译：**
```markdown
之所以该工具能成为"闪念胶囊"式收集工具，是因为它通过小程序承接转发操作，实现了"长按转发 → 自动生成.md"的零摩擦收集流程。关键环节是本地Token认证机制，确保数据不经第三方服务器。
```

**强对话链接：**
```markdown
- 链接至 [[multi-platform-content-sync]] | 理由：补充了某生态的插件化方案
- 若存在关于"闪念胶囊类工具对比"的笔记，本笔记将提供该工具的机制解释
```

**播种：**
```markdown
1. 该工具的几秒同步延迟在什么场景下会成为致命缺陷？
2. 如果平台官方封禁小程序接口，整个方案会如何失效？
3. 它与其他Web Clipper的收集逻辑有何同构？
```

**压缩率：** 原文 5000 字节 → 原子笔记约 1200 字节（24%）

### 范例2：概念提炼（示例场景）

**原文：**《某概念的双向转化》（约3000字）

**闪念捕捉：**
```
- 概念A与概念B是同一股能量
- 有无形状决定是毁灭还是创造
- 创作是转化的桥梁
- 真正厉害的人都曾允许自己狠狠经历
```

**触点判定：**
- 潜在启发：是（反常识：概念A≠负面）

**提纯：**
创作是把概念A转化为概念B的动作，用的是同一股能量。

**类型：** 主张/规律

**转译：**
```markdown
概念A与概念B的本质是同一股能量，区别只在于有无给它形状。概念A是燃料（推动力），概念B是方向（要去哪里），创作是车（让你前行）。如果你不开车，燃料会烧掉你的油箱——概念A向内毁灭，向外创作。
```

**强对话链接：**
```markdown
- 链接至 [[外化思考]] | 理由：提供了能量转化的机制解释
- 链接至 [[概念A未被转化的三种症状]] | 理由：补充了未转化状态的诊断
```

**播种：**
```markdown
1. 如果概念A被完全消除，概念B是否还存在？
2. 这个模型是否适用于组织层面的"破坏性创新"？
3. 有什么证据可能证明概念A与概念B不是同一股能量？
```

**压缩率：** 原文 3000 字 → 原子笔记约 600 字（20%）
