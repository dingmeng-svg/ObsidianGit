## 一、核心铁律

### 1.1 文件操作安全

| 铁律 | 说明 |
|:---|:---|
| **write_file 前备份** | 文件已存在且内容将变更时，先 `cp` 备份 |
| **rename 后全库查引用** | 重命名后必须全库搜索旧名，批量更新引用 |
| **删文件前必请示** | 任何删除操作都先问再执行 |
| **归档时只移动指定文件** | 🔴 禁止清空目标目录（2026-07-11 数据丢失事故） |
| **创建后必验证可用性** | 检查 CSS 污染、双链引用、插件依赖 |

### 1.2 用户沟通风格

- **命令式、直接执行**：用户给任务后直接执行，不确认中间步骤
- **每阶段汇报结果**：执行完一批操作后清单式汇总
- **不要问"要xxx吗？"**：用户说什么就做什么
- **"播完通知我"模式**：批量任务做完通知即可，不更新进度
- **审计报告不夸大问题**：区分 P0（需立即修复）与 P1/P2（不紧急）

## 三、原子笔记命名合规 SOP

### 3.1 NAMING-01 合规标准

**合规格式**：纯概念名，无后缀

| 状态 | 示例 |
|:---|:---|
| ✅ 合规 | `LLM Wiki.md`、`杀意未被转化的三种症状.md` |
| ❌ 冗余副标题 | `LLM Wiki：AI 驱动的知识库构建方法论.md` |
| ❌ 括号出处 | `蔡格尼克效应（心理学）.md` |

### 3.2 执行流程

```
步骤1：全库搜索引用
  grep -r "旧文件名" --include="*.md" | grep -v "_备份"

步骤2：重命名文件
  mv "旧路径/旧文件名.md" "旧路径/新文件名.md"

步骤3：更新文件内容
  - YAML title 字段
  - 正文 # 标题

步骤4：批量更新引用（Python）
  for root, dirs, files in os.walk(BASE):
      dirs[:] = [d for d in dirs if "_备份" not in d]
      for f in files:
          if f.endswith(".md"):
              # 替换旧名 → 新名

步骤5：验证无残留
  grep -r "旧文件名" --include="*.md" | grep -v "_备份" || echo "✅ 无残留"
```

## 四、文件归档操作规范

### 前置检查：项目结项萃取

在执行项目归档前，必须先完成结项萃取检查点。Agent 扫描项目目录并生成萃取建议清单，人类逐项决策后方可继续归档。

### 系统文档废弃流程

系统文档的废弃须执行前置依赖校验。详见 [[HERMES#系统文档废弃前置校验规则]]。

### 4.1 核心铁律

|| 铁律 | 说明 |
|:---|:---|
| **只移动指定文件** | 禁止清空目标目录 |
| **移动前检查目标** | 确认哪些需要保留 |
| **移动后验证完整性** | 原有 + 新增文件都存在 |

### 4.2 归档流程

```
步骤1：检查目标目录内容
  ls "目标目录/"

步骤2：列出需移动的文件
  避免误删目标目录已有内容

步骤3：执行移动
  mv "源路径/文件.md" "目标路径/"

步骤4：验证
  ls "目标路径/" | wc -l  # 文件数
```

**项目向导快照复用**：项目启动/结项向导同步复用 Ingest 流程的 Worklog 快照机制。
中断时在当月 Worklog 中记录 `【流程快照】`，恢复时读取最新快照从断点继续。

## 五、断链修复 SOP

### 5.1 执行流程

```
步骤1：用 find 查实际路径
  find . -name "*关键词*" -type f

步骤2：列诊断表格
  | 原链接 | 实际文件 | 操作建议 |

步骤3：根据数量决定
  - 断链 > 3 条 → 给清单让用户手动修
  - 断链 ≤ 3 条且路径确定 → 直接 patch
```

## 九、系统文档编码规范

### 9.1 编码规则

| 规则 | 说明 |
|:---|:---|
| **从 01 开始连续分配** | 不预留空号 |
| **HERMES.md 不编码** | 保持原文件名不动 |

## 十一、外部方法论与本系统关系

### 11.1 处理原则

当发现原子笔记记录了外部方法论来源（如 Karpathy 的 LLM Wiki），但本系统做出了不同选择时：

| 原则 | 说明 |
|:---|:---|
| **保留来源笔记** | 方法论来源是重要参考，不删除 |
| **添加关系声明** | 在笔记末尾明确"来源 vs 本系统选择"的分野 |
| **命名合规检查** | 确保文件名符合 NAMING-01 |

### 11.2 声明模板

```markdown
## 与本系统设计哲学的关系

> [!important] 方法论来源与实现路径的分野
> 
> 本文记录了 XXX 方法论，是本系统的设计思想来源之一。
> 但本系统在实际实现中走出了不同的哲学路径：
> 
> | 维度 | XXX 方法论 | 本系统 |
> |:---|:---|:---|
> | ... | ... | ... |
```
