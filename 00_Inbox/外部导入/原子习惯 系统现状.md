## 建议方案：统一为 `[habit::]` 一套系统

### 1. 统一标记方式

日记中保持 `[habit::]` 格式，去掉 emoji 时段标记。所有追踪从 `[habit::]` 抓取。

### 2. 重新设计日记习惯打卡区

```markdown
## 习惯打卡

**身份锚点**：我是一个健康、精进、有爱的人。

| 习惯 | 今日 | 连续天数 |
|:---|:---:|:---:|
| [habit:: 读书] | ☐/☑ | 12 天 |
| [habit:: 运动] | ☐/☑ | 7 天 |
| [habit:: 冥想] | ☐/☑ | 3 天 |

**中断补救**：如果今天错过了，明天做 2 分钟版本即可。
```

### 3. 重新设计 Habit Scorecard 看板

查询条件统一改为 `[habit::]`，显示当月每日完成情况。

### 4. 建立执行/退出机制

| 阶段 | 状态 | 条件 |
|:---|:---|:---|
| **孵化中** | 设计池 | 在 Habit Design Reference 中，未上线 |
| **执行中** | active | 已上线，每日打卡追踪 |
| **稳定中** | mature | 连续 21 天不间断 → 进入"维护模式"（不再需要每日追踪） |
| **退出** | archived | 连续 7 天无打卡 + 无挽救意愿 → 确认放弃，归档 |

## 为什么这个方案能解决之前的问题

**之前混乱的根源**：我们试图用一套工具系统（`[habit::]` + Scorecard + 7个概念）去管理一堆零散的习惯（读书/运动/冥想/早起喝水/晚间复盘……），但没有一个统一的身份框架来锚定它们。所以你会困惑"到底怎么落地"——因为每个习惯的"为什么"都不一样。

**这个方案给出了答案：**

| 问题 | 之前 | 现在 |
|:---|:---|:---|
| 为什么是这三个？ | 随意选择，没有逻辑 | 守护→执行→校准，完整的日循环 |
| 身份在哪？ | 七零八落的原子笔记里 | 一句话宣言 + 三个身份子句 |
| 追踪查什么？ | `[habit::]` 不知道标记什么 | 三个习惯，每个对应一个 `[habit::]` 标记 |
| 什么时候退出？ | 没有规则 | 三个阶段：孵化→执行→稳定→退出 |
| 七个概念怎么落地？ | 散落的理论 | 环境设计→守护者（早晨环境改造）；执行意图→执行者（先投一票）；习惯堆叠→校准者（睡前仪式链） |

## 具体的落地建议

以你现在的身份框架，重新设计日记中的习惯打卡区：

```markdown
## 🎯 今日优先任务

- [ ] 🔴 MIT 1
- [ ] 🔴 MIT 2
- [ ] 🔴 MIT 3

## ✅ 身份习惯打卡

**此刻的清醒责任人**

- [x] [habit:: 守护者] 晨起10分钟：拉伸+静坐+喝水
- [ ] [habit:: 执行者] 上午先投一票：完成最重要那件事
- [x] [habit:: 校准者] 睡前5分钟：复盘+终局过滤+丢弃烦恼
```

这样 `[habit::]` 只有三个值，追踪系统完全统一。

**Habit Scorecard 看板的查询条件也只需匹配这三个值。Habit Design Reference 作为设计层保留，但只有在上线新习惯时才查阅。**
