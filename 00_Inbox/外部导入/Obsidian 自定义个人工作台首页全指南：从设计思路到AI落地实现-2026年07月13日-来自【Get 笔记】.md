# 🎯 定制首页的核心动因

原生Obsidian默认首页体验不佳，对于定位为个人知识库的工具来说，首页应当被打造成专属个人工作台，同时满足两大核心需求：一是视觉层面具备舒适美感，二是信息布局与密度完全匹配个人使用习惯。作者仅花费2小时就完成了这套高完成度的定制方案，最终实现了兼顾美观度与实用性的落地效果。

# 📋 最终首页效果全景拆解

这套定制首页整体遵循「该做的在上，该想的在下」的设计逻辑，上半区承载待办、素材与稿件的日常操作，下半区通过洞察镜帮助用户看清自身注意力分配情况，完整模块划分如下：
1.  **顶部视觉横幅**：搭配绿植风格生成背景图，设置「刷新洞察」「查看原文」「今日日记」快捷操作按钮，同时展示当前日期与笔记同步助手的存量统计数据。
2.  **操作区核心模块**

| 模块名称 | 功能定位 | 细分内容 |
|---|---|---|
| 今日行动 | 确认当日核心推进事项 | 分为「重点跟进」「工作待办」「OPC待办」「生活待办」4个彩色分类卡片，覆盖不同维度的待办事项 |
| 今日输入 | 自动抓取最新同步素材与资讯 | 展示笔记同步助手最新8篇素材，同时罗列X资讯、GitHub、YouTube三大栏目最新一期内容 |
| 今日输出 | 管理正在撰写的稿件与固定工具链 | 包含「Obsidian用法稿」「个人技能沉淀」两个输出入口卡片 |
| 常用补充 | 高频功能快捷入口 | 提供技术文章、原始剪藏、洞察归档三个快速跳转按钮 |

3.  **洞察镜核心模块**
    基于「七维注意力分析」框架搭建，7个维度的具体作用如下：

| 维度 | 核心价值 | 关键数据示例 |
|---|---|---|
| 总览 | 展示近期笔记整体新增/活跃情况 | 近7天vault（Obsidian本地知识库）新增/活跃笔记共53篇，其中笔记同步助手25篇、工作/OPC目录28篇 |
| 潜意识偏好 | 挖掘用户未察觉的高频关注方向 | 识别出3个核心关注赛道：AI工程化落地、个人知识库方法论、内部AI提效工具 |
| 被遗忘的内容 | 提醒用户查看长期未回访的存量笔记 | 自动筛选出5篇同步后几乎未操作的历史笔记 |
| 认知盲区 | 定位「输入多、输出沉淀少」的错位领域 | 例如Harness/OpenSpec相关文章已大量输入，但对应SOP实践笔记尚未完成输出 |
| 热点趋势 | 统计近期素材库的主题升温/降温情况 | 近期升温主题包含Spec-Driven工程、Agent Skills工作流、知识库+AI洞察，纯模型相关内容热度下降 |
| 注意力热力图 | 可视化展示近一年笔记修改活跃度 | 近7天注意力分布占比：AI编程/工程化约45%、知识库/Obsidian约25%、工作交付约15%，呈现输入侧集中、输出侧偏冷的特征 |
| 行动建议 | 基于全维度分析生成可落地的当日执行指引 | 给出3条具体建议：优先完成1件可关单的工作、整理1篇当日素材沉淀为个人笔记、推进当前正在撰写的稿件收尾 |

# 🛠️ 设计思路与架构逻辑

整套首页被划分为**操作台**和**洞察镜**两大板块：
- 操作台完全服务于日常操作流，按照「待办-输入-输出」的逻辑排布，完全贴合费曼学习法的实践路径，让知识库从单纯的收藏夹升级为可落地的内容生产枢纽。
- 洞察镜采用半自动化机制：一半数据由Dataview插件自动汇总生成，另一半由AI执行刷新指令，将七维分析结果写入`AI洞察/当日.md`文件后嵌入首页展示。

# ⚙️ 技术实现全流程

这套方案全程以AI为核心生产力，主要使用Cursor作为开发工具，背景图由Codex+GPT Image 2.0生成，整体采用「结构-样式-数据三者分离」的分层架构：
1.  **三层核心文件**

| 文件类型 | 路径与作用                                                               |
| ---- | ------------------------------------------------------------------- |
| 首页骨架 | `首页.md`，承载整个页面的HTML卡片与区块嵌入逻辑，仅负责内容展示                                |
| 样式文件 | `.obsidian/snippets/knowledge-home.css`，统一控制配色、圆角、毛玻璃效果、淡绿底色等所有视觉细节 |
| 洞察数据 | `AI洞察/当日.md`，独立存储七维分析的完整内容，首页仅做区块引用，避免内容重复                          |
  2.  **必备插件清单**

| 插件名称             | 核心作用                |
| ---------------- | ------------------- |
| Homepage         | 实现打开Obsidian时自动加载首页 |
| Dataview         | 动态抓取最新同步素材、自动生成统计数据 |
| Heatmap Calendar | 渲染近一年笔记活跃度的注意力日历热力图 |
3.  **分步落地流程**
    1.  先敲定信息架构，明确上半区操作台、下半区洞察镜的整体布局
    2.  生成基础Markdown骨架，完成卡片、分区标题、洞察嵌入的基础排版
    3.  定制CSS样式，按照「绿植工作台」的调性统一视觉风格
    4.  接入动态数据，通过Dataview自动拉取最新素材与资讯，关联热力图组件
    5.  多轮微调迭代，通过截图反馈逐步优化配色、字号、边框、间距等细节，作者累计迭代3个版本最终达到理想效果。
4.  **AI协作落地路径**
    全程通过自然语言向AI传递需求：先让AI评估当前知识库的已有配置与缺失能力，分阶段推进功能落地，将插件安装、Dataview查询规则配置、样式调整等重复性工作全部交由AI完成，大幅降低自定义门槛。

# 03 为什么要这么设计

首页既然是个人工作台，总得摆盆盆景吧，这样至少显得不寒碜。

我喜欢绿植，于是让 Codex 直接生成了张背景图，现在看确实挺好看，尤其炎炎夏日，显得格外清凉。

整个首页分成 **操作台** 和 **洞察镜** 两块。操作台管日常操作；洞察镜一半靠 Dataview 自动汇总数据，一半靠 AI
分析：跑一条刷新指令，把七维洞察写进 `AI洞察/当日.md`，首页再嵌进来。

对 **操作台**，**今日行动** 自然成为重点，关注的是今天的 **待办** 。然后是 **今日输入** 和
**今日输出**。在我看来，这是典型的费曼学习法，也是知识库之所以叫知识库，而不是收藏夹的要义所在。

于是，很自然的，我把这三块，设计成了 **待办 + 输入 + 输出** 三块卡片。

对 **洞察镜** ，具体要包含哪些内容，其实一开始也没想法，说来也巧，正好今天看到篇 OpenWiki 的文章，里面有提到
**七维注意力分析**，看后感觉有些道理，于是将这种思维，运用了过来。

七个维度分别是：

* **总览**
  你保存了什么，整体画面是什么样的
* **潜意识偏好**
  你可能没意识到，但你反复在关注的方向
* **被遗忘的内容**
  你存了但从没回看的东西，可能值得重新看看
* **认知盲区**
  基于你的阅读模式，推测你可能忽略了哪些领域
* **热点趋势**
  你最近关注的主题是在升温还是降温
* **注意力热力图**
  你的注意力在哪些领域最密集
* **行动建议**
  基于以上分析，给你具体的下一步建议

跑完第一版洞察后我看了下，有些角度确实是自己没意识到的，挺有意思。

## 总体实现框架

先说清楚这首页是用什么搭起来的，其实就三层东西：

* **一个首页文件**
  `首页.md`，整张页面的骨架，HTML 卡片 + 区块嵌入都写在这里。
* **一份样式文件**
  `.obsidian/snippets/knowledge-home.css`，所有颜值都靠它，配色、圆角、毛玻璃、洞察镜的淡绿底，全在这一个 CSS 片段里。
* **一份洞察数据**
  `AI洞察/当日.md`，七维分析的正文单独放这，首页只是把它一段段「引」过来，不重复写。
再配上三个插件：**Homepage**（开 Obsidian 自动打开首页）、**Dataview**（动态抓取最新素材、生成热力图）、**Heatmap Calendar**（画那张注意力日历）。

一句话：**结构、样式、数据三者分开**，首页只管展示，数据各回各家。

画成图，大概是这么个关系：

看图就清楚了：首页只是个「展示台」，样式负责好看，数据负责内容，AI 负责扫描 vault 后写入洞察。

## 总体实现流程

整个过程不是一次到位，而是按这个顺序推进的：

1. **先定信息架构**
   想清楚首页到底要展示什么——上面是操作台（待办 / 输入 / 输出），下面是洞察镜（七维分析）。
2. **AI 写骨架**
   把卡片、分区标题、洞察嵌入的 Markdown 骨架敲出来，先不管好不好看。
3. **写样式**
   让 AI 按「绿植工作台」的调性写 CSS，统一配色、卡片、间距。
4. **接数据**
   用 Dataview 把「笔记同步助手」最新几篇、各栏目资讯自动抓上来，热力图也接上。
5. **反复微调**
   截图 → 圈问题 → 改 → 再截图，配色、字号、边框、间距一点点抠。
前面四步搭出能用的版本，真正花时间的是第五步。

整个过程大概迭代了三个版本，才到现在这个样子。
