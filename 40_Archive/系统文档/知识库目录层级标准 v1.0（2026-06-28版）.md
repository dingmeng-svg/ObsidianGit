# 知识库目录层级标准 v1.0

> 本文档定义了 Obsidian 知识库的全量目录结构与层级规范。所有新建笔记必须按此标准归位。
> 架构基础：PARA（项目/领域/资源/归档）× Bullet Journal × Zettelkasten × Atomic Habits 四体系融合。

---

## 一、顶层命名规范

| 编号 | 目录名 | 体系对应 | 说明 |
|:----:|:-------|:---------|:-----|
| `00` | `Inbox` | PARA 收件箱 | 未处理/待归档的临时笔记 |
| `10` | `Projects_Things I'm actively working on` | PARA 项目 | 有明确目标和截止日期的活跃项目 |
| `20` | `Areas_My roles and responsibilities` | PARA 领域 | 长期责任领域，无截止日期 |
| `30` | `Resources_Things I'm interested in` | PARA 资源 | 感兴趣的主题、素材、原子笔记 |
| `40` | `Archive_Completed or inactive things` | PARA 归档 | 已完成/不活跃的内容冷库 |
| `50` | `Bullet_Journal` | Bullet Journal | 日志系统（每日/每周/每月/未来） |
| `60` | `Habits` | Atomic Habits | 习惯追踪与周期复盘 |
| `90` | `System` | 系统维护 | 知识库自身的配置、模板、规范 |

> **规则**：顶层目录编号为两位数字，后跟英文描述，加下划线分隔，首字母大写。
> 英文标识在前、中文补充在后（如 `10_Projects`）。

## 二、10_Projects：项目层

> 项目的判定标准：有明确目标 + 有截止日期（或预期完成时间）。

```
10_Projects/
├── 11_工作/
│   ├── _项目模板/                     # 项目模板（非实际项目）
│   └── 01_操盘手骑士/                  # 实际项目：编号+项目名
│       ├── 01_规划/                   # 项目规划文档
│       ├── 02_执行/                   # 执行记录、会议纪要
│       │   ├── 会议纪要/
│       │   └── 完整台本/
│       ├── 03_资料/                   # 项目参考资料
│       │   └── 工具箱/
│       ├── 股市数据播报/
│       │   └── 【月】月/
│       │       └── 每日复盘直播稿/
│       └── 短视频脚本/
│           └── 散户痛点系列/
└── 12_个人/
    ├── _项目模板/
    ├── 01_知→行→进化/               # 个人认知成长项目
    │   └── (各书的子目录)
    ├── 02_ 100 Word Tales｜百词百篇/
    ├── Active_Listening_Project/
    └── Self_Worth_Diary/
```

### 规则

| 规则 | 说明 |
|:-----|:------|
| **编号前缀** | 项目编号：两位数字（如 `01_操盘手骑士`） |
| **目录间隔** | 项目文件夹内：数字+下划线+中文名 |
| **模板目录** | `_项目模板/` 以下划线开头，排在最前 |
| **URL双链** | 不混入文件级双链，项目间引用用 `project:` 字段 |
| **YAML** | 每个项目文件应含 `project: "项目名"` 字段 |

## 三、20_Areas：领域层

> 领域的判定标准：长期责任，无法 "完成"，只有持续维护。

```
20_Areas/
├── 21_工作/                   # 职业/事业
│   └── 短视频/
├── 22_个人成长/               # 认知、学习、哲学
│   ├── 传统文化/
│   ├── 写作素材/
│   ├── 心理学/
│   └── 知识管理/
├── 23_生活与健康/             # 日常、烹饪、运动、健康
│   ├── 健康/
│   ├── 食物/
│   └── 游泳/
├── 24_关系/                   # 社交、亲密关系、家庭
│   ├── 伴侣/
│   │   └── 媚媚/              # ♥ 个人专属子目录
│   │       ├── 💌情書/
│   │       └── 事務/
│   ├── 家人/
│   ├── 朋友/
│   ├── 社群/
│   ├── 拓展/
│   └── 同事/
├── 25_财务与资产/
│   └── 丁萌/
└── 26_技术/
```

### 规则

| 规则 | 说明 |
|:-----|:------|
| **编号前缀** | 两位数字 + 下划线（如 `21_工作`） |
| **子目录平铺** | 领域子目录只到二级（如 `24_关系/伴侣/`），不超三级 |
| **个人专属** | 涉及具体人名的子目录直接用人名（如 `伴侣/媚媚/`） |
| **emoji前缀** | 个人情感类子目录允许 emoji 前缀（如 `💌情書/`、`事務/`） |

## 四、30_Resources：资源层

> 资源的判定标准：感兴趣但不紧急的主题素材，以及核心原子笔记库。

```
30_Resources/
├── 31_Atomic_Notes/           # Zettelkasten 原子笔记库
│   ├── Concepts/              # 概念笔记
│   ├── Models/                # 模型笔记
│   ├── Critiques/             # 批判/思辨笔记
│   ├── Practices/             # 实践/操作笔记
│   └── People/                # 人物相关笔记
├── 32_MOCs/                   # Map of Content 结构索引
├── AI/
├── Notion/
├── Obsidian/
├── Reading/
├── Video/
├── 财富与财务/
├── 参考信息/
├── 个人爱好/
├── 个人成长/
├── 心理学与行为科学/
├── 兴趣话题/
├── 研究课题/
├── 英语/
├── 营销与文案/
└── 智库-思维模型/
```

### 规则

| 规则 | 说明 |
|:-----|:------|
| **原子笔记** | `31_Atomic_Notes/` 下设 Concepts/Models/Critiques/Practices/People 五个标准子目录，**不新增** |
| **MOC** | `32_MOCs/` 仅存放 MOC 笔记，必须含 `type: moc` 字段 |
| **领域子目录** | 兴趣类目录直接平铺，**不超过二级**，用中文名 |
| **文件名** | 原子笔记不加前缀，后缀仅同名消歧义时加 `（出处）` |

### 细分触发条件

当某个领域文件夹文件数超过 **8 个**时，考虑新增子目录：

| 父目录 | 子目录规划 | 触发条件 |
|:-------|:-----------|:---------|
| `生活/` | `健康/` `食物/` `运动/` `旅行/` | ✅ ≥8 文件时启用 |
| `个人成长/` | `认知与心智/` `知识管理/` `人生哲学/` | ✅ ≥8 文件时启用 |
| `心理学/` | 暂不分 | < 8 文件保持平铺 |
| `营销与品牌/` | 暂不分 | < 8 文件保持平铺 |

### 归档文件状态

所有归档文件的 `status` 字段统一为 `archived`。

## 六、50_Bullet Journal：日志系统

```
50_Bullet_Journal/
├── Collections/       # 子弹笔记收藏集
├── Daily Logs/        # 每日记录
├── Future Logs/       # 未来日志（6个月以上规划）
├── Monthly Logs/      # 每月记录
└── Weekly Logs/       # 每周记录
```

### 规则

| 规则 | 说明 |
|:-----|:------|
| **命名** | `YYYY-MM-DD-描述.md`（Daily），`YYYY-MM.md`（Monthly） |
| **状态** | 使用 `active`（进行中）或 `finished`（未来归档前暂用） |
| **存档** | 季度末从 Daily/Weekly 移至 Archive |

## 九、目录命名规范总表

| 层级 | 格式 | 示例 | 规则 |
|:-----|:------|:-----|:-----|
| 顶层 | `NN_英文描述` | `10_Projects` | 两位数字 + 下划线 + 英文 |
| 项目/领域编号 | `NN_中文名` | `11_工作` | 两位数字 + 下划线 + 中文 |
| 项目内 | `NN_中文名` | `01_操盘手骑士` | 两位数字 + 下划线 + 中文 |
| 通用子目录 | `中文名/` | `健康/` | 纯中文，不加编号 |
| 系统目录 | `NN_英文/` | `91_Templates/` | 两位数字 + 英文，以 9 开头 |
| 模板目录 | `_描述/` | `_项目模板/` | 以下划线开头，排最前 |
| 情感目录 | emoji + 中文 | `💌情書/` | 仅限个人情感类文件夹 |
| MOC | `32_MOCs/` | 固定路径 | 不允许其他目录存放 MOC |
| 原子笔记 | `31_Atomic_Notes/子类/` | 固定路径 + 5 个子类 | 不新增子类目录 |

## 十、目录归属判断树

当新建一篇笔记时，按以下顺序判断它应该放在哪里：

```
1️⃣ 是否有截止日期/产出目标？
    ├── 是 + 活跃 → 10_Projects/ 对应项目编号下
    └── 否 → 跳 2️⃣

2️⃣ 是否属于长期责任领域？
    ├── 是 → 20_Areas/ 对应领域下
    └── 否 → 跳 3️⃣

3️⃣ 是原子笔记（概念/模型/批判/实践）？
    ├── 是 → 30_Resources/31_Atomic_Notes/ 对应子类下
    └── 否 → 跳 4️⃣

4️⃣ 是某个主题的索引/MOC？
    ├── 是 → 30_Resources/32_MOCs/
    └── 否 → 跳 5️⃣

5️⃣ 是感兴趣但不紧急的主题素材？
    ├── 是 → 30_Resources/ 对应领域子目录下
    └── 否 → 跳 6️⃣

6️⃣ 内容已完成/项目已结项？
    ├── 是 → 40_Archive/ 对应领域子目录下
    └── 否 → 00_Inbox/ 待分类
```

> 一篇文件的位置由其生命周期状态决定，标签由其内容决定。
