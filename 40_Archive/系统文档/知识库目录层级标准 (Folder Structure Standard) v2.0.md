# 知识库目录层级标准 v2.0

> [!warning] 已归档
> 本文档已被 [[01_知识库统一规范总纲|总纲 v3.0]] 替代。
> 完整编码、命名、标签、目录、元数据规范以总纲为准。
> 本文仅作历史追溯留存。

> 本文档定义了 Obsidian 知识库的全量目录结构与层级规范。所有新建笔记必须按此标准归位。
> 架构基础：PARA（项目/领域/资源/归档）× Zettelkasten × Atomic Habits 四体系融合。

---

## 一、顶层命名规范

|  编号  | 目录名                                       | 体系对应         | 说明                          |
| :--: | :---------------------------------------- | :----------- | :-------------------------- |
| `00` | `Inbox`                                   | PARA 收件箱     | 未处理/待归档的临时笔记，含 `_raw/` 原料入口 |
| `10` | `Projects_Things I'm actively working on` | PARA 项目      | 有明确目标和截止日期的活跃项目             |
| `20` | `Areas_My roles and responsibilities`     | PARA 领域      | 长期责任领域，无截止日期                |
| `30` | `Resources_Things I'm interested in`      | PARA 资源 + ZK | 原子笔记、MOC、参考资料               |
| `40` | `Archive_Completed or inactive things`    | PARA 归档      | 已完成/不活跃的内容冷库                |
| `90` | `System`                                  | 系统维护         | 知识库自身的配置、模板、规范、架构文档         |

> **规则**：顶层目录编号为两位数字，后跟英文描述，加下划线分隔，首字母大写。
> 英文标识在前、中文补充在后（如 `10_Projects`）。
> **移除**：原 `50_Bullet_Journal` 和 `60_Habits` 已分别归入 `20_Areas/22_个人成长/` 和 `31_Atomic_Notes/` + `91_Templates/`。

## 二、10_Projects：项目层

> 项目的判定标准：有明确目标 + 有截止日期（或预期完成时间）。

```
10_Projects/
├── 11_工作/
│   ├── _项目模板/                     # 项目模板（非实际项目）
│   └── 01_操盘手骑士/                  # 实际项目：编号+项目名
│       ├── 01_规划/                   # 项目规划文档
│       ├── 02_执行/                   # 执行记录、会议纪要
│       │   ├── 会议纪要/
│       │   └── 完整台本/
│       ├── 03_资料/                   # 项目参考资料
│       │   └── 工具箱/
│       ├── 股市数据播报/
│       │   └── 【月】月/
│       │       └── 每日复盘直播稿/
│       ├── 短视频脚本/
│       │   └── 散户痛点系列/
│       └── 系统文档/                   # 项目级 SOP
└── 12_个人/
    ├── _项目模板/
    ├── 01_知→行→进化/               # 个人认知成长项目
    │   ├── Atomic Habits/
    │   ├── BASB/
    │   ├── BUJO/                     # BUJO 知识（方法论笔记，V2_升级预案）
    │   └── Zettelkasten/
    ├── 02_ 100 Word Tales｜百词百篇/
    ├── Active_Listening_Project/
    └── Self_Worth_Diary/
```

### 规则

| 规则 | 说明 |
|:-----|:------|
| **编号前缀** | 项目编号：两位数字（如 `01_操盘手骑士`） |
| **目录间隔** | 项目文件夹内：数字+下划线+中文名 |
| **模板目录** | `_项目模板/` 以下划线开头，排在最前 |
| **YAML** | 每个项目文件应含 `project: "项目名"` 字段 |
| **股市数据播报** | `【月】月/` 格式，`【】` 内为月份数字 |

## 三、20_Areas：领域层

> 领域的判定标准：长期责任，无法"完成"，只有持续维护。

```
20_Areas/
├── 21_工作/                   # 职业/事业
│   └── 短视频/
├── 22_个人成长/               # 认知、学习、哲学
│   ├── Bullet Journal/        # ⭐ 子弹日记系统（每日日记 + 未来日志 + V2_升级预案）
│   ├── Atomic Habits/              # ⭐ 习惯记分卡（空白追踪表，14天后启动）
│   ├── 传统文化/
│   ├── 写作素材/
│   ├── 心理学/
│   └── 知识管理/
├── 23_生活与健康/             # 日常、烹饪、运动、健康
│   ├── 健康/
│   │   └── 体态/
│   ├── 食物/
│   │   ├── 中餐/
│   │   ├── 烘焙/
│   │   ├── 营养/
│   │   └── 食品风味/
│   └── 游泳/
├── 24_关系/                   # 社交、亲密关系、家庭
│   ├── 伴侣/
│   │   └── 媚媚/
│   │       ├── 💌情書/
│   │       └── 事務/
│   ├── 家人/
│   ├── 朋友/                  # 含 阿新（茉莉）张津

├── 25_财务与资产/
│   └── 丁萌/
│       └── 财务/
└── 26_技术/
```

### 规则

| 规则 | 说明 |
|:-----|:------|
| **编号前缀** | 两位数字 + 下划线（如 `21_工作`） |
| **子目录平铺** | 领域子目录只到二级（如 `24_关系/伴侣/`），不超三级 |
| **个人专属** | 涉及具体人名的子目录直接用人名（如 `伴侣/媚媚/`） |
| **emoji前缀** | 个人情感类子目录允许 emoji 前缀（如 `💌情書/`、`事務/`） |
| **Bullet Journal** | 作为持续维护的领域责任归入 `22_个人成长`，不是项目 |

### 规则

| 规则 | 说明 |
|:-----|:------|
| **原子笔记** | `31_Atomic_Notes/{领域}/{类型}/` 三层结构。领域=8个，类型=概念/模型/实践/批判 |
| **单域标签** | 原子笔记使用一个领域标签（如 `[个人成长]`），习惯类可用 `[个人成长, 习惯]` |
| **MOC** | `32_MOCs/` 仅存放 MOC 笔记，必须含 `type: moc` 字段 |
| **文件名** | `概念名（出处）.md` 格式，出处标注来源 |
| **无平铺文件夹** | 取消所有兴趣类平铺目录。新概念一律写入 `31_Atomic_Notes/{领域}/概念/` |

## 七、目录命名规范总表

| 层级 | 格式 | 示例 | 规则 |
|:-----|:------|:-----|:-----|
| 顶层 | `NN_英文描述` | `10_Projects` | 两位数字 + 下划线 + 英文 |
| 项目/领域编号 | `NN_中文名` | `11_工作` | 两位数字 + 下划线 + 中文 |
| 项目内 | `NN_中文名` | `01_操盘手骑士` | 两位数字 + 下划线 + 中文 |
| 通用子目录 | `中文名/` | `健康/` | 纯中文，不加编号 |
| 系统目录 | `NN_英文/` | `91_Templates/` | 两位数字 + 英文，以 9 开头 |
| 模板/特殊目录 | `_描述/` | `_项目模板/` | 以下划线开头，排最前 |
| 情感目录 | emoji + 中文 | `💌情書/` | 仅限个人情感类文件夹 |
| MOC | `32_MOCs/` | 固定路径 | 不允许其他目录存放 MOC |
| 原子笔记 | `31_Atomic_Notes/{领域}/{类型}/` | 8领域×4类型 | 领域=中文，类型=概念/模型/实践/批判 |

## 八、目录归属判断树

当新建一篇笔记时，按以下顺序判断它应该放在哪里：

```
1️⃣ 是否属于每日日记/习惯追踪？
    ├── 是 → 20_Areas/22_个人成长/Bullet Journal/ 或 Atomic Habits/
    └── 否 → 跳 2️⃣

2️⃣ 是否有截止日期/产出目标？
    ├── 是 + 活跃 → 10_Projects/ 对应项目编号下
    └── 否 → 跳 3️⃣

3️⃣ 是否属于长期责任领域？
    ├── 是 → 20_Areas/ 对应领域下
    └── 否 → 跳 4️⃣

4️⃣ 是原子笔记（概念/模型/批判/实践）？
    ├── 是 → 30_Resources/31_Atomic_Notes/{领域}/{类型}/
    └── 否 → 跳 5️⃣

5️⃣ 是某个主题的索引/MOC？
    ├── 是 → 30_Resources/32_MOCs/
    └── 否 → 跳 6️⃣

6️⃣ 内容已完成/项目已结项？
    ├── 是 → 40_Archive/ 对应领域子目录下
    └── 否 → 00_Inbox/_raw/ 待 Ingest
```
