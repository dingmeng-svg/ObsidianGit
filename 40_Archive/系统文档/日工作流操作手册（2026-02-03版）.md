## 文档一：日工作流操作手册（修改版）
# 日工作流操作手册
> 本文是 [[知识库融合架构设计]] 的可执行版本。每天早上按这个流程操作，不要思考，直接执行。
> 
> **如果你中断了一天或几天：不要思考"我怎么又没做到"，直接打开今天的 Daily，从打卡开始。系统的价值不体现在从不中断，而体现在中断后恢复的成本极低。**

## 一、晨间 5 分钟（06:30）
### 1.1 打开今日 Daily Log

路径：50_Bullet_Journal/Daily/YYYY-MM-DD.md  
系统文档：50_Bullet_Journal/Daily/_模板.md

text

### 1.2 习惯打卡
在 Daily 顶部填写：

🔲 习惯打卡  YYYY-MM-DD
🏃 冷水澡        ✓ / — / ✗
🏃 运动           ✓ / — / ✗
🏃 早睡           ✓ / — / ✗
🧠 阅读 30 分钟   ✓ / — / ✗
🧠 写作           ✓ / — / ✗
🧠 不刷短视频     ✓ / — / ✗
🚀 深度工作 2h    ✓ / — / ✗
🚀 推进 MIT       ✓ / — / ✗
🔗 午晚餐聊天     ✓ / — / ✗
🔗 不生气         ✓ / — / ✗
🔗 联系朋友       ✓ / — / ✗

> `✓` 已完成 `—` 未计划今天做 `✗` 计划了但没做

### 1.3 迁移昨日未完成

1. 打开昨日 Daily Log
    
2. 找到所有标记 `▶`（未完成迁移）和 `✗`（放弃但需重审）的条目
    
3. 决定：
    
    - 今天继续 → 抄到今天 Daily，标记 `▶`
        
    - 不再需要 → 在原条目后面写 `✗ 放弃`
        
    - 太大了 → 拆成小步骤，抄第一小步到今天
        

### 1.4 设定今日 MIT（Most Important Tasks）

markdown

★ MIT
□ 从 10_Projects 当前激活项目提取
□ 从 20_Areas 维护事务提取
□ 不超过 3 条

**信息来源：**

- [[_Project_Index]] → 查看当前 status=active 的项目
    
- [[_Areas_Index]] → 查看各领域的待处理事项
    

> **🆕 MIT 优先级裁决规则**：
> 
> **默认规则：MIT 优先从 Projects 提取。** Areas 事务仅在以下两种情况进入 MIT：
> 
> 1. 它已经拖延超过 7 天，并产生了实际可见的代价
>     
> 2. 它今天不做，会在未来 7 天内引发危机
>     
> 
> 其余所有 Areas 事务统一放入下午 14:00 的维护时段处理。如果在提取 MIT 时遇到不确定的情况，执行这个默认规则，不要在 06:35 消耗决策心力。

## 二、全天 Rapid Logging

### 2.1 符号系统

|符号|含义|示例|
|---|---|---|
|`·`|笔记 / 想法|`· 卡片笔记的本质是降低认知负荷`|
|`○`|事件|`○ 杨媚说周末想去爬山`|
|`□`|任务（待完成）|`□ 写完第六节课台本初稿`|
|`✓`|完成|`✓ 写完第六节课台本初稿`|
|`✗`|放弃 / 取消|`✗ 今天去银行（不需要了）`|
|`▶`|迁移到明天|`▶ 继续写第七节课台本`|
|`★`|优先级 / MIT|`★ 完成 Q4 预算表`|
|`!`|灵感 / 重要发现|`! 或许可以用炒菜来类比仓位管理`|

### 2.2 规则

1. **一句话一条**。不要写长段落。
    
2. **随时记，不筛选**。先捕获，后处理。
    
3. **灵感→Inbox**。任何引发"这个有意思"的 → 立即在 `00_Inbox/` 创建一个文件。
    

> **🆕 Rapid Logging 与 Inbox 的边界判断**：
> 
> 当你拿不准一条想法应该记在 Daily Log 的 `·` 还是进 `00_Inbox/` 时，使用这个标准：
> 
> |情况|放哪里|
> |---|---|
> |一句话就能完整表达这个想法|Daily Log `·`|
> |需要 3 句以上才能说清楚|`00_Inbox/` 创建独立文件|
> |不确定|先进 Daily Log `·`，晚间复盘时再决定是否升级到 Inbox|
> 
> 不要在这个判断上花超过 10 秒。不确定就记 Daily，晚上再说。

### 2.3 灵感捕获模板

当有灵感闪现时，在 `00_Inbox/` 新建文件：

markdown

---
date: YYYY-MM-DD
source: 系统文档-log
status: draft
---
# 一句话标题
一句话描述这个想法。
## 为什么重要
（可选的 1-2 句）

## 三、深度工作时段

### 3.1 进入深度工作

1. 打开 `10_Projects/当前项目/02_执行/` 下的任务文件
    
2. 手机静音，通知关闭
    
3. 设定 50 分钟计时器
    
4. 只做一件事
    

> **🆕 卡住时的默认出口**：
> 
> 在每个激活项目的执行文件顶部，预先写好这句话：
> 
> markdown
> 
> > 🆘 卡住时的默认动作：如果连续 15 分钟无进展 → 在 `00_Inbox` 新建文件描述卡点 → 切换到该项目的另一个子任务，或切换到 Areas 维护事务。
> 
> 这句话的价值不在于你每次都用它，而在于它在你卡住时提供了一个"已经决定好的出口"，降低焦虑、防止死磕。

### 3.2 产出记录规则

|产出类型|记录位置|示例|
|---|---|---|
|台本/文案/代码|项目文件夹 `02_执行/`|`02_执行/第六节课台本_v1.md`|
|进度标记|Daily Log|`✓ 第六节课台本初稿完成`|
|卡住的问题|`00_Inbox/`|创建 `第六节课节奏问题`|
|需要调研的|`30_Resources/`|创建文献笔记|

> **关键原则：产出写项目，进度写 Daily，问题进 Inbox。**

## 四、晚间复盘（21:00）

### 4.1 习惯打分

在 Daily Log 底部：

markdown

---
🔄 日复盘 YYYY-MM-DD
习惯汇总：
🏃 身体：冷水澡 ✓  运动 ✗  早睡 ✓
🧠 心智：阅读 ✓    写作 ✗  不刷短视频 ✓
🚀 产出：深度工作 ✓  推进 MIT ✓
🔗 联结：聊天 ✓    不生气 ✓  联系朋友 —

### 4.2 三个问题


今天完成了什么？
- （列出 1-3 件实际完成的事，不是计划的事）
有什么卡住了？
- （是什么阻碍了你？外部因素还是内部因素？）
今天学到的一个东西：
- （可以是知识、洞察、关于自己的发现）

> **🆕 习惯与实际的对照（新增）**：
> > 
> 习惯与实际的对照：
> - 今天哪个打 ✓ 的习惯其实质量不高？（比如"深度工作 2h"打了 ✓，但实际上有一半时间在走神）
> - 今天哪个打 ✗ 的习惯背后有可消除的障碍？（比如"运动 ✗"是因为没带跑鞋，而不是不想动）
> 
> 这两个问题把打卡从"记账"升级为"诊断"。不需要长篇大论，每个问题一句话即可。如果某天实在不想写，可以跳过，但周复盘时会缺少关键数据。

### 4.3 Inbox 清零

markdown

Inbox 处理：
- 今天新增 _ 条 → 已处理 _ 条
- 剩余 _ 条 → 明天继续

**处理流程（每条 1 分钟决策）：**

1. 这个想法还重要吗？→ 不重要就删
    
2. 可行动吗？→ 有截止日放 `10_Projects`，无截止日放 `20_Areas`
    
3. 是知识吗？→ 放 `30_Resources`
    
4. 已完成/过时？→ 放 `40_Archive`
    

> **🆕 被丢弃的想法的价值**：
> 
> 每条被你主动决定"不追"的 Inbox 条目，不是在浪费——它已经被你看见了，被评估了，并为你的判断力贡献了一次训练。一个被评估后丢弃的想法，和"从来没想到过"有本质区别。

### 4.4 明天三件事

明天最重要的三件事：
1. □
2. □
3. □

> **🆕 废弃 MIT 追踪**：
> 
> 如果一个 MIT 连续三天被标记为 `▶` 迁移，或在一个自然周内被标记 `✗` 放弃超过一次，将其记入：
> 
> 
> 🪦 本周被放弃或第三次迁移的 MIT：
> - [[某任务]] — 第三次迁移，原因：等待外部反馈
> 
> 这个区域在周复盘时专门回顾。它帮你识别"名义上的重要任务"——那些一直挂在 MIT 位置但从没真正进入执行的东西。

## 五、周工作流（周日 30 分钟）

### 5.1 打开本周 Weekly Log

text

路径：50_Bullet_Journal/Weekly/YYYY-WXX.md

### 5.2 回顾 7 天 Daily Log

- 浏览本周 7 天的 Daily Log
    
- 提取所有标记 `▶` 的未完成条目
    
- 每个条目执行：**放弃 / 分解 / 迁移**
    
- **🆕 回顾每日的"🪦 废弃 MIT"区域，判断这些任务是否需要彻底放弃或重新定义**
    

### 5.3 Inbox 清零

- 确保 `00_Inbox/` 中所有 fleeting notes 都已处理
    
- 目标：Inbox 文件数为 0
    

### 5.4 知识提炼（本周最重要的 15 分钟）

1. 回顾本周新增的 `30_Resources` 文献笔记
    
2. 挑选最有价值的一条
    
3. 提炼为永久笔记 → 写入 `31_Atomic_Notes/`
    
4. 格式：
    

```
---
date: YYYY-MM-DD
source: "[[原始文献笔记]]"
tags: []
---
```

# 概念名
用自己的话，不超过 300-500 字。
## 为什么重要
## 它和什么相关
- [[另一张永久笔记]]

> **🆕 反向链接动作（新增步骤）**：
> 
> 写完永久笔记后，执行一个额外的 2 分钟动作：
> 
> 1. 打开新笔记中链接到的每一张旧永久笔记
>     
> 2. 在旧笔记中加上一条指向新笔记的链接，并用一句话标注两者的关系
>     
> 
> 例如：新笔记 `[[炒菜类比仓位管理]]` 链接到了旧笔记 `[[仓位管理基本原则]]`。去旧笔记里加上：
> 
> 
> ### 相关类比
> - [[炒菜类比仓位管理]] — 用炒菜的火候控制类比仓位调整的节奏感
> 
> 这一步把单向引用变成双向对话。它是 Luhmann 原始 知识管理 最核心也最容易被忽略的动作。

### 5.5 项目审查

打开 `10_Projects/`，对每个 status=active 的项目：

- 本周有推进吗？
    
- 需要更新 status 吗？
    
- deadline 还合理吗？
    

### 5.6 习惯回顾

- 汇总 7 天打卡数据
    
- 写入 `60_Habits/习惯记分卡.md`
    
- 格式：
    


## 2026-WXX
| 习惯 | 一 | 二 | 三 | 四 | 五 | 六 | 日 | 完成率 |
|------|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|
| 冷水澡 | ✓ | ✓ | ✓ | ✗ | ✓ | — | — | 80% |
| ... |
### 本周观察
- （趋势、异常、调整计划）

> **🆕 习惯回顾时特别关注**：
> 
> - 回顾本周操盘手骑士/直播稿中的"习惯与实际的对照"，提取反复出现的模式
>     
> - 如果一个习惯本周出现 2 次以上"打了 ✓ 但质量不高"，下周需要重新定义这个习惯的"完成"标准，或降低难度
>     

### 5.7 下周预览

- 查看 `50_Bullet_Journal/Future/` 中本月目标
    
- 结合本周未完成
    
- 设定下周焦点（不超过 3 个）

### 每日时间分配建议

|时段|时长|做什么|方法|
|---|---|---|---|
|06:30|5 min|打卡 + 迁移 + MIT|BJ + AH|
|07:00|60 min|冷水澡 + 阅读|AH|
|09:00|120 min|深度工作（核心产出）|PARA|
|12:00|30 min|午餐 + Rapid Logging|BJ|

> **🆕 当时间表被打乱时**：
> 
> 如果某天无法完整执行时间表，保留这三个核心锚点（其他可以跳过）：
> 
> 1. **晨间 5 分钟**（打卡 + MIT）——用最小动作激活系统
>     
> 2. **至少一段 50 分钟深度工作**——确保今天有实质产出
>     
> 3. **晚间 3 个复盘问题**——不让今天的信息和洞察蒸发
>     
> 
> 这三个锚点构成你系统的"最小可运行单元"。即使一天只有 15% 的执行力，这三个动作也能让系统保持呼吸。
