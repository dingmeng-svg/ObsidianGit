# 知识库元数据规范 (Metadata Specification) v2.0

> [!warning] 已归档

> 本文档是知识库所有笔记类型的元数据最高标准。所有新建笔记必须遵循本文档规定。
> **版本说明**：本文档使用 `v主版本.次版本` 格式。主版本变更（如字段增删、类型重构）时，需手动批量更新相关笔记的 Front Matter；次版本变更（如标签字典新增条目、措辞调整）向后兼容，无需迁移已有笔记。

## §0 架构核心原则

### 原则一：`type` 字段的克制

`type` 字段仅用于需要高频 Dataview 查询或具备专属处理流程的笔记类型。当前全库六种：

| type 值 | 笔记类型 | 存放路径 |
| :--- | :--- | :--- |
| `concept` | 原子笔记——概念类 | `31_Atomic_Notes/{领域}/概念/` |
| `model` | 原子笔记——模型类 | `31_Atomic_Notes/{领域}/模型/` |
| `practice` | 原子笔记——实践类 | `31_Atomic_Notes/{领域}/实践/` |
| `critique` | 原子笔记——批判类 | `31_Atomic_Notes/{领域}/批判/` |
| `moc` | MOC 结构索引 | `32_MOCs/` |
| `recipe` | 食谱 | 按领域归类 |
| `training_plan` | 训练计划 | 按领域归类 |

其余所有笔记（归档、系统文档）**不设 `type` 字段**，统一用 `tags` 软分类。

### 原则二：出处信息的单一来源

- 文件名仅表达"这是什么概念"，后缀仅同名消歧义时加（出处）。
- 所有的作者、来源信息优先交给 YAML 的 `author` 和 `source` 字段维护。
- 不推荐文件名后缀与 YAML 字段的双轨维护。

### 原则三：元数据与正文的分层

- **元数据（YAML）服务于机器检索**：数值化字段用于 Dataview 排序/筛选。
- **正文服务于人类阅读**：详细描述、说明等深度内容放正文。
- 链接统一放在 YAML `related:` 字段，正文不残留 `## 关联笔记` 区块。

### 原则四：全局基础状态与扩展状态分层

- **全局基础状态**（`draft` / `active` / `archived`）：全库通用生命周期。
- **类型扩展状态**（如 `mature`）：特定笔记类型在基础状态上的语义细化。

## §1 通用知识笔记标准

> 适用于不属于原子笔记、MOC、食谱、训练计划的所有常规笔记。

```yaml
---
title: "{{title}}"
date: {{date}}
status: ""              # draft | active | archived
tags: []                # 从 §8 选取，单域标签
aliases: []
related: []
---
```

| 字段 | 必填 | 说明 |
| :--- | :---: | :--- |
| `title` | ✅ | 文档标题 |
| `date` | ✅ | 创建或最后修改日期 |
| `status` | ✅ | `draft` / `active` / `archived` |
| `tags` | ✅ | 从 §8 标签字典中选取，**至少 1 个** |
| `aliases` | 选填 | 搜索别名 |
| `related` | 选填 | 关联笔记双链 |

## §2 原子笔记标准

> 存放于 `31_Atomic_Notes/{领域}/{类型}/` 下。领域=8种，类型=概念/模型/实践/批判。

### 文件名规则

- **默认**：`概念名（出处）.md`，如 `蔡格尼克效应（心理学）.md`。
- **出处**：标准学术模型用 `（AuthorName）`，原创框架用 `（原创）`，如 `梅拉宾法则（Mehrabian）.md`。

### 标准模板

```yaml
---
title: "概念名（出处）"
date: 2026-06-28
status: active        # draft | active | mature | archived
type: concept         # concept | model | practice | critique
tags: [工作]           # 单域标签，从 §8 选取
aliases:
  - "别名"
related:
  - "[[相关笔记]]"
human_edited: true    # 存量笔记默认 true，AI 禁止覆盖正文
---
```

### 模板说明

| 字段 | 必填 | 说明 |
| :--- | :---: | :--- |
| `title` | ✅ | `概念名（出处）` 格式 |
| `date` | ✅ | 创建日期 |
| `status` | ✅ | `draft`(草稿) / `active`(仍在生长) / `mature`(已完成提炼) / `archived`(已归档) |
| `type` | ✅ | `concept` / `model` / `practice` / `critique` |
| `tags` | ✅ | **一个**领域标签，从 §8 选取。习惯类可用 `[个人成长, 习惯]` |
| `source` | 选填 | 来源文件双链或 URL |
| `author` | 选填 | 原作者 |
| `aliases` | 选填 | 搜索别名 |
| `related` | 选填 | 同级原子笔记双链 |
| `human_edited` | ✅ 存量 | `true` = 人类编辑，AI 禁止覆盖正文；新建笔记选填 |

### 原子笔记状态流转

```
draft → active → mature → archived
  │                 │
  └─────────────────┴──────→ archived (任意阶段均可废弃归档)
```

- `draft`：灵感碎片，概念尚未成型。
- `active`：概念清晰，仍在打磨中。
- `mature`：提炼完成，内容稳定，可作为可靠引用源。
- `archived`：概念过时或不再维护。

## §3 MOC 笔记标准

> 存放于 `32_MOCs/`。MOC 是笔记的结构索引。

```yaml
---
title: "主题名称 MOC"
date: 2026-06-28
type: moc
status: active
tags: [心理学]           # 单域标签
human_edited: true
---
```

| 字段 | 必填 | 说明 |
| :--- | :---: | :--- |
| `type` | ✅ | 固定为 `moc` |
| `title` | ✅ | MOC 主题名称，建议含 `MOC` 后缀 |
| `date` | ✅ | 创建日期 |
| `status` | ✅ | `draft` / `active` / `archived` |
| `tags` | ✅ | 纯领域标签（如 `[心理学]`），不使用 `知识管理` |
| `human_edited` | ✅ | 存量笔记默认 `true` |

## §4 归档文件标准

> 按 PARA 体系归档至 `40_Archive/` 的文件。归档是冷库，保持极简。

```yaml
---
title: "文档标题"
date: 2026-06-28
status: archived
tags:
  - 归档
  - 个人成长       # 来源领域标签
---
```

| 字段 | 必填 | 说明 |
| :--- | :---: | :--- |
| `title` | ✅ | 文档标题 |
| `date` | ✅ | 创建或归档日期 |
| `status` | ✅ | 固定为 `archived` |
| `tags` | ✅ | `[归档, 领域]`，领域标签从 §8 选取 |
| `aliases` | 选填 | 搜索别名 |
| `related` | 选填 | 关联笔记双链 |

**注意**：归档文件**不设 `type` 字段**，不设 `project` 字段。

## §8 YAML 书写规范（全库通用）

1. `---` 独立成行，不黏内容。
2. `tags` 不使用 `#` 前缀，使用 YAML 数组语法（`tags: [领域]` 或换行列表示）。
3. 双链引用用引号包列表格式：`related: ["[[笔记名]]"]` 或多行列表。
4. 修改后执行 `yaml.safe_load()` 校验语法。
5. 正文不可残留 `## 关联笔记` 区块——链接统一放在 YAML `related:` 字段。
6. `project` 字段统一用项目名（如 `操盘手骑士`），非标签。
7. `human_edited: true` 的存量笔记，AI 禁止覆盖正文。

## §9 标签字典

> 单域标签系统。每篇笔记**一个**领域标签，习惯类可用 `[个人成长, 习惯]`。

### 领域标签

| 标签 | 覆盖范围 |
| :--- | :--- |
| `工作` | 职场、管理、创业、协作、操盘手骑士项目文件 |
| `个人成长` | 认知、学习、写作、传统文化、习惯方法论 |
| `生活` | 日常、烹饪、运动、健康、旅行 |
| `关系` | 人际、亲密关系、沟通、伴侣、家人、朋友 |
| `财务` | 投资、理财、记账、资产 |
| `技术` | 编程、架构、AI、工具、Obsidian |
| `心理学` | 情绪、认知、行为、人格 |
| `知识管理` | 笔记法、PKM、卡片盒 |
| `国际政治` | 时政、国际关系、地缘 |
| `科学` | 物理、生物、化学、数学、AI 底层原理 |
| `系统文档` | 90_System/ 下所有文件 |
| `归档` | 40_Archive/ 下所有文件（状态标签） |
| `素材` | 外部摘抄、剪辑、灵感收集 |
| `日记` | 每日日记（类型标签） |
| `习惯` | 习惯方法论概念，**仅与 `个人成长` 联用** |

### 标签使用规则

- **单域原则**：一篇笔记只用一个领域标签。例外：习惯概念用 `[个人成长, 习惯]`。
- **归档标签**：`[归档, 领域]`，需与一个领域标签搭配。
- **操盘手骑士不是标签**：项目名写在 `project:` 字段，文件用 `[工作]` 标签。
- **无子类标签**：禁用旧版 `#领域/子类` 格式（如 `#生活/烹饪`），全部扁平。
- **原子笔记的 `type` 字段**：类型信息在 `type:` 字段（concept/model/practice/critique），不在 tags 里。

## §10 难度字典（食谱与训练计划共享）

| level | difficulty | 食谱特征 | 训练计划特征 |
| :--- | :--- | :--- | :--- |
| 1 | ★ | 极简：无需基础，零失败 | 入门/康复：零基础，低强度 |
| 2 | ★★ | 简单：基础操作，新手友好 | 初级：基础动作组合 |
| 3 | ★★★ | 中等：需经验，关键步骤 | 中级：需一定经验 |
| 4 | ★★★★ | 困难：多步骤，精确控温/控时 | 高级：高强度/高复杂度 |
| 5 | ★★★★★ | 大师：需专业设备或长期训练 | 专业：竞技级别 |
