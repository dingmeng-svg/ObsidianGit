### 第一阶段：核心规范落地

**目标**：产出总纲 v3.0、速查卡、目录别名映射表三份核心文档，并通过压力测试验证规则自洽。

**步骤**：

1. **撰写速查卡**（先于总纲正文）
   - 从六轮裁决中提取全部核心规则（约 15-20 条），生成 `知识库规范速查.md`
   - 采用 YAML 代码块 + Markdown 表格双层结构
   - 顶部嵌入版本戳，版本戳下方嵌入冲突仲裁声明：「当本速查卡与《总纲》内容不一致时，以《总纲》为准。」
   - 为所有核心章节分配永久英文锚点，锚点一经分配永不修改

2. **撰写总纲 v3.0 正文**（以速查卡为索引展开）
   - 按 §总则 → §命名 → §标签 → §目录 → §YAML → §归档 → §MOC → §双链 → §内容质量 → §系统维护 顺序撰写
   - §总则和附录最后撰写（后置确保摘要与正文严格一致）
   - 总纲文件名使用功能性命名，不受纯概念名规则约束

3. **生成目录别名映射表**
   - 新建 `90_System/目录别名映射表.md`
   - 使用 YAML 代码块格式

4. **确认 Obsidian 设置**
   - 确认 `设置 → 文件与链接 → 自动更新内部链接` 处于开启状态

5. **P0 压力测试**（总纲初稿完成后立即执行）
   - 按附录 D 四个场景逐一测试
   - 通过标准：四个场景全部符合现有规则、无逻辑冲突、无操作歧义
   - 测试结果写入 `系统演进备忘录.md`，不进入总纲正文
   - 若出现规则矛盾，优先调整总纲细则再继续

### 第二阶段：旧体系清理与迁移

**目标**：合并旧规范文档，修复项目目录编码不一致，建立外部导入隔离。

**步骤**：

1. **合并与归档旧规范文档**
   - 将 `标签与命名规范总表 v2.0` 中的纯规则条款萃取进总纲对应章节
   - 旧文档中的动态数据快照（133KB 全库标签表）直接归档，不进入总纲
   - 旧规范文件移入 `90_System/_归档旧规范/`
   - 所有保留的专项手册开头增加统一引用声明：「完整编码、命名、标签规范详见《知识库统一规范总纲 v3.0》，本文档仅为专项流程补充，不替代总规范。」

2. **修复项目目录编码不一致**
   - 将 `Active_Listening_Project`、`Self_Worth_Diary` 等无编码英文文件夹重命名为 `NN_中文名` 格式
   - 重命名完成后，随机抽查 5-10 篇该项目下笔记的反向链接，确认无断裂

3. **外部导入文件隔离**
   - 在 `00_Inbox/` 下创建 `外部导入/` 子目录
   - 后续所有外部剪藏或导入内容统一存放于此

4. **存量迁移可选标记**
   - 过渡期内，未完成命名规范化的存量笔记，可在 YAML 中临时添加 `legacy: true` 标记
   - 迁移完成后移除该字段
   - 此标记为可选项，不强制批量添加

### 第三阶段：系统韧性加固

**目标**：集中附件存储，P0 验收，启动新规范运行。

**步骤**：

1. **附件集中存储**
   - 新建 `90_System/Assets/` 作为附件主目录
   - 后续新增附件统一存放于此
   - 存量附件保持原位不动，后续日常使用遇到时顺手移入 `90_System/Assets/`

2. **P0 验收**
   - 抽检 5 篇新建笔记，同时校验三项：
     - 文件名纯概念名，无括号出处后缀
     - `source` 字段为单值，格式符合约定
     - `tags` 符合从属互斥规则，无无效双标签
   - 三项全部通过则验收通过
   - 验收结果写入 `系统演进备忘录.md`

3. **生效节点**
   - 以 P0 验收通过作为 v3.0 规范正式生效的唯一节点
   - 生效后新建笔记严格执行新规则
   - 在首页索引文件临时增加 v3.0 总纲的跳转入口，过渡期保留 1 个月

---

### 核心原则

- **存量笔记渐进式迁移**：不进行批量重命名，旧笔记在后续日常使用和复盘时顺手修改。短期接受新旧命名混存的过渡状态。
- **新笔记立即执行**：自总纲生效之日起，所有新建原子笔记严格采用纯概念名，出处信息下沉至 YAML 元数据。
- **AI 辅助边界**：Agent 仅辅助重命名、补全 YAML 字段等操作，所有修改结果需人工确认。
