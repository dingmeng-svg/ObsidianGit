# 四体系角色分工与习惯落地路径

> **归档原因**：当前知识库已进入 v2.3+ 迭代，此文档为 v2.2 架构参考。已由新版系统架构文档接替。保留备查。

> 本文档记录 v2.2 架构中 PARA / Bullet Journal / AH / ZK 四体系的分层关系，以及个人习惯体系在此架构中的落地路径。

---

## 一、四体系不是并列的方法论

四者在当前架构中是**分层的**，各管一个维度：

| 体系 | 维度 | 一句话定位 | 物理落点 |
|:---|:---|:---|:---|
| **PARA** | 空间 | 文件放哪里 | `00_Inbox/` `10_Projects/` `20_Areas/` `30_Resources/` `40_Archive/` |
| **Bullet Journal** | 时间 | 什么时候做什么 | `20_Areas/.../Bullet Journal/`（日/周/月）+ `22_个人成长/`（季/年） |
| **AH** | 行为 | 怎么坚持做 | 分布式嵌入 Bullet Journal 各层 Callout |
| **ZK** | 思考 | 学到的东西去哪 | `31_Atomic_Notes/` |

```
PARA → 分配空间（文件放哪）
Bullet Journal → 驱动节奏（什么时候做）
AH   → 塑造行为（怎么坚持做）
ZK   → 沉淀思考（学到的东西去哪）
```

每天打开 Obsidian：
- **PARA** 保证你找得到文件
- **BuJo** 告诉你今天该干什么
- **AH** 帮你打卡、反思习惯
- **ZK** 把你读到的东西变成你自己的

- PARA 为其他三者提供物理目录结构，不参与执行逻辑

## 三、习惯体系在 v2.2 中的完整落地路径

### 3.1 已有组件映射

| 个人需求 | 已有组件 | 位置 |
|:---|:---|:---|
| 想培养的好习惯、想改掉的坏习惯（心愿单） | 习惯设计参考 · 孵化池 | `20_Areas/22_个人成长/Atomic Habits/习惯设计参考.md` |
| 已确定习惯的每日打卡 | 习惯记分卡 | `20_Areas/22_个人成长/Atomic Habits/习惯记分卡.md` |
| 未完成的事、做坏了想补救的事 | Daily 子弹记录 + Weekly/Monthly 任务迁移 | `Bullet Journal/` |
| 习惯进展的趋势反思 | Weekly/Monthly Callout 的 MIT 回顾和习惯趋势 | 各日记文件内 |
| 习惯是否服务于身份认同 | Quarterly §3 身份对齐检查 | 季度复盘文件 |

### 3.2 四步工作流

```
第一步：捕获（随时随地）
  ├─ 刷到习惯灵感 / 自己意识到想改 → 记在当天 Daily 闪念区
  └─ 不紧急的习惯灵感 → 直接写入习惯设计参考·孵化池表格

第二步：梳理（每周）
  ├─ Weekly 复盘时打开孵化池，判断哪些习惯准备好进入记分卡
  ├─ Bullet Journal 每周迁移自动捞出未完成任务（"做坏了想补救的事"在这里被看到）
  └─ 决定：迁移到下周 / 标记取消 / 拆解成更小步骤

第三步：执行（每天）
  ├─ 习惯记分卡告诉你今天该打哪些卡
  └─ Daily 日记记录执行情况

第四步：校准（每月/每季）
  ├─ Monthly Callout「习惯系统调整」→ 判断是否新增/废弃/调整习惯
  └─ Quarterly §3「身份对齐检查」→ 问自己：这些习惯有没有让我成为我想成为的人？
```

### 3.3 孵化池使用规则

- 把新习惯写入孵化池，**观察 14 天**
- 14 天内不强制打卡，只观察自然状态下的行为频率
- 14 天后三选一：
  - ✅ 正式纳入记分卡
  - ❌ 放弃
  - ⏳ 继续孵化

## 四、核心纪律：一次聚焦一个习惯

> 把记分卡上的项目控制在手上能数的数量。
> —— James Clear

**陷阱**：事无巨细地排查所有坏习惯 → 清单越来越长 → 每个都只坚持三天 → 清单变成焦虑源头。

**正确做法**：
- 孵化池可以列很多（捕获不受限）
- 记分卡一次只追踪 **3-5 个习惯**（执行要聚焦）
- 每季度通过 Quarterly 复盘决定哪个习惯该进入、哪个该退出

## 五、数据流全景

```
习惯灵感
  ↓ Daily 闪念区捕获
  ↓ Weekly 复盘梳理
  ↓ 习惯设计参考·孵化池（14天观察）
  ↓
习惯记分卡（每日打卡）
  ↓ Daily 记录执行
  ↓ Weekly Callout 汇总趋势
  ↓ Monthly Callout 判断系统调整
  ↓
Quarterly §3 身份对齐（校准）
  ↓ Annual Compass 年度检查点（瞭望）
```

未完成任务的数据流：
```
Daily 子弹记录（- [ ] 未完成项）
  ↓ Dataview 自动捞取到次日待办
  ↓ Weekly 复盘时审视
  ↓ 决定：迁移 / 取消 / 拆解
```
