# 知识库融合架构设计

> 基于 **Bullet Journal**、**PARA**、**知识管理（知识管理/知识管理）** 和 **Atomic Habits（原子习惯）** 四大方法论的深度融合，针对本知识库实际结构设计的综合架构。

---

## 一、四大方法论概述

### 1.1 各自的核心基因

| 方法论                | 核心基因                | 解决的核心问题      | 在库中的对应位置                                                                                                     |
| ------------------ | ------------------- | ------------ | ------------------------------------------------------------------------------------------------------------ |
| **Bullet Journal** | 快速记录 + 迁移机制         | "我现在该做什么？"   | `50_Bullet_Journal/`                                                                                         |
| **PARA**           | 按可行动性四层分类           | "这个信息放哪里？"   | `10_Projects_Things/`(两级: `11_工作/01_项目`) → `20_Areas_My/` → `30_Resources_Things/` → `40_Archive_Completed/` |
| **Zettelkasten**   | 原子化 + 双向链接 + 自下而上浮现 | "这个知识如何生长？"  | `30_Resources/31_Atomic_Notes/` → `30_Resources/32_MOCs/`                                                    |
| **Atomic Habits**  | 身份驱动 + 微小增量 + 环境设计  | "我如何成为那样的人？" | `60_Habits/` + `61_Reviews/`                                                                                 |

### 1.2 关键词索引

- **Rapid Logging**（快速记录）：Bullet Journal 的核心技术，用一句话符号记录想法、事件、任务
- **Fleeting Notes**（闪念笔记）：知识管理 的第一阶段，捕获瞬间灵感
- **Literature Notes**（文献笔记）：用自己的话转述所读内容，标注来源
- **Permanent Notes**（永久笔记）：原子化的、互联的、可独立理解的知识卡片
- **MOC**（Map of Content，内容地图）：链接聚合多张永久笔记的索引页面
- **Implementation Intention**（执行意图）："当 X 发生时，我就做 Y"的行为编程
- **Habit Stacking**（习惯堆叠）：将新习惯锚定在已有习惯之后
- **Habit Scorecard**（习惯记分卡）：每日对关键习惯进行 + / - / = 打分

## 二、交集：四者的共振点

四套方法论来自不同作者、不同时代，但底层逻辑高度收敛。

### 共振点 1：唯一入口 → 减少决策疲劳

- BJ 的 **Daily Log** 是所有当天信息的唯一页面
- ZK 的 **Fleeting Notes** 是所有想法的唯一捕获点
- PARA 的 **Inbox** 是所有待处理信息的唯一入口
- AH 的 **环境设计** 要求把好习惯的触发器放在唯一可见的位置

> **本库实现：** `00_Inbox` 是唯一信息入口，`50_Bullet_Journal/Daily/` 是唯一时间入口。一个管"来了什么"，一个管"今天做什么"。

### 共振点 2：定期迁移 → 防止熵增

- BJ 要求每月将未完成任务迁移到下个月的 Monthly Log
- PARA 要求定期将完成的 Projects 移入 Archive
- ZK 要求定期从闪念笔记提炼为永久笔记
- AH 要求每周回顾习惯记分卡，调整策略

> **本库实现：** 日清零 Inbox → 周提炼永久笔记 → 月归档项目 → 季复盘习惯趋势。四级迁移节奏。

### 共振点 3：原子化 → 降低启动阻力

- ZK：一条笔记一个概念，不超过一屏
- AH：2 分钟规则——把新习惯缩到 2 分钟内可完成
- BJ：Rapid Logging 一句话一条，不写长篇
- PARA：一个项目一个文件夹，独立完整

> **本库实现：** `31_Atomic_Notes` 一卡一概念；Daily Log 一句一条；`10_Projects` 每个项目独立文件夹；`60_Habits` 每条习惯都可 2 分钟启动。

### 共振点 4：身份驱动 → 从"做什么"到"是谁"

- AH 的核心理念：**身份认同驱动行为，行为反过来强化身份**
- BJ 通过每日反思强化自我认知
- ZK 通过与自己的永久笔记对话，塑造思想体系
- PARA 通过 Projects 的输出定义"我是创造者"

> **本库实现：** `60_Habits/身份认同.md` 是整个系统的价值观底座。

## 三、冲突：四者之间的张力与解决

| 冲突 | 表现 | 本库解决方案 |
|------|------|------------|
| **BJ vs PARA：按时间还是按领域组织？** | 同一条记录"给杨媚打电话"，放 Daily 还是 `24_关系/伴侣`？ | 行动类写 Daily，持久信息放 Area。Daily 是"今天要打"，Area 是"如何维护关系" |
| **ZK vs PARA：知识放 Resources 还是 Atomic Notes？** | 读书笔记放 `30_Resources` 还是提炼后放 `31_Atomic_Notes`？ | 两者都放。`30_Resources` 存文献笔记（有来源的），`31_Atomic_Notes` 存永久笔记（完全用自己的话） |
| **AH vs BJ：习惯打分嵌入哪里？** | 独立追踪还是嵌入 Daily Log？ | **嵌入 Daily Log 顶部**。晨间打卡写 Daily，周日汇总写入 `60_Habits/习惯记分卡.md` |
| **Project vs Daily：工作产出记录在哪？** | 今天推进了操盘手骑士第六节课，成果写项目文件夹还是 Daily？ | **产出写项目**，进度写 Daily。Daily 写"完成第六节初稿 ✓"，具体内容在 `10_Projects/01_操盘手骑士/02_执行/` |

## 四、融合策略：垂直分层模型

关键认知：**四种方法论不是平行的竞争关系，而是垂直的分层关系。**

```
┌─────────────────────────────────────────────┐
│              身份层 (Atomic Habits)           │
│        "我是一个系统化的创作者"                 │
│        价值观 → 身份 → 习惯 → 行为              │
├─────────────────────────────────────────────┤
│              时间层 (Bullet Journal)          │
│    Daily → Weekly → Monthly → Future         │
│    "今天这 16 小时怎么过"                      │
│    捕获、排序、迁移、反思                      │
├──────────────┬──────────────────────────────┤
│  行动层 (PARA)│        知识层 (ZK)            │
│  P → A → R → A│  闪念 → 文献 → 永久 → MOC     │
│  "做什么"     │      "怎么想"                 │
│  交付物驱动    │      理解驱动                 │
├──────────────┴──────────────────────────────┤
│              复盘层 (AH + BJ)                 │
│   习惯记分 + 日/周/月/季复盘                    │
│   "我做到了吗？学到了什么？接下来怎么调？"        │
└─────────────────────────────────────────────┘
```

### 设计逻辑

1. **身份层在最上**：所有行动和知识的源头是"我是谁"。如果你不定义身份，PARA 的项目就会变成任务清单，ZK 的笔记就会变成信息囤积。
2. **时间层是操作系统**：BJ 的 Daily Log 是每天打开 Obsidian 第一个看到的页面。时间层不存储内容，只存储"今天注意力的分配"。
3. **行动层和知识层并排**：PARA 管输出（交付项目），ZK 管输入内化（理解世界）。两者通过 Daily Log 的 MIT 和晚间 Inbox 清零连接。
4. **复盘层是反馈回路**：从行动和知识的结果中提取模式，反馈到身份层和习惯层。没有复盘，系统就会熵增。

## 六、日工作流（核心引擎）

### 6.1 一日流程

```
06:30  打开 50_Bullet_Journal/Daily/YYYY-MM-DD.md
       │
       ├── 🔲 习惯打卡（对照 60_Habits/习惯记分卡）
       │     🏃 冷水澡        ✓ / — / ✗
       │     🧠 阅读 30 分钟   ✓ / — / ✗
       │     🚀 深度工作 2h    ✓ / — / ✗
       │     🏃 运动           ✓ / — / ✗
       │     🔗 午晚餐聊天     ✓ / — / ✗
       │
       ├── ▶ 迁移：翻昨日 Daily 未完成 → 决定今天是否继续
       │
       ├── ★ MIT（从 10_Projects 当前激活项目提取 1-3 件事）
       │
       ├── · 全天 Rapid Logging（灵感、事件、笔记）
       │    · 每条用一句话，符号前缀：
       │      · 笔记  ○ 事件  □ 任务  ✓ 完成  ✗ 放弃  ▶ 迁移  ★ 优先级
       │    · 灵感闪现 → 📥 00_Inbox（只记标题 + 一条链接）
       │
       └── 🔄 晚间 21:00 日复盘（写在同一文件底部）
            ├── 习惯打分汇总
            ├── 今天完成了什么？
            ├── 有什么卡住了？
            ├── 学到的一个东西
            ├── 习惯与实际的对照
            └── 明天最重要的三件事
```

### 6.2 日工作流中的关键决策点

| 时刻       | 你在 Daily 中做什么            | 联动哪个层级         | 用了哪个方法论          |
| -------- | ------------------------ | -------------- | ---------------- |
| 晨间 5 分钟  | 迁移未完成 + 设定 MIT + 习惯打卡    | AH → BJ → PARA | BJ 迁移 + AH 记分    |
| 全天       | Rapid Logging（一条一句）      | BJ 原生          | BJ               |
| 灵感闪现     | 记到 `00_Inbox`（一个想法一个文件）  | BJ → ZK        | ZK Fleeting Note |
| 晚间 15 分钟 | 日复盘 + Inbox 清零（至少处理 3 条） | BJ → PARA / ZK | BJ 反思 + PARA 分类  |

> 详细操作指南参见 [[日工作流操作手册]]

## 八、知识内化路径（知识管理 三阶）

```
📥 00_Inbox                    ← 第一阶段：闪念笔记（Fleeting Notes）
     │                             一句话记录灵感、问题、发现
     │                             每天清零，不过夜
     ▼
📚 30_Resources                ← 第二阶段：文献笔记（Literature Notes）
     │                             用自己的话重写，标注来源
     │                             一篇文章一条笔记
     │                             每周提炼 1~2 次
     ▼
🧠 31_Atomic_Notes             ← 第三阶段：永久笔记（Permanent Notes）
     │                             一卡一个概念，完全原子化
     │       ┌────────────────────── 用自己的话，不依赖原文
     │       ├── 不超过一屏（约 300-500 字）
     │       ├── 与其他永久笔记双向 [[链接与索引（卡片笔记写作法）]]
     │       ├── 一个想法写完后问：它还和哪些想法有关？
     │       └── 五分类：Concepts / Critiques / Models / People / Practices
     │
     ▼
🗺️ 32_MOCs                     ← 第四阶段：索引笔记（MOC - Map of Content）
          └── 触发条件：当某个主题的原子笔记超过 5 条时，创建 MOC
              链接所有相关原子笔记，标注它们之间的关系
              MOC 本身也是笔记，会随着理解不断更新
```

### 关键原则

1. **不要跳过任何阶段**。闪念不过夜，文献用自己的话，永久必须原子化。
2. **提炼是瓶颈，也是价值所在**。一天读 10 篇文章不如把 1 条闪念变成永久笔记。
3. **链接比笔记本身更重要**。一张永久笔记的价值 = 它被多少其他笔记链接 + 它链接了多少其他笔记。
4. **MOC 是涌现的，不是预设的**。不要提前创建空 MOC。等原子笔记积累到 5+ 条再创建。

> **🆕 8.1 PARA 与 ZK 的并行判断模型**
> 
> 你的架构中，行动层（PARA）和知识层（ZK）是并排的。同一条外部信息可能同时触发两条路径。以下判断模型解决"什么时候进 PARA，什么时候进 ZK"的问题：

| 问题的性质          | 去哪                                 | 为什么        |
| -------------- | ---------------------------------- | ---------- |
| "我该怎么做这件事？"    | PARA（10_Projects 或 20_Areas）       | 它需要产出行动或决策 |
| "我该怎么理解这件事？"   | ZK（30_Resources → 31_Atomic_Notes） | 它需要沉淀为理解   |
| "这两件事之间有什么关系？" | ZK（31_Atomic_Notes 的双向链接或 32_MOCs） | 它在建立知识结构   |

 > **关键洞察：同一个外部信息可能同时触发两条路径。** 比如你读到一篇关于叙事结构的文章——如果你正在写台本，它的"怎么做"部分进 Projects 的执行文件；它的"怎么理解"部分进 Resources 然后提炼为永久笔记。这两条路径不互斥，只是回答不同的问题。
> 
> 具体流程图参见 [[融合架构Mermaid图]] 第七节"PARA 与 ZK 并行判断模型"。

## 九、习惯系统（Atomic Habits）

### 9.1 习惯系统的四个组件

| 组件       | 文件                   | 核心问题           | AH 概念                    |
| -------- | -------------------- | -------------- | ------------------------ |
| **身份认同** | `60_Habits/身份认同.md`  | 我是谁？我想成为什么样的人？ | Identity-Based Habits    |
| **记分卡**  | `60_Habits/习惯记分卡.md` | 我今天做得怎么样？      | Habit Scorecard          |
| **执行意图** | `60_Habits/执行意图.md`  | 什么时候、在哪里、做什么？  | Implementation Intention |
| **习惯堆叠** | `60_Habits/习惯堆叠.md`  | 做完什么之后立刻做什么？   | Habit Stacking           |
| **环境设计** | `60_Habits/环境设计.md`  | 如何让好习惯不费力？     | Environment Design       |

### 9.2 四大支柱习惯

建议从这四个维度各选 1-2 个习惯开始，不要贪多：

| 支柱 | 含义 | 示例习惯 |
|------|------|---------|
| 🏃 **身体** | 生理基础设施 | 冷水澡、运动、早睡、控制饮食 |
| 🧠 **心智** | 认知能力维护 | 深度阅读 30 分钟、写作、不刷短视频 |
| 🚀 **产出** | 创造性输出 | 深度工作 2h、每天推进 MIT |
| 🔗 **联结** | 人际关系 | 午/晚餐和家人聊天、不生气、主动联系一位朋友 |

### 9.3 习惯追踪嵌入 Daily Log

每天晨间在 `50_Bullet_Journal/Daily/` 顶部打卡：

```markdown
🔲 习惯打卡
🏃 冷水澡 ✓    运动 —    早睡 ✓
🧠 阅读 ✓      写作 ✗    不刷短视频 ✓
🚀 深度工作 ✓  推进 MIT ✓
🔗 午晚餐聊天 ✓ 不生气 ✓  联系朋友 —
```

# 知识库融合架构设计

> 基于 **Bullet Journal**、**PARA**、**知识管理（知识管理/知识管理）** 和 **Atomic Habits（原子习惯）** 四大方法论的深度融合，针对本知识库实际结构设计的综合架构。

---

## 一、四大方法论概述

### 1.1 各自的核心基因

| 方法论 | 核心基因 | 解决的核心问题 | 在库中的对应位置 |
|--------|---------|---------------|-----------------|
| **Bullet Journal** | 快速记录 + 迁移机制 | "我现在该做什么？" | `50_Bullet_Journal/` |
| **PARA** | 按可行动性四层分类 | "这个信息放哪里？" | `10_Projects_Things/`(两级: `11_工作/01_项目`) → `20_Areas_My/` → `30_Resources_Things/` → `40_Archive_Completed/` |
| **Zettelkasten** | 原子化 + 双向链接 + 自下而上浮现 | "这个知识如何生长？" | `30_Resources/31_Atomic_Notes/` → `30_Resources/32_MOCs/` |
| **Atomic Habits** | 身份驱动 + 微小增量 + 环境设计 | "我如何成为那样的人？" | `60_Habits/` + `61_Reviews/` |

### 1.2 关键词索引

- **Rapid Logging**（快速记录）：Bullet Journal 的核心技术，用一句话符号记录想法、事件、任务
- **Fleeting Notes**（闪念笔记）：知识管理 的第一阶段，捕获瞬间灵感
- **Literature Notes**（文献笔记）：用自己的话转述所读内容，标注来源
- **Permanent Notes**（永久笔记）：原子化的、互联的、可独立理解的知识卡片
- **MOC**（Map of Content，内容地图）：链接聚合多张永久笔记的索引页面
- **Implementation Intention**（执行意图）："当 X 发生时，我就做 Y"的行为编程
- **Habit Stacking**（习惯堆叠）：将新习惯锚定在已有习惯之后
- **Habit Scorecard**（习惯记分卡）：每日对关键习惯进行 + / - / = 打分

## 二、交集：四者的共振点

四套方法论来自不同作者、不同时代，但底层逻辑高度收敛。

### 共振点 1：唯一入口 → 减少决策疲劳

- BJ 的 **Daily Log** 是所有当天信息的唯一页面
- ZK 的 **Fleeting Notes** 是所有想法的唯一捕获点
- PARA 的 **Inbox** 是所有待处理信息的唯一入口
- AH 的 **环境设计** 要求把好习惯的触发器放在唯一可见的位置

> **本库实现：** `00_Inbox` 是唯一信息入口，`50_Bullet_Journal/Daily/` 是唯一时间入口。一个管"来了什么"，一个管"今天做什么"。

### 共振点 2：定期迁移 → 防止熵增

- BJ 要求每月将未完成任务迁移到下个月的 Monthly Log
- PARA 要求定期将完成的 Projects 移入 Archive
- ZK 要求定期从闪念笔记提炼为永久笔记
- AH 要求每周回顾习惯记分卡，调整策略

> **本库实现：** 日清零 Inbox → 周提炼永久笔记 → 月归档项目 → 季复盘习惯趋势。四级迁移节奏。

### 共振点 3：原子化 → 降低启动阻力

- ZK：一条笔记一个概念，不超过一屏
- AH：2 分钟规则——把新习惯缩到 2 分钟内可完成
- BJ：Rapid Logging 一句话一条，不写长篇
- PARA：一个项目一个文件夹，独立完整

> **本库实现：** `31_Atomic_Notes` 一卡一概念；Daily Log 一句一条；`10_Projects` 每个项目独立文件夹；`60_Habits` 每条习惯都可 2 分钟启动。

### 共振点 4：身份驱动 → 从"做什么"到"是谁"

- AH 的核心理念：**身份认同驱动行为，行为反过来强化身份**
- BJ 通过每日反思强化自我认知
- ZK 通过与自己的永久笔记对话，塑造思想体系
- PARA 通过 Projects 的输出定义"我是创造者"

> **本库实现：** `60_Habits/身份认同.md` 是整个系统的价值观底座。

## 三、冲突：四者之间的张力与解决

| 冲突 | 表现 | 本库解决方案 |
|------|------|------------|
| **BJ vs PARA：按时间还是按领域组织？** | 同一条记录"给杨媚打电话"，放 Daily 还是 `24_关系/伴侣`？ | 行动类写 Daily，持久信息放 Area。Daily 是"今天要打"，Area 是"如何维护关系" |
| **ZK vs PARA：知识放 Resources 还是 Atomic Notes？** | 读书笔记放 `30_Resources` 还是提炼后放 `31_Atomic_Notes`？ | 两者都放。`30_Resources` 存文献笔记（有来源的），`31_Atomic_Notes` 存永久笔记（完全用自己的话） |
| **AH vs BJ：习惯打分嵌入哪里？** | 独立追踪还是嵌入 Daily Log？ | **嵌入 Daily Log 顶部**。晨间打卡写 Daily，周日汇总写入 `60_Habits/习惯记分卡.md` |
| **Project vs Daily：工作产出记录在哪？** | 今天推进了操盘手骑士第六节课，成果写项目文件夹还是 Daily？ | **产出写项目**，进度写 Daily。Daily 写"完成第六节初稿 ✓"，具体内容在 `10_Projects/01_操盘手骑士/02_执行/` |

## 四、融合策略：垂直分层模型

关键认知：**四种方法论不是平行的竞争关系，而是垂直的分层关系。**

```
┌─────────────────────────────────────────────┐
│              身份层 (Atomic Habits)           │
│        "我是一个系统化的创作者"                 │
│        价值观 → 身份 → 习惯 → 行为              │
├─────────────────────────────────────────────┤
│              时间层 (Bullet Journal)          │
│    Daily → Weekly → Monthly → Future         │
│    "今天这 16 小时怎么过"                      │
│    捕获、排序、迁移、反思                        │
├──────────────┬──────────────────────────────┤
│  行动层 (PARA)│        知识层 (ZK)            │
│  P → A → R → A│  闪念 → 文献 → 永久 → MOC     │
│  "做什么"     │      "怎么想"                  │
│  交付物驱动    │      理解驱动                   │
├──────────────┴──────────────────────────────┤
│              复盘层 (AH + BJ)                 │
│   习惯记分 + 日/周/月/季复盘                    │
│   "我做到了吗？学到了什么？接下来怎么调？"        │
└─────────────────────────────────────────────┘
```

### 设计逻辑

1. **身份层在最上**：所有行动和知识的源头是"我是谁"。如果你不定义身份，PARA 的项目就会变成任务清单，ZK 的笔记就会变成信息囤积。
2. **时间层是操作系统**：BJ 的 Daily Log 是每天打开 Obsidian 第一个看到的页面。时间层不存储内容，只存储"今天注意力的分配"。
3. **行动层和知识层并排**：PARA 管输出（交付项目），ZK 管输入内化（理解世界）。两者通过 Daily Log 的 MIT 和晚间 Inbox 清零连接。
4. **复盘层是反馈回路**：从行动和知识的结果中提取模式，反馈到身份层和习惯层。没有复盘，系统就会熵增。

```
              ├── 🚀 项目审查
              │    └── 10_Projects 中每个激活项目：status 需要更新吗？deadline 还合理吗？
              │
              ├── 🎯 习惯回顾
              │    └── 7 天打分汇总 → 60_Habits/习惯记分卡.md 追加周趋势
              │
              └── 🔮 下周预览
                   └── 查看 50_BJ/Future/ 本月目标 → 定下周焦点 → 写入下周 Weekly
```

## 八、知识内化路径（知识管理 三阶）

```
📥 00_Inbox                    ← 第一阶段：闪念笔记（Fleeting Notes）
     │                             一句话记录灵感、问题、发现
     │                             每天清零，不过夜
     ▼
📚 30_Resources                ← 第二阶段：文献笔记（Literature Notes）
     │                             用自己的话重写，标注来源
     │                             一篇文章一条笔记
     │                             每周提炼 1~2 次
     ▼
🧠 31_Atomic_Notes             ← 第三阶段：永久笔记（Permanent Notes）
     │                             一卡一个概念，完全原子化
     │       ┌────────────────────── 用自己的话，不依赖原文
     │       ├── 不超过一屏（约 300-500 字）
     │       ├── 与其他永久笔记双向 [[链接与索引（卡片笔记写作法）]]
     │       ├── 一个想法写完后问：它还和哪些想法有关？
     │       └── 五分类：Concepts / Critiques / Models / People / Practices
     │
     ▼
🗺️ 32_MOCs                     ← 第四阶段：索引笔记（MOC - Map of Content）
          └── 触发条件：当某个主题的原子笔记超过 5 条时，创建 MOC
              链接所有相关原子笔记，标注它们之间的关系
              MOC 本身也是笔记，会随着理解不断更新
```

### 关键原则

1. **不要跳过任何阶段**。闪念不过夜，文献用自己的话，永久必须原子化。
2. **提炼是瓶颈，也是价值所在**。一天读 10 篇文章不如把 1 条闪念变成永久笔记。
3. **链接比笔记本身更重要**。一张永久笔记的价值 = 它被多少其他笔记链接 + 它链接了多少其他笔记。
4. **MOC 是涌现的，不是预设的**。不要提前创建空 MOC。等原子笔记积累到 5+ 条再创建。

## 九、习惯系统（Atomic Habits）

### 9.1 习惯系统的四个组件

| 组件 | 文件 | 核心问题 | AH 概念 |
|------|------|---------|--------|
| **身份认同** | `60_Habits/身份认同.md` | 我是谁？我想成为什么样的人？ | Identity-Based Habits |
| **记分卡** | `60_Habits/习惯记分卡.md` | 我今天做得怎么样？ | Habit Scorecard |
| **执行意图** | `60_Habits/执行意图.md` | 什么时候、在哪里、做什么？ | Implementation Intention |
| **习惯堆叠** | `60_Habits/习惯堆叠.md` | 做完什么之后立刻做什么？ | Habit Stacking |
| **环境设计** | `60_Habits/环境设计.md` | 如何让好习惯不费力？ | Environment Design |

### 9.2 四大支柱习惯

建议从这四个维度各选 1-2 个习惯开始，不要贪多：

| 支柱 | 含义 | 示例习惯 |
|------|------|---------|
| 🏃 **身体** | 生理基础设施 | 冷水澡、运动、早睡、控制饮食 |
| 🧠 **心智** | 认知能力维护 | 深度阅读 30 分钟、写作、不刷短视频 |
| 🚀 **产出** | 创造性输出 | 深度工作 2h、每天推进 MIT |
| 🔗 **联结** | 人际关系 | 午/晚餐和家人聊天、不生气、主动联系一位朋友 |

### 9.3 习惯追踪嵌入 Daily Log

每天晨间在 `50_Bullet_Journal/Daily/` 顶部打卡：

```markdown
🔲 习惯打卡
🏃 冷水澡 ✓    运动 —    早睡 ✓
🧠 阅读 ✓      写作 ✗    不刷短视频 ✓
🚀 深度工作 ✓  推进 MIT ✓
🔗 午晚餐聊天 ✓ 不生气 ✓  联系朋友 —
```

每周日在 `60_Habits/习惯记分卡.md` 汇总趋势。

## 十二、关键设计原则

| # | 原则 | 来源 | 体现位置 |
|---|------|------|---------|
| 1 | **一个入口，绝不绕路** | BJ + ZK + AH | `00_Inbox` + `Daily Log` |
| 2 | **行动驱动知识** | PARA | `10_Projects` → `20_Areas` → `30_Resources` 的排列顺序 |
| 3 | **原子化一切** | ZK + AH | `31_Atomic_Notes` 一卡一概念；Daily Log 一句话一条记录 |
| 4 | **定期迁移，永不堆积** | BJ + PARA | 日清零 Inbox → 周提炼笔记 → 月归档项目 → 季复盘趋势 |
| 5 | **身份 > 目标 > 系统 > 习惯** | AH | `60_Habits/身份认同.md` → 习惯记分卡 → 执行意图 → 环境设计 |
| 6 | **复盘闭环，没有复盘就退化** | AH + BJ | `61_Reviews` 周 → 月 → 季，反馈到 Habits 和 Projects |
| 7 | **MOC 是涌现的** | ZK | 不预设空 MOC，等原子笔记积累到 5+ 条再创建 |
| 8 | **一个工具，所有方法** | 系统设计 | 所有方法论都在 Obsidian 内实现，不引入外部工具 |
