# 三层文件体系 · 架构说明

> 基于 Hermes Agent + Obsidian 构建的可执行知识闭环系统。
> 将笔记从「档案库」升级为**可编程工作记忆**。

---

## 核心理念

传统笔记系统的根本缺陷在于 **Dead Files**——笔记越积越多但调用率低于 10%，因为缺乏：
- **动态上下文关联**——Agent 无法识别笔记间的逻辑关系
- **执行层接口**——笔记无法直接转化为行动指令
- **经验沉淀机制**——新知识无法自动反哺旧系统

三层文件体系的本质突破：**人类维护核心上下文（判断性工作），Agent 处理执行与沉淀（重复性劳动），Markdown 文件作为通用交互协议。**

---

## 三层结构

```
┌─────────────────────────────────────┐
│           🧠 MEMORY 层               │  ← 长期稳定、跨会话的上下文
│  MEMORY.md · USER.md                │
│  Personality: zh-user (config.yaml) │
├─────────────────────────────────────┤
│           📁 PROJECT 层              │  ← 具体任务的工作记录
│  10_Projects/                       │
│  操盘手骑士 · 知→行→进化              │
│  cron 输出 · daily worklog           │
├─────────────────────────────────────┤
│           ⚙️ 系统文档 层                  │  ← 可复用的工作流/技能
│  ~/.hermes/skills/                  │
│  obsidian-vault-manager              │
│  a-share-market-review              │
│  a-share-holiday-review             │
└─────────────────────────────────────┘
```

### 🧠 Memory 层（长期偏好 · 已验证错误）

| 文件 | 用途 | 更新方式 |
|:----|:-----|:---------|
| `MEMORY.md` | Hermes 持久记忆（环境事实、工具习性、项目约定） | Hermes 自动写入（`memory` tool） |
| `USER.md` | 用户画像（称呼、偏好、避坑） | Hermes 自动写入，用户可修正 |
| `config.yaml personality: zh-user` | 通用人设：简体中文、简洁直接、不客套 | 手动配置 |
| `90_System/进度与待办.md` | 知识库重整进度表 | 定期人工更新 |

**原则：** Memory 层只存**跨会话依然有用**的事实。任务进度、临时状态不记在此。

### 📁 Project 层（具体任务上下文）

| 区域 | 内容 | 示例 |
|:----|:-----|:-----|
| `10_Projects/11_工作/01_操盘手骑士` | 直播稿、数据播报、系统文档 | `2026-06-23-A股复盘直播稿.md` |
| `10_Projects/12_个人/01_知→行→进化` | Zettelkasten、卡片笔记、习惯追踪 | `卡片笔记写作法 MOC` |
| cron 输出 | 定时任务产物 | `~/.hermes/cron/output/` |
| `90_System/Worklogs/` | 每日工作日志 | `Hermes-Agent-Worklog-2026-06-24.md` |

**原则：** Project 层是**正在进行的判断性工作**的现场。完成后可归档至 `40_Archive/`。

### ⚙️ 系统文档 层（可复用工作流）

| Skill | 用途 | 触发方式 |
|:------|:-----|:---------|
| `obsidian-vault-manager` | Vault 管理（命名/标签/双链/审阅） | 用户指示 |
| `a-share-market-review` | 交易日 A 股复盘 | cron 18:18 |
| `a-share-holiday-review` | 休市日审计/推演 | cron 自动判断 |
| `reading-enhance.css` | Obsidian 阅读优化（行高/tag胶囊/checklist） | CSS snippet |
| Worklog 脚本 | 每日 06:00 创建空 worklog 文件 | cron + no_agent |

**原则：** 系统文档 层是**重复性劳动**的自动化封装。Agent 执行后自动沉淀经验回 Memory 层。

## 数据流

```
用户判断/指示
    ↓
Project 层（任务上下文） ──→ Agent 执行 ──→ 系统文档 层（复用工作流）
    ↑                              │
    │                              ↓
    └──────── 经验沉淀 ────────── Memory 层（长期记忆）
```

---

## 防坑原则

| 原则 | 说明 |
|:----|:------|
| ❌ 禁止全库加载 | 避免上下文污染，skill 按需加载 |
| ✅ 动态加载策略 | 每个任务只读相关笔记，不过度遍历 |
| ✅ 保持人类可读 | Agent 不污染笔记正文，YAML 仅做结构化元数据 |
| ✅ 人类判断 + Agent 执行 | 人决策方向，Agent 执行操作 |
| ✅ Markdown 为通用协议 | 所有文件纯文本，不依赖特定工具 |
