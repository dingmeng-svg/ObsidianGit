# Dify 部署 Agent 指南

> **归档说明**：本指南基于 Dify 云服务及 Docker 部署场景整理。本人已采用云服务完成部署，不再需要 Docker 方式，本文档作为记录归档。

这份 Dify 部署指南会像一份菜单，将方案清晰地分为几个部分，你可以像点菜一样，选择性地执行。整个过程大约需要 30-60 分钟。

## 🧭 开始前：选择一个部署方案

开始前，先决定如何搭建 Dify 环境。这里有三种选择：

| 部署方式 | 核心描述 | 适合人群 | 💰 成本 |
| :-------------- | :----------------------------------------------- | :-------------------------------- | :--------------- |
| **云服务 (SaaS版)** | 使用官方提供的云端服务，无需自己搭建服务器，注册即可用。 | 个人用户、希望快速尝试、不想折腾技术细节的技术小白 | 有免费额度，使用量超出后付费 |
| **本地 Docker 部署** | 在自己的电脑上通过 Docker 技术搭建一个 Dify。这种方式数据完全掌握在自己手中，隐私性最高。 | 对数据安全有要求，且电脑配置不错的个人或团队（内存建议 8GB 以上） | 免费，但需自己承担电费和硬件成本 |

> **💎 首选推荐：云服务**
> 对技术小白而言，云服务无疑是最省心、最快的启动方式。它会自动更新和扩展，你连服务器都不用管。下面的步骤主要基于云服务操作，本地部署的步骤也会单独说明。

---

## 📦 第一步：部署你的 Dify

### 方案 A：极速启动云服务（推荐）

1. **注册账户**：访问 Dify 官网（[cloud.dify.ai](https://cloud.dify.ai)），点击“免费开始”，用邮箱或 GitHub 账号完成注册。
2. **登录与准备**：登录后，你即可进入主控界面，准备创建应用。

### 方案 B：本地部署（进阶）

如果你有私人部署的强烈需求，可以在电脑上操作：

1. **环境准备**：确保电脑已安装 Docker 和 Docker Compose。
2. **启动服务**：打开终端，依次运行以下命令：
   ```bash
   # 下载官方配置文件
   curl -L -O https://raw.githubusercontent.com/langgenius/dify/main/docker/docker-compose.yaml
   # 启动服务（这个过程可能需要几分钟，会自动下载所需的镜像文件）
   docker-compose up -d
   ```
3. **访问控制台**：在浏览器中输入 `http://localhost` 访问。首次登录的默认账号是 `admin@dify.ai`，密码是 `difyai.com`。**务必尽快修改密码**。

---

## 🧠 第二步：为 AI 配置模型（Model）

AI 需要一个大脑才能思考。Dify 本身不是 AI，它需要连接外部的大语言模型（LLM）来获得思考能力。这就像给电脑安装操作系统一样。

1. **进入设置**：点击右上角的头像，进入“设置” -> “模型供应商”。
2. **选择模型提供商**：你会看到一系列模型供应商的卡片。
   - **国内用户推荐**：**通义千问（Tongyi Qianwen）**。
3. **获取并配置 API Key**：以“通义千问”为例，点击“安装”插件，然后点击“设置”，在弹出的窗口中填入你的 API Key。没有 API Key 的开发者，可以去阿里云百炼平台注册并获取。
   - **官方云服务**：在模型供应商页面，你通常就能直接找到获取 API Key 的入口或指引。
   - **本地部署**：在模型供应商界面，可以配置本地模型（如 Ollama）或兼容 OpenAI API 的第三方服务。

> **💡 如何获取其他模型的 API Key？**
> 对于 DeepSeek、智谱 AI 等模型，前往它们的官网注册账号，在开发者或 API 管理页面就能找到并生成新的 API Key。
>
> 对于 Claude 模型，可以直接在 Anthropic 官网生成密钥。所有模型的通用配置流程都是一样的，找到对应的“模型供应商”卡片，填入 API Key 即可。

---

## 📚 第三步：构建你的 AI 知识库（Knowledge）

现在，我们把电脑上散落的文档（PDF、Word、TXT 等）集中起来，让 AI 能够从这些资料中学习。这就像是给 AI 准备一个专门的图书馆。

### 核心配置

1. **创建知识库**：在顶部导航栏进入“知识库”，点击“创建知识库”按钮。
2. **上传文档**：在弹出的窗口中，选择“上传本地文件”，将你的知识文档上传。Dify 支持 PDF、TXT、Markdown、Word 等多种格式。
3. **设置分段与清洗（核心环节）**：这是影响检索质量最关键的一步。AI 会将长文档切分成“内容分段”来进行索引。你可以在界面中调整分段方式，并预览效果。如果效果不理想，后续可以调整。
4. **等待嵌入处理**：上传后，Dify 会自动进行“向量化”处理，将文本转化为 AI 能理解的数学语言。处理时间取决于文档大小，一般几 MB 的文件只需一两分钟。

### 进阶管理

- **文档状态**：知识库建成后，可以随时**启用/禁用**文档，而无需删除；不常用的文档可以**归档**起来；**删除**文档则需谨慎，操作不可逆。
- **分段管理**：点击文档标题，可以查看所有内容分段，支持“展开”查看完整文本，或进入“全屏模式”浏览。

---

## 🤖 第四步：创建并“教育”你的 Agent

AI 拥有了知识（知识库），完成了思考（模型）的配置。现在，我们需要创建一个具体的 AI 助手（Agent），并教会它如何工作。

### 制作你的 Agent

1. **创建应用**：在“工作室”页面，点击“创建空白应用”。
2. **选择类型**：在弹出的窗口中，选择 **“Agent”** 类型。
3. **设定角色**：在“提示词”中，清晰地描述 AI 的角色、任务和能力。比如：“你是一个专业的客服助手，负责回答我们产品的使用问题，回答需要专业、简洁、有用。当你不知道答案时，请告知用户并建议联系人工客服。”
4. **关联知识库**：在 Agent 编排界面，点击“上下文”，添加你在上一步创建的知识库。这样 AI 就能基于你提供的私有知识回答问题。
5. **赋予能力（工具）**：Agent 可以调用外部工具来完成复杂任务。在“工具”栏中，点击“+”，为你的 Agent 添加需要的工具，如“联网搜索”。
   - **注意**：工具调用受限于模型本身的能力（是否支持 Function Calling），部分模型可能无法使用此功能。
6. **发布**：点击右上角的“发布”按钮。

> **🧠 Agent 的思考策略**
> 在配置 Agent 时，你可能会遇到“Agent 策略”选项。Dify 目前提供两种策略：
> - **Function Calling**：精确高效，适合需要明确调用特定函数的任务。
> - **ReAct（Reason + Act）**：灵活应变，适合需要多步推理和探索的复杂任务。
>
> 对于知识库问答这种任务，通常两者均可。如果希望 AI 的“思考过程”更清晰可见，可以优先选择 ReAct。

---

## 🔗 第五步：集成与发布

完成上述步骤后，就可以把你创建的 AI 助手“发布”出去了。

1. **Web 应用**：发布后，Dify 会自动生成一个可公开访问的网页链接，你可以把链接分享给他人使用。
2. **API 集成**：每个应用都有独立的 API 密钥，你可以用它将 AI 能力集成到自己的网站、App 或微信机器人中。
   - **集成到微信/飞书/钉钉**：可以借助 **LangBot** 这类开源项目，快速将你的 Dify Agent 接入各个聊天平台。配置时只需提供你 Dify Agent 的 API 密钥即可。

---

## 🛠️ 第六步：调试与持续优化

部署完成不是结束，持续改进才能让 AI 越来越好。

1. **调试**：在 Agent 界面右侧的调试窗口，你可以直接发消息测试。Dify 会显示每一步的“思考-行动-观察”日志，方便你随时调整配置。
2. **分析**：进入“日志与分析”面板，可以查看用户与 Agent 的真实对话记录，分析回答是否准确。
3. **优化**：对于回答不理想的地方，你可以进行“标注回复”，提供更优答案。这些数据会成为宝贵的反馈，帮你持续优化 Agent。

---

## ⚠️ 注意事项与避坑指南

- **知识库上传失败**：请检查文件格式是否为 Dify 支持的类型（PDF, TXT, Markdown, Word 等），同时确认文件大小是否在平台限制内。
- **模型 API 调用失败**：检查 API Key 是否填写正确、是否还有余额。Dify 社区版用户还需留意网络是否能够正常访问你所选模型的 API 服务。
- **Agent 思考卡住**：如果 AI 不回答问题或表现异常，很可能是“系统提示词”写得不清晰，尝试优化你的提示词。
- **Docker 端口冲突**：如果你使用 Docker 部署，且电脑的 80 端口已被占用，可以修改 `docker-compose.yml` 文件，将 `ports: - "80:80"` 改为 `ports: - "8080:80"`，之后通过 `http://localhost:8080` 访问。
