# 第一部分：每日决策入口（开始日）

## 1.1 统一决策树

```
获取当前日期 + 星期
  │
  ├── 步骤A：是否为交易日？
  │   检查：周末（六/日）→ 否
  │   检查：2026年法定节假日（元旦/春节/清明/五一/端午/中秋/国庆）→ 否
  │   检查：调休补班日（国务院通知）→ 是（即使周末也交易）
  │   检查：调休放假 → 否（即使工作日也休市）
  │
  ├── 是（交易日）
  │   └── 执行【第二部分：交易日复盘 系统文档】
  │
  └── 否（休市日）
      ├── 检查重大突发事件触发重定向
      │   ├── 全球主要股指单日跌幅>3% → 暂停原模板，输出事件速报+影响评估
      │   ├── 央行意外降息/加息 → 同上
      │   ├── 地缘冲突导致原油单日涨幅>5% → 同上
      │   └── 国内出台资本市场顶层设计文件 → 同上
      │
      └── 判断休市类型 → 执行【第三部分：休市日 系统文档】
```

## 1.2 2026年法定节假日参考

| 节日 | 日期 | 休市安排 |
|:---|:---:|:---|
| 元旦 | 1月1日（周四） | 1月1日-4日 |
| 春节 | 2月17日（周二） | 2月14日-22日（调休） |
| 清明节 | 4月5日（周日） | 4月4日-6日 |
| 劳动节 | 5月1日（周五） | 5月1日-5日 |
| 端午节 | 6月19日（周五） | 6月19日 |
| 中秋节 | 9月25日（周五） | 9月25日-27日 |
| 国庆节 | 10月1日（周四） | 10月1日-7日 |

> **注意**：以上为2026年预估安排，每次执行前须搜索确认国务院官方通知。
> 休市日复盘须标注 `next_trading_day` 字段。

## 1.3 去重机制（每日强制）

无论交易日还是休市日，执行前必须：
1. 读取前一日已保存的复盘/审计文件的 `top_news` / `weekly_key_events`
2. 重复新闻（相似度>70%）→ 仅保留一句结论性语句或标注"昨日已述"
3. 新新闻（相似度<50%）→ 正常详细展开
4. 休市日连续多天时，对比前一天审计报告的假设追踪表

# 第二部分：交易日复盘 系统文档

## 2.1 核心理念

交易日≠仅仅播报数据，而是**用结构化框架把收盘信号转化为可行动的认知**。

## 2.2 可信数据源

### Tier 1 — 直接可靠（curl可用）

| 数据源 | 用途 | 获取方式 |
|--------|------|----------|
| 腾讯财经行情API | 三大指数+成交额 | `curl -s "https://qt.gtimg.cn/q=sh000001,sz399001,sz399006" \| iconv -f GBK -t UTF-8` |
| 腾讯财经行情API | 美股/港股收盘 | `curl -s "https://qt.gtimg.cn/q=usIXIC,usDJI,hkHSI" \| iconv -f GBK -t UTF-8` |

### Tier 2 — 浏览器依赖（动态JS加载）

| 数据源 | 用途 |
|--------|------|
| 东方财富 (finance.eastmoney.com) | 新闻/板块排名/资金流向 |
| 同花顺行情中心 (q.10jqka.com.cn) | 涨跌分布/涨跌停数据 |

### Tier 3 — 已知不可用

| 数据源 | 问题 |
|--------|------|
| push2.eastmoney.com (curl直连) | 返回空/404 |
| 10jqka.com.cn/thshy/ | Nginx forbidden |
| vip.stock.finance.sina.com.cn | 返回空/Forbidden |

## 2.3 腾讯API数据格式解析

```
v_sh000001="1~上证指数~000001~4090.48~4108.08~...~20260618161419~-17.60~-0.43~..."
```

字段位置（0-indexed）：
- idx 3：最新价
- idx 4：昨收
- idx 5：开盘价
- idx 31：时间戳 (YYYYMMDDHHMMSS)
- idx 32：涨跌额
- idx 33：涨跌幅
- 末尾 `~数字~`：成交额（元）→ 需 ÷1e8 转亿

## 2.4 数据采集流程

1. **腾讯API** → 三大指数收盘 + 成交额
2. **同花顺首页**（浏览器）→ 涨跌分布、涨跌停家数
3. **对比前一日文件** → 交叉验证
4. **东方财富**（浏览器）→ 板块排名、资金流向
5. **新闻采集**（浏览器/东方财富证券聚焦）

### 数据交叉验证允许误差

| 指标 | 允许误差 |
|------|----------|
| 指数点数 | 0误差 |
| 成交额 | ±50亿 |
| 涨跌家数 | ±50家 |
| 涨停家数 | ±5家 |

## 2.6 新闻采集优先级

| 优先级 | 内容 | 来源 |
|:---:|:---|:---|
| 第一 | 央行操作、关键经济数据、重大政策、盘中突发 | 财联社、央行官网 |
| 第二 | 美股/港股指数、A50期指、人民币汇率 | 东方财富全球 |
| 第三 | 商品期货、港股异动、亚太市场 | 同上 |
| 第四 | 日常行业新闻 | 东方财富要闻 |

## 2.7 数据缺失/异常处理（审核硬性规定）

| 场景 | 处理方式 |
|:---|:---|
| **北向资金净额** | 自2024年起不再按日披露。YAML写 `null` + 注释"机制变更" |
| **北向成交额** | 仍按日披露，正常填写 |
| **成交额** | 精确值+双源佐证。**不可同时写"精确值"和"约"** |
| **美联储主席信息** | 必须核实身份+事件日期。沃什2026-05-22就任，6月17日首次FOMC |
| **板块排名无法获取** | 从新闻中间接推断 |

## 2.8 交付格式硬性规定

1. **先写文件，再出回复**：`write_file` 落盘发生在回复输出之前
2. **最终回复 = 干净简报 + --- + 附加信息区**
   - 简报区：每行一个数据指标，不带emoji对齐
   - 附加信息区：系统提示、文件路径等集中在此
3. **YAML规范**：无官方数据写 `null` + 注释

## 2.9 交易日 Pitfalls

- 腾讯API返回GBK编码，必须 `iconv -f GBK -t UTF-8`
- 东方财富push2.eastmoney.com curl不可用，仅浏览器JS
- 百度搜索弹出验证码，不可用
- 成交额单位：腾讯API返回元→需÷1e8转亿
- browser-heavy任务容易达到50次迭代上限

# 第三部分：休市日 系统文档

## 3.1 核心理念

**休市日≠信息真空，而是"回顾整理+前瞻预期"的黄金窗口。**

休市日的核心价值不是"播报行情"，而是**"重构认知"**——回答三个问题：
1. **本周市场验证了什么？**（周六型·周度审计）
2. **下周市场可能发生什么？**（周日型·策略推演）
3. **我们的判断框架是否需要修正？**（月度元复盘）

## 3.2 休市类型判断

```
休市类型判断：
├── 周六（或周五为节假日首日）
│   └── 【周六型·周度审计】
├── 周日（或节假日第二/三日）
│   └── 【周日型·策略推演】
├── 节假日连续第3天及以上
│   └── 【长假守望型】
├── 距下一交易日 ≤ 1天
│   └── 【收假前一日·节后交易计划】（强制覆盖）
└── 每月第一个周六
    └── 附加【SOP健康度自检报告】
```

### 重大突发事件触发重定向

| 触发条件 | 示例 | 处理方式 |

| 全球主要股指单日跌幅>3% | 纳斯达克跌4.2% | 暂停原模板，输出事件速报+影响评估 |
| 央行意外降息/加息 | 美联储紧急加息 | 同上 |
| 地缘冲突导致原油单日涨幅>5% | 中东冲突升级 | 同上 |
| 国内出台资本市场顶层设计文件 | 国务院/证监会重大政策 | 同上 |

### data_quality 验证状态规则

| 状态 | 含义 | 要求 |
|:---|:---|:---|
| `verified` | 双源交叉验证通过 | ≥2个独立信源，附cross_check说明 |
| `estimated` | 单源估算 | 附caveat说明误差可能 |
| `unavailable` | 制度性缺失 | 附reason说明原因，附alternative替代指标 |

## 3.5 数据缺失处理规范

### 标准处理流程

| 步骤 | 操作 | 示例 |
|:---|:---|:---|
| Step 1 | 检索多信源确认数据是否确实缺失 | 检索新华财经、东方财富、搜狐历史行情 |
| Step 2 | 若有数据但非主流信源 → 采用并注明来源 | "据搜狐历史行情，科创50周一收盘1748.33" |
| Step 3 | 若确实无法检索到 → 表格中用"—"标注 | 表格列填"—" |
| Step 4 | 在表格下方加"💡 数据说明" | 说明缺失原因+若有实际值则补充 |

### 边界规则

| 场景 | 处理方式 |
|:---|:---|
| 指数收盘数据缺失 | **必须尽力检索**（收盘是最核心指标） |
| 指数开盘数据缺失 | 可标注"—"，在数据说明中补充说明 |
| 板块资金流向数据缺失 | 使用同花顺/东方财富替代数据，标注来源 |
| 北向资金净额 | 自2024年起不再按日披露，**禁止编造** |

# 第六部分：全局 Pitfalls

1. 腾讯API返回GBK编码 → 必须 `iconv -f GBK -t UTF-8`
2. 东方财富push2.eastmoney.com curl不可用 → 仅浏览器JS
3. 百度搜索弹出验证码 → 不可用
4. 成交额单位：腾讯API返回元 → 需÷1e8转亿
5. browser-heavy任务容易达到50次迭代上限 → 控粒度，分批采集
6. **北向资金**自2024年起不再按日披露 → YAML写null+注释，禁止编造
7. **美联储主席信息**必须核实身份+事件日期 → 禁止"AI幻觉"
8. **成交额**不可同时写"精确值"和"约"
9. **数据缺失**时禁止编造数据 → 宁愿标"—"也不造假
10. **PEG估值**必须用真实可查的数据 → 不可编造PE/增速
11. **跨周期对标**必须找到具体年份/行情名称 → 不可笼统说"类似历史"
12. 每日执行前必须**去重** → 读前一日文件的top_news
