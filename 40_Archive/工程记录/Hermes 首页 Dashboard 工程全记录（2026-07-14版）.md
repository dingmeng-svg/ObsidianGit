## 一、项目背景

为 Hermes 知识库构建一个「操作台 + 洞察镜」双层架构的个人工作台首页，作为打开 Obsidian 时的默认入口。严格对齐 PARA + BuJo + Zettelkasten + Inbox 分区，数据由 Dataview 自动拉取。

## 三、核心认知突破（Obsidian 底层物理铁律）

### 3.1 跳转方式对照表

| 语法 | 是否可被 HTML 标签包裹 | 原因 |
|------|------------------------|------|
| `[[双链]]` | ❌ 绝对不可 | Obsidian 解析器在遇到 HTML 标签时停止解析内部双链 |
| `![[嵌入]]` | ❌ 绝对不可 | 同上 |
| `[[双链\|别名]]` | ❌ 绝对不可 | 同上 |
| `<a href="...">` | ✅ 可以 | HTML 原生链接标签，不受限制 |
| `obsidian://` 协议 | ✅ 可以 | Obsidian 原生支持 URL Scheme 跳转 |

### 3.2 CSS 选择器行为对比

| 选择器 | 行为 | 风险 |
|--------|------|------|
| `A + B`（相邻兄弟） | 仅当 A 和 B 紧邻时生效 | 任何空行、注释、换行都会打断 |
| `A ~ B`（通用兄弟） | A 和 B 同父级，B 在 A 之后即可 | 容错性好，但可能误伤同类型元素 |
| `.class`（显式类名） | 精准命中带 class 的元素 | 最稳定 |

### 3.3 `{.class}` 语法的风险

在 Obsidian 中，`{.class}` 行内标记会触发自动 `<div>` 包裹，阻断双链解析。**禁止在包含 `[[双链]]` 的区块使用 `{.class}` 标记。**

## 五、永久禁区清单

1. ❌ `dv.el()` / `dv.span()` 注入复杂 HTML — 阅读模式下样式脱落、布局失控
2. ❌ 原生 Markdown 表格内放 `[[双链]]` — 表格解析器物理级限制，源码裸露
3. ❌ `all: initial` / `all: revert` 隔离插件 — 杀死插件渲染上下文
4. ❌ HTML 容器（div/p/ul）包裹 `[[双链]]` — 阅读模式下双链解析失效
5. ❌ 无 `.homepage` 命名空间的 `table`/`td` 样式 — 污染 Dataview 表格
6. ❌ 在 `dv.span()` 内拼接 ``` 代码块 — 不进行二次 Markdown 解析
7. ❌ `obsidian://advanced-uri` 协议链接 — 依赖第三方插件，静默失效
8. ❌ 表格内混入外部链接 — 污染同行所有双链解析
9. ❌ `{.class}` 行内标记包裹 `[[双链]]` — 触发自动 `<div>` 包裹，阻断解析
10. ❌ `A + B` 相邻兄弟选择器作为主要布局手段 — DOM 结构变化即可失效

## 六、踩坑清单（完整版）

| # | 坑 | 原因 | 解决 |
|---|-----|------|------|
| 1 | `dv.dateformat is not a function` | 旧版 API 已被废弃 | 改用 `dv.date("now").toFormat(...)` |
| 2 | 周日显示 `undefined` | `weekday` 返回 1-7，数组下标越界 | 取余 `% 7` |
| 3 | 积压天数显示小数 | `diff()` 返回浮点数 | `.toFixed(0)` 取整 |
| 4 | HTML 内的 `[[双链]]` 不解析 | Obsidian 渲染引擎限制 | 双链放在 HTML 标签外部 |
| 5 | HTML 内的 `$= dv...` 不解析 | 同上 | 内联查询放在 HTML 标签外部 |
| 6 | `<details>` 内嵌套 Callout 语法外露 | 双层嵌套解析冲突 | 改用原生折叠 Callout |
| 7 | 阅读模式下 CSS 脱落 | `dv.el()` 动态注入的 DOM 样式作用域丢失 | 回归静态 Markdown + HTML |
| 8 | `dv.html()` 输出的空状态样式失效 | 游离 DOM 节点，CSS 选择器无法匹配 | 改用 `dv.el("div", "...", {cls: "empty-state"})` |
| 9 | CSS 写死 `14px` 导致"太小" | 强制覆盖用户主题默认字号 | 改用 `rem` 相对单位 |
| 10 | `obsidian://advanced-uri` 静默失效 | 未安装 Advanced URI 插件 | 改用原生 `[[双链]]` 或 `obsidian://open` |
| 11 | `{.class}` 导致双链失效 | 触发自动 `<div>` 包裹 | 禁止在含双链区块使用该语法 |
| 12 | `h2 + ul` 选择器失效 | 空行/注释打断相邻关系 | 改用 `h2 ~ ul` 通用兄弟选择器 |
| 13 | 热力图空白 | 使用空 ` ```heatmap``` ` 未喂数据 | 使用 `renderHeatmapCalendar(this.container, data)` |

## 七、核心原则

1. **Markdown 是唯一真值源**：静态写在 Markdown 文件中的 HTML 是可靠的，动态注入的 DOM 是不可靠的
2. **阅读模式是唯一验收标准**：任何修改必须在阅读模式下验证
3. **顺应引擎而非对抗引擎**：理解 Obsidian 的物理限制，在限制内工作
4. **分治而非统一**：不同区域用不同技术方案，不必强求全栈统一
5. **卡片视觉用 `<a>` 标签，纯文本列表用 `[[双链]]`**，二者分治，各安其位

若 Heatmap Calendar 插件因版本兼容问题失效，保留纯 Unicode 字符画热力图作为备选：
- 优点：零外部依赖，仅用 `dv.span()` 输出纯文本色块

- 详见 v6.0.3-revised 热力图代码

### 6.2 插件依赖极简原则

- 首页仅保留两个必需依赖：**Obsidian 核心 + Dataview**
- 第三方日期/热力图类插件仅作为可选增强，非必需
- Heatmap Calendar 为当前推荐方案，但不应成为架构强依赖

### 6.3 版本迭代变更规则

- 仅改文案/路径：只更新 `last_sync`
- 改结构/CSS/查询逻辑：递增版本号 + 备份 `.bak` + 截图归档

- 视觉效果元素已基本出现

- 热力图依赖 Heatmap Calendar 插件 + `renderHeatmapCalendar()` API
- 后续修改参照封板宪章和永久禁区清单
