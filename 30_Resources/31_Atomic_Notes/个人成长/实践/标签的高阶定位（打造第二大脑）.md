# 标签：高阶技术，非基础操作

## 核心概念

标签应被视为一种**高阶技术（Advanced Technique）**，而非基础操作——不应在系统建立之初就使用。

## 潘多拉魔盒隐喻

> 一旦开始使用标签，很容易不假思索地给每条笔记贴标签，陷入“为标签而标签”的陷阱。

## 为什么是“高阶”？

| 原因 | 说明 |
|------|------|
| **易滥用** | 标签用起来太方便，容易贴得太多 |
| **易分心** | 标签让人专注于“组织”而非“产出” |
| **判断力要求高** | 好标签需要足够的使用经验才能判断 |

## 使用建议

1. **先积累**：等待你已捕捉数百条笔记、完成多个项目后再尝试使用标签
2. **先简单**：尽可能久地坚持用 PARA 文件夹（更简单）
3. **先产出**：当前阶段的努力应聚焦于**将笔记转化为实际产出**

## 标签 vs PARA

| 维度 | PARA | 标签 |
|------|------|------|
| 复杂度 | 低 | 高 |
| 使用门槛 | 初学即可使用 | 高阶用户使用 |
| 组织方式 | 一个笔记只能在一个文件夹 | 一个笔记可以有多个标签 |
| 灵活性 | 较低 | 较高 |
| 维护成本 | 较低 | 较高 |

> PARA 是基础，标签是进阶。

## 在“知→行→进化”中的位置

| 维度 | 贡献 |
|------|------|
| **知** | 理解标签的真正定位，避免过早滥用 |
| **行** | 先把基础做好（PARA、产出），再考虑标签 |
| **进化** | 标签作为进阶技能，在系统成熟后自然生长出来 |

## 一句话总结

> 在你不确定是否需要标签的时候——你不需要。先做 PARA，先做产出，标签会自然浮现。
