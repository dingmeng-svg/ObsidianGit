# 可执行知识闭环：三步最小测试

> 先做一个最小工作流跑通，让 Agent 读笔记、做任务、写回经验，下一次再复用。这个闭环起来以后，再去谈图谱、同步、VPS、cron、多 Agent。顺序别反。

## 前置准备

在 Obsidian vault 中准备三类文件：

| 层级 | 示例路径 | 内容 |
|:----|:---------|:-----|
| 🧠 长期偏好 | `Memory/preferences.md` | 你是谁、偏好什么方式、排除过什么方向 |
| 📁 项目上下文 | `Projects/customer-research.md` | 当前项目的具体记录 |
| ⚙️ 可复用流程 | `SOP/analyze-user-feedback.md` | 某个重复工作的方法论 |

## 三步测试

### 第一步：读取 → 总结

让 Agent 读取偏好和项目文件，做一次判断：

> 请读取我的 Obsidian vault 中 Memory/preferences.md 和 Projects/customer-research.md，总结我在评估垂直 SaaS 机会时最应该遵守的 10 条规则

**验证标准：** Agent 能正确找到文件并输出有依据的总结，而非泛泛之谈。

### 第二步：写入 → 沉淀

让 Agent 把总结结果写回文件系统：

> 把这次总结出来的需求判断规则，追加到 SOP/analyze-user-feedback.md，保留原文，不要覆盖旧内容

**验证标准：** Agent 能改文件，文件变更后下次可被复用。

### 第三步：执行 → 反馈

让 Agent 基于已有上下文执行一个真实任务，并在最后沉淀新经验：

> 基于 SOP/analyze-user-feedback.md 和 Projects/customer-research.md，帮我整理这批用户访谈，判断哪些痛点值得做成 SaaS 产品。最后把新学到的判断经验追加回 Projects/customer-research.md

**验证标准：** 闭环成立——读取→执行→沉淀→下次可复用。

## 通过标准

这三步都走通了，才说明你的 Obsidian 不只是资料库——它开始进入执行循环了。

## 延伸

闭环跑通后，可升级为 cron 自动化：
- 每天早上读取新反馈，更新项目文件
- 每周做一次高频痛点复盘
- 每次研究后把排除的假设写回 rejected-assumptions
