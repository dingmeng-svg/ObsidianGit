# 可编程工作记忆：Hermes × Obsidian 架构原理

## 核心概念

将笔记从「档案库」升级为**可编程工作记忆**——通过 AI Agent + 本地知识库的协同架构，实现知识的**复利增长而非线性堆积**。

## 传统笔记系统的根本缺陷（Dead Files）

90% 的用户陷入「整理陷阱」——笔记越积越多但调用率低于 10%，核心原因：

| 缺陷 | 表现 |
|:----|:-----|
| ❌ 缺乏动态上下文关联 | Agent 无法识别笔记间的逻辑关系 |
| ❌ 缺乏执行层接口 | 笔记无法直接转化为行动指令 |
| ❌ 缺乏经验沉淀机制 | 新知识无法自动反哺旧系统 |

## 三层文件体系

| 层级 | 定位 | 内容 | 维护者 |
|:----|:-----|:-----|:------|
| 🧠 **Memory** | 长期上下文 | 偏好、已验证错误、人设 | Agent 自动 + 人工修正 |
| 📁 **Project** | 任务现场 | 具体项目的执行记录 | 人 + Agent 协作 |
| ⚙️ **SOP** | 可复用流程 | 工作流/技能封装 | Agent 执行，人优化 |

## 协同分工

| 角色 | 负责 |
|:----|:-----|
| **人类**（判断性工作） | 决策方向、维护核心上下文、修正 Agent 错误 |
| **Agent**（重复性劳动） | 执行 SOP、沉淀经验、按需读取笔记 |
| **Markdown 文件** | 通用交互协议，人类可读，工具可解析 |

## 关键防坑

- ❌ **禁止全库加载** — 避免上下文污染
- ✅ **动态加载** — 按需读取相关笔记
- ✅ **保持人类可读** — 避免黑箱化
- ✅ **经验沉淀闭环** — 新知识自动反哺旧系统

## 与卡片盒理念的关系

这套架构不是替代 Zettelkasten，而是为其补上**执行层**。卡片盒负责「思考与链接」，Agent 负责「执行与沉淀」——两者协同，让知识从静态档案变成动态的工作记忆。

## 原文金句

> 普通聊天是你在喂上下文，这个模式是 Agent 自己去找上下文，用完以后再沉淀。

> 不是把所有东西塞进脑子里，而是知道什么时候该拿哪一张卡出来。

> 上下文从聊天框里拿出来，放回一个人和 Agent 都能读写的文件系统里。聊天记录是流水，Markdown 文件才更像资产。

> 第二大脑不是你整理出来的，是它真的开始替你参与下一次判断和执行时，才长出来的。

> Hermes Agent + Obsidian 最适合的第一批用户，不是想收藏更多资料的人，而是已经有重复工作流的人。

> 一条 prompt 用完就没了，一条 SOP 可以被下一个任务复用。

> 那不是第二大脑，那是第二个需要你反复培训的实习生。
